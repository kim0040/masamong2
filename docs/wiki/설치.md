# 설치

**한국어** | [English](https://github.com/kim0040/masamong2/wiki/Installation)

Masamong은 설치할 때 관리자 권한이 필요 없습니다. 프로그램은 사용자 폴더에 설치되고, 데이터 폴더는 제거해도 남습니다.

## 시작하기 전에

| 필요한 것 | 받는 곳 | 쓰는 때 |
|---|---|---|
| Git과 Go 1.27 이상 | [git-scm.com](https://git-scm.com), [go.dev/dl](https://go.dev/dl) (macOS `brew install git go`, Windows `winget install Git.Git GoLang.Go`) | 설치할 때. 아직 공개된 릴리스가 없어서 지금은 소스에서 빌드합니다 |
| 모델 API 키 | [OpenRouter](https://openrouter.ai)가 가장 쉽습니다(키 하나로 대화·기억·그림). CometAPI, Gemini, OpenAI 호환 서비스도 됩니다 | 설정 마법사에서. 연습 모드는 필요 없음 |
| Discord 봇 토큰 | [Discord 개발자 포털](https://discord.com/developers/applications) → New Application → **Bot** → Reset Token, 그리고 **Message Content Intent** 켜기([Discord 연결](https://github.com/kim0040/masamong2/wiki/Discord-연결)) | 설정 마법사에서, 또는 나중에 |
| 선택 도구 키 | 기상청(날씨), 카카오(장소), 웹 검색 서비스, Finnhub, ExchangeRate-API([도구와 한도](https://github.com/kim0040/masamong2/wiki/도구와-한도)) | 언제든 **연결** 화면에서 |

키와 토큰은 관리 화면에만 넣습니다. macOS 키체인, Windows 자격 증명 관리자, Linux·FreeBSD는 소유자 전용 파일에 보관됩니다. 대화창, 이슈, 셸 명령에 붙여 넣지 마세요.

## AI 코딩 에이전트로 설치하기

Claude Code, Codex, Cursor, Gemini CLI 같은 코딩 에이전트에 아래를 붙여 넣으세요. 에이전트용으로 쓴 [INSTALL.md](https://github.com/kim0040/masamong2/blob/main/INSTALL.md)를 따릅니다. 명령은 실행 전에 보여 주고, Git이나 Go를 설치하기 전에 묻고, 키는 모두 사용자에게 맡깁니다.

```text
마사몽을 설치해 줘. 먼저 https://raw.githubusercontent.com/kim0040/masamong2/main/INSTALL.md 을 끝까지 읽고, 이 컴퓨터에서 그 단계를 차례대로 진행해 줘. Discord 토큰이나 API 키를 이 대화에 붙여 넣으라고 하지 마. 키는 내가 마사몽 관리 화면에 직접 넣을게.
```

터미널에서 한 줄로: `claude "$(curl -fsSL https://raw.githubusercontent.com/kim0040/masamong2/main/INSTALL.md)"` (Codex: `codex "$(curl -fsSL …)"`).

이 페이지의 나머지는 같은 설치를 손으로 하는 방법입니다.

## 지원 환경

| 운영체제 | CPU | 배포 파일 | 비고 |
|---|---|---|---|
| macOS 12 이상 | Apple Silicon(arm64), Intel(amd64) | `masamong_darwin_*.tar.gz` | 메뉴 막대 아이콘, `.app` 만들기 가능 |
| Linux | amd64, arm64 | `masamong_linux_amd64/arm64.tar.gz` | 알림 영역 아이콘(데스크톱), systemd 자동 시작(서버) |
| Linux (Raspberry Pi 32비트) | armv7 | `masamong_linux_armv7.tar.gz` | Raspberry Pi OS 32비트, armv7l/armv8l |
| Linux | riscv64 | `masamong_linux_riscv64.tar.gz` | |
| Windows 10 이상 | amd64, arm64 | `masamong_windows_*.zip` | 알림 영역 아이콘, 로그인 시 자동 시작 |
| FreeBSD | amd64, arm64 | `masamong_freebsd_*.tar.gz` | 트레이 아이콘 없이 서비스·콘솔 사용. 서버에서 자동 시작은 rc.d/cron |

배포 파일은 실행 파일 두 개입니다. macOS를 뺀 모든 대상은 외부 라이브러리(CGO) 없이 빌드하고, macOS만 메뉴 막대 아이콘 때문에 CGO로 빌드합니다(소스에서 설치할 때 Xcode 명령줄 도구가 없으면 아이콘 없이 빌드됩니다).

- `masamong` — 명령줄 도구이자 런처. 콘솔 열기, 서비스 시작·중지, 원격 연결
- `masamongd` — 실제 봇 서비스(데몬). DB, Discord 연결, 관리 콘솔을 실행

## macOS · Linux · FreeBSD

### 소스에서 (Go 1.27 이상)

```bash
git clone https://github.com/kim0040/masamong2.git
cd masamong2
./install.sh
masamong open
```

### 빠른 시험 실행 (테스트 인스턴스)

개발 중 설치 없이 기능을 바로 시험해 보려면 소스를 내려받은 뒤 아래 명령을 실행합니다:

```bash
make try
# 또는 macOS에서 루트의 start-test.command 더블클릭
```

실제 인스턴스와 완전히 분리된 임시 테스트 인스턴스(`~/.masamong-try`)를 띄우고 브라우저로 관리 콘솔을 즉시 엽니다. `Ctrl+C`를 누르면 안전하게 종료됩니다. Windows에서는 `start-test.ps1`을 씁니다([Windows](#windows)).

### Go 없이

Go가 없으면 `install.sh`가 CPU·운영체제에 맞는 배포 파일을 GitHub Release에서 내려받아 설치합니다. 특정 버전은 `MASAMONG_VERSION=v0.2.0 ./install.sh`처럼 고릅니다. Release 파일을 직접 받았다면 압축을 풀고 그 안의 `install.sh`를 실행합니다. (아직 공개된 Release가 없습니다. 첫 Release 전까지는 Go를 설치해 소스에서 빌드하세요.)

```bash
tar -xzf masamong_linux_arm64.tar.gz
cd masamong_linux_arm64
./install.sh
```

### 설치 옵션

| 옵션 | 뜻 |
|---|---|
| `--prefix DIR` | `DIR/bin`에 설치 (기본 `~/.local`) |
| `--no-modify-path` | 셸 설정 파일에 PATH를 추가하지 않음 |
| `--app` | macOS: `~/Applications/Masamong.app`도 만듦 (더블클릭으로 열기) |
| `--uninstall` | 서비스 중지, 자동 시작 끔, 프로그램 삭제 (데이터는 유지) |

macOS 앱으로 쓰려면:

```bash
./install.sh --app
open "$HOME/Applications/Masamong.app"
```

## Windows

설치에 관리자 권한은 필요 없습니다. 아래 명령은 모두 Windows 10에 들어 있는 **PowerShell**에서 입력합니다. Git Bash, WSL, `make`는 필요 없습니다.

| 항목 | 위치 |
|---|---|
| 프로그램 | `%LOCALAPPDATA%\Programs\Masamong` (`masamong.exe`, `masamongd.exe`). **사용자** PATH에 추가됩니다 |
| 데이터 | `%APPDATA%\Masamong` (DB, 설정, 로그, 키 파일). 프로그램 폴더와는 다른 폴더이며 제거해도 남습니다 |

`install.ps1`은 세 가지 상황에서 동작합니다.

1. **릴리스 ZIP, Go 없이.** `masamong_windows_amd64.zip`(ARM 노트북은 `arm64`)을 풀고, 풀린 폴더 안에서 스크립트를 실행합니다.
2. **저장소 복제본, Go 있음**(`winget install Git.Git GoLang.Go`). 스크립트가 두 프로그램을 소스에서 빌드합니다. Go가 `go.mod`의 버전보다 낮으면 멈추고 Go를 업데이트하라고 알려 줍니다.
3. **저장소 복제본(또는 스크립트만), Go 없음.** Go도 없고 스크립트 옆에 프로그램도 없으면 GitHub Releases에서 `masamong_windows_<amd64|arm64>.zip`과 `SHA256SUMS`를 내려받아 체크섬을 확인한 뒤에야 설치합니다. 버전은 실행 전에 `$env:MASAMONG_VERSION = 'v0.2.0'`처럼 고릅니다.

```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1
```

PowerShell 파이프에서도 실행할 수 있습니다(예: 스크립트를 내려받아 `Invoke-Expression`으로 전달). 이때 스크립트는 현재 폴더에 있는 다른 파일을 전제로 하지 않습니다.

끝나면 스크립트가 다음에 칠 명령을 알려 줍니다.

```text
Installed and verified Masamong in C:\Users\you\AppData\Local\Programs\Masamong.

Next:
  Same window: & 'C:\Users\you\AppData\Local\Programs\Masamong\masamong.exe' open
  New terminal: masamong open
```

**왜 두 가지인가요?** 설치 스크립트는 사용자 PATH에 폴더를 추가하지만, 이미 열려 있던 창은 시작할 때의 PATH를 그대로 갖고 있어서 그 창에서는 `masamong`이 "인식할 수 없는 명령"이라고 나옵니다. **새** PowerShell을 열어 `masamong open`을 실행하거나, 같은 창에서 전체 경로로 실행하세요(`cmd.exe`에서는 `"%LOCALAPPDATA%\Programs\Masamong\masamong.exe" open`).

- 설치 폴더에 쓸 수 있는지 확인하고 새 프로그램 두 개를 옆에 먼저 준비한 **뒤에** 각 데이터 폴더를 기준으로 실행 중인 모든 서비스와 트레이 인스턴스를 멈춥니다. 준비한 파일로 교체하며, 교체에 실패하면 이전 파일을 되돌리고 이전에 켜져 있던 서비스도 다시 시작합니다. 폴더에 쓸 수 없으면 서비스를 멈추기 전에 실패합니다. 쓰기 가능한 폴더는 `-Prefix`로 지정하세요.
- 사용자 PATH의 원래 레지스트리 값과 형식을 보존합니다. `%USERPROFILE%\...` 같은 환경 변수 항목이 있는 `REG_EXPAND_SZ`도 그대로 유지하며, 제거할 때 Masamong 항목만 뺍니다.
- 설치 폴더에는 버전이 있는 `.masamong-manifest.json`을 둡니다. 제거할 때는 표식에 적힌 Masamong 파일만 지우며, 유효한 표식이 없는 옛 설치는 정해진 Masamong 파일 이름만 대상으로 삼습니다. 관계없는 파일은 남고 폴더도 비어 있을 때만 지웁니다. 유효한 표식 없이 내용물이 있는 폴더는 먼저 내용을 확인한 뒤 `-Force`를 지정해야 사용할 수 있습니다. 드라이브 루트, 사용자 프로필 루트, Program Files, Windows 폴더는 설치 위치로 거절합니다.
- `-Prefix C:\Apps\Masamong`으로 다른 곳에 설치할 수 있습니다.
- `install.ps1 -Uninstall`은 서비스를 멈추고 로그인 시 자동 시작을 끄고 프로그램을 지운 뒤 **사용자 PATH에 넣었던 항목도 지웁니다**. 데이터 폴더는 남깁니다.
- `install.ps1 -Uninstall -RemoveKeys`를 쓰면 현재 Windows 사용자의 `masamong/*` 자격 증명 관리자 항목도 지웁니다. `-RemoveKeys`가 없으면 저장한 키는 남습니다.
- 로그인 시 자동 시작은 `masamong autostart on`입니다(사용자 레지스트리의 `Run` 항목. `masamong autostart off`로 지웁니다). 아이콘은 알림 영역(트레이)에 나타나며, `masamong stop`은 서비스와 함께 아이콘도 닫습니다.
- 콘솔에서 입력한 키는 **Windows 자격 증명 관리자**에 저장됩니다([보안과 개인정보](https://github.com/kim0040/masamong2/wiki/보안과-개인정보)).

### Windows에서 빠른 시험 실행

Go가 있는 저장소 복제본에서:

```powershell
powershell -ExecutionPolicy Bypass -File .\start-test.ps1
```

지금 소스를 `build\try`에 빌드하고, 실제 인스턴스와 분리된 테스트 인스턴스(데이터는 `%USERPROFILE%\.masamong-try`, 또는 `MASAMONG_TRY_ROOT`가 가리키는 폴더)를 띄운 뒤 로그인된 콘솔을 열고 로그를 이어서 보여 줍니다. `Ctrl+C`로 테스트 서비스를 끕니다. 키는 자격 증명 관리자 대신 그 폴더의 파일로 보관되므로(`MASAMONG_SECRET_STORE=file`) 실제 인스턴스의 키와 섞이지 않습니다.

| 플래그 | 뜻 |
|---|---|
| `-Reset` | `start-test.ps1`이 쓴 소유 표시 파일의 내용까지 정확히 맞는 테스트 폴더만 지우고 처음 설정부터 시작합니다. 이름이 `.masamong-try`여도 표시가 없으면 거절합니다 |
| `-Check` | 시작 전에 `go vet`과 `go test`를 먼저 실행 |
| `-Stop` | 테스트 서비스만 멈춤 |

`make`가 설치되어 있다면 `make try`가 같은 스크립트를 실행합니다(`make try ARGS=-Reset`).

### Windows에서 로그인 전 부팅 시 시작

로그인 시 자동 시작과 별개로 **작업 스케줄러**에서 부팅 작업을 만들 수 있습니다. 아래는 사용자가 직접 등록하는 절차이며, 설치 프로그램은 작업이나 서비스를 등록하지 않습니다. 먼저 전용 계정이 읽고 쓸 수 있는 데이터·로그 폴더와 설치된 `masamongd.exe`의 절대 경로를 정합니다. 기본 `%APPDATA%`는 실행 계정에 따라 달라지므로 반드시 `--data-root`를 지정합니다.

1. 작업 스케줄러에서 **작업 만들기**를 엽니다. 인스턴스마다 다른 이름을 정하고, 일반 탭에서 **사용자의 로그온 여부에 관계없이 실행**을 선택합니다. 관리 권한이 필요한 폴더를 쓰지 않는다면 **가장 높은 수준의 권한으로 실행**은 켜지 않습니다. 등록 시 실행 계정의 암호를 요구할 수 있습니다.
2. 트리거를 **시스템 시작 시**로 만듭니다.
3. 동작은 **프로그램 시작**입니다. 프로그램에는 `masamongd.exe`의 절대 경로, 시작 위치에는 설치 폴더를 지정합니다. 인수는 아래처럼 지정하고, 공백이 있는 경로는 큰따옴표로 감쌉니다.

   ```text
   --supervise --data-root "C:\Masamong Data\always-on" --log-file "C:\Masamong Data\always-on\logs\daemon.log"
   ```

   이는 `masamongd --supervise --data-root <폴더> --log-file <파일>` 실행입니다. 콘솔을 설정에서 껐다면 `--web`도 추가해야 정상 중지 API를 사용할 수 있습니다. 로그인 전 실행에는 트레이 아이콘이 없습니다. 같은 계정의 `masamong --data-root "C:\Masamong Data\always-on" open`으로 관리할 수 있습니다.
4. 설정 탭에서 **작업이 실패하는 경우 다시 시작**(예: 1분 간격, 3회)을 켜고, **작업이 다음 시간 이상 실행되면 중지**는 끕니다. 이미 실행 중이면 **새 인스턴스를 시작하지 않음**을 선택합니다. 상시 실행 장비라면 전원 조건도 운영 방침에 맞게 정합니다.
5. 먼저 같은 데이터 폴더로 수동 실행·정상 중지를 확인한 뒤 작업을 저장합니다. 해제할 때는 먼저 `masamong --data-root "C:\Masamong Data\always-on" stop`으로 해당 인스턴스를 중지하고, 그 작업만 사용 안 함으로 바꾸거나 삭제합니다. 작업 스케줄러의 **끝내기**와 프로세스 강제 종료는 정상 중지 요청을 보내지 않습니다.

감시 프로세스의 일반 종료 요청(`WM_CLOSE`)은 해당 자식 PID·데이터 폴더의 로컬 콘솔 API로 중지하고, 그 요청이 성공한 뒤 약 60초(데몬의 종료 예산에 데이터베이스를 닫을 시간을 더한 값) 기다린 뒤에만 강제 종료합니다. 콘솔이나 인증 파일이 없거나 인스턴스 확인에 실패하면 이유를 로그에 남기고 자식만 강제 종료합니다. 로그인 사용자 세션에서는 숨은 최상위 창으로 로그오프·시스템 종료를 감지합니다. `WM_QUERYENDSESSION`에는 즉시 동의하고, 확정된 `WM_ENDSESSION`에서만 정리합니다. Windows의 약 5초 종료 한도 안에 끝내도록 이때는 최대 4초만 기다립니다. 작업 중인 응답·작업이 많거나 강제 종료라면 정리가 완료되지 않을 수 있습니다.

**로그온 여부와 관계없이 실행하는 세션 0의 시스템 종료 감지는 보장하지 않습니다.** 데몬의 SIGTERM 처리 경로는 있지만 숨은 창 메시지 전달과 Windows의 종료 순서는 실제 장비에서 확인해야 합니다. 데몬의 SIGTERM 경로가 세션 0에서 동작하는지도 미검증입니다. 부팅 시 시작·로그인 전 실행·재부팅·실제 로그오프/종료·작업 스케줄러 끝내기는 아직 검증하지 않았습니다. 이 절차는 Windows 서비스 배포를 추가하지 않습니다. 개발용 인스턴스와는 데이터 폴더를 분리하고, 로그인 자동 시작과 부팅 작업이 같은 폴더를 중복 실행하지 않게 선택합니다.

## 서버에 설치하기 (원격 운영)

서버에 설치한 뒤 데몬만 시작하고, 관리는 내 컴퓨터에서 SSH로 연결합니다. 콘솔은 서버의 외부 포트를 열지 않습니다.

```bash
# 서버에서
./install.sh
masamong start
masamong autostart on     # 로그인·부팅 시 자동 시작 (Linux: systemd 사용자 유닛)
masamong status

# 내 컴퓨터에서
masamong connect user@server
```

로그아웃해도 systemd 사용자 서비스가 계속 돌게 하려면 서버에서 한 번 `loginctl enable-linger $USER`를 실행합니다.

FreeBSD처럼 systemd가 없는 서버에서는 `masamong autostart on`이 지원되지 않는다고 알려 줍니다. 이때는 `crontab -e`에 `@reboot $HOME/.local/bin/masamong start`를 넣거나 rc.d 스크립트에서 `masamong start`를 실행합니다.

## 데이터 폴더

| 운영체제 | 기본 경로 |
|---|---|
| macOS | `~/Library/Application Support/Masamong` |
| Linux · FreeBSD | `${XDG_DATA_HOME:-~/.local/share}/masamong` |
| Windows | `%APPDATA%\Masamong` |

`--data-root` 또는 환경 변수 `MASAMONG_DATA_ROOT`로 바꿀 수 있습니다. 봇을 여러 개 운영하거나 시험하려면 데이터 폴더를 따로 씁니다.

```bash
masamong --data-root /srv/masamong-friends open
masamong --data-root /tmp/masamong-demo status --output json
```

데이터 폴더 하나는 데몬 하나만 사용합니다(`daemon.lock`). 같은 폴더로 두 번째 데몬을 띄우면 거부됩니다.

## 처음 실행할 때 보안 경고가 뜨면

릴리스 파일은 아직 코드 서명을 하지 않아서 운영체제가 한 번 경고할 수 있습니다. 받은 파일이 게시된 체크섬과 같은지는 `SHA256SUMS`로 확인합니다(`shasum -a 256 -c SHA256SUMS`, Windows는 `Get-FileHash .\masamong_windows_amd64.zip`을 실행해 `SHA256SUMS`의 해당 줄과 비교). 이 검사는 파일 손상을 찾지만 체크섬을 누가 게시했는지는 증명하지 않습니다. Windows 설치 스크립트는 ZIP을 직접 내려받을 때 이 확인을 스스로 합니다.

- **macOS**: "확인되지 않은 개발자" 경고가 뜨면 **시스템 설정 → 개인정보 보호 및 보안** 아래의 **그래도 열기**를 누릅니다. 터미널에서는 설치 폴더에 `xattr -dr com.apple.quarantine <폴더>`를 한 번 실행해도 됩니다.
- **Windows**: SmartScreen의 "Windows의 PC 보호" 창에서 **추가 정보 → 실행**을 누릅니다.

## 자동 복구

아이콘·`masamong open`·`masamong start`로 띄운 서비스는 감시 프로세스 아래에서 돕니다. 서비스가 비정상 종료되면 자동으로 다시 켜지고, 가동 이력과 운영자 알림에 이유가 남습니다. 10분 안에 5번 넘게 죽으면 재시작을 멈춥니다([문제 해결](https://github.com/kim0040/masamong2/wiki/문제-해결)).

## 업데이트와 제거

- **새 버전 알림**: 하루 한 번 새 릴리스가 있는지 확인해서 콘솔 **유지보수**와 알림 목록에 알려 줍니다(`updates.check: false`로 끔). 확인만 하고 아무것도 내려받지 않습니다.
- **앱에서 업데이트**: 릴리스 파일로 설치했다면 **유지보수 → 지금 업데이트**를 누르면 됩니다. 순서는 다음과 같습니다.
  1. 이 컴퓨터용 압축 파일과 `SHA256SUMS`를 내려받아 체크섬을 확인합니다.
  2. 새 `masamong`과 `masamongd` **두 프로그램 모두** 이 컴퓨터에서 실행되고 버전이 맞는지 확인합니다.
  3. 백업을 만듭니다.
  4. 두 프로그램을 저널에 기록하면서 한 단계로 바꾸고 서비스를 다시 시작합니다.

  내려받기나 검증에 실패하면 설치된 프로그램은 손대지 않습니다. 저널을 기록한 교체가 시작된 뒤에는 데몬이 DB를 열기 전에 재시도하거나 되돌리기를 마무리합니다. 되돌릴 때는 옛 프로그램을 설치된 파일 옆에 복사·검증한 뒤 이름을 원자적으로 바꾸므로 실행 가능한 프로그램이 0개가 되지 않습니다. 복구를 끝내지 못하면 봇은 꺼져 있고 복구 안내에 지금 쓸 명령만 나옵니다. 업데이트가 성공하면 콘솔이 새 버전으로 다시 열립니다.
- **업데이트가 중간에 끊기면**(강제 종료, 정전): 다음 시작에서 다른 어떤 작업보다 먼저 교체를 마무리하거나 이전 프로그램 한 쌍을 되돌립니다. 감시 프로세스도 서비스를 다시 띄우기 전에 똑같이 확인합니다. 정리가 끝나지 않으면 봇은 꺼지고, 데몬은 현재 상태에서 쓸 수 있는 명령만 담은 현지화 복구 안내를 띄웁니다([문제 해결](https://github.com/kim0040/masamong2/wiki/문제-해결#콘솔에-복구-필요가-뜰-때-유지보수-모드)). `masamong open`과 트레이의 열기로 볼 수 있고, `doctor`와 `masamongd --maintenance status`에 유지보수로 표시되며 `masamong stop`으로 오프라인 복구 전에 데몬을 멈춥니다. Windows에서 실행 중인 프로그램이 붙들고 있는 옛 파일은 새 프로그램 한 쌍을 확인한 뒤 지웁니다.
- **설치 스크립트로 업데이트**: 소스에서 빌드한 설치(`git describe` 버전)나 프로그램 폴더에 쓸 수 없는 설치는 앱에서 바꿀 수 없습니다. 콘솔에 이유가 표시됩니다. 이때는 `git pull` 후 `install.sh`(또는 `install.ps1`)를 다시 실행합니다. Windows에서는 PATH를 바꾸고 이전에 실행 중이던 각 데이터 루트가 정상 상태를 보고할 때까지 이전 프로그램을 보존합니다. 중간에 실패하면 이전 파일·표식·원래 PATH를 복원하고, 각 `--data-root`로 해당 인스턴스를 다시 시작합니다.
- **데이터는 그대로**: 어느 방법이든 프로그램 파일만 바꾸고 데이터 폴더는 건드리지 않습니다. 새 버전이 처음 시작할 때 백업을 하나 더 만들어 두므로, 이전 버전으로 돌아가야 하면 이전 설치 파일을 다시 설치하고 그 백업으로 복원합니다. 업데이트 전·첫 시작 백업은 종류마다 최근 3개를 남깁니다.
- **제거**: `./install.sh --uninstall` 또는 `install.ps1 -Uninstall`. Windows에서는 표식에 적힌 Masamong 파일(옛 설치는 정해진 파일 이름만)을 지우며 관계없는 파일과, 비어 있지 않은 설치 폴더는 남깁니다. 데이터 폴더도 지우지 않으므로 다시 설치하면 그대로 이어서 씁니다. 완전히 지우려면 데이터 폴더를 직접 삭제합니다(먼저 [백업](https://github.com/kim0040/masamong2/wiki/저장소와-백업)을 권장).
- **처음부터 다시**: 프로그램은 두고 데이터만 지우려면 콘솔의 **유지보수 → 초기화**를 씁니다([저장소와 백업](https://github.com/kim0040/masamong2/wiki/저장소와-백업#초기화)).

### 데이터가 지워지는 경우

데이터 폴더는 운영체제가 사용자 데이터용으로 두는 자리에 있습니다. 캐시나 임시 폴더가 아니므로 운영체제 업데이트, 디스크 정리(macOS 저장 공간 관리, Windows 디스크 정리·저장소 센스), BleachBit 같은 일반 청소 도구의 기본 항목에는 들어가지 않습니다. 서비스는 `/tmp`나 `%TEMP%`에 오래 남길 파일을 두지 않습니다.

| OS | 데이터 폴더 |
|---|---|
| macOS | `~/Library/Application Support/Masamong` |
| Windows | `%APPDATA%\Masamong` |
| Linux·BSD | `$XDG_DATA_HOME/masamong` (기본 `~/.local/share/masamong`) |

다음 경우에만 지워집니다.
- 콘솔에서 **초기화**를 했을 때
- 사용자가 데이터 폴더를 직접 지웠을 때
- 청소 도구의 "남은 앱 파일(leftovers)" 정리에서 위 폴더를 골랐을 때. 예를 들어 CleanMyMac은 `.app`이 없는 폴더를 지워도 되는 것으로 표시할 수 있으니 목록에서 빼 두세요.

중요한 데이터는 [예약 백업](https://github.com/kim0040/masamong2/wiki/저장소와-백업)을 켜 두는 것이 가장 확실합니다.
