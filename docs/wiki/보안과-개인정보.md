# 보안 및 개인정보 처리 원칙

**한국어** | [English](https://github.com/kim0040/masamong2/wiki/Security-and-Privacy)

## 관리 콘솔 접속 보안

- 관리 콘솔은 오직 **로컬 루프백 인터페이스(`127.0.0.1`)에만 바인딩**됩니다. 외부 네트워크 인터페이스에 직접 포트를 개방하는 기능은 아키텍처상 제공되지 않으며, 원격 관리는 암호화된 SSH 터널(`masamong connect`)이나, 관리자가 `admin.web.hosts`에 허용한 이름을 서버의 `tailscale serve`가 넘겨 주는 경우(tailnet 안에서만)에만 가능합니다. 목록에 없는 이름으로 온 요청은 로그인 화면 전에 거절됩니다.
- 콘솔 인증은 `masamong open` 또는 `masamong connect` 실행 시 발행되는 **보안 1회용 로그인 링크**나, 접속 토큰(`masamong admin token`, Tailscale 기기에서 필요)으로 처리됩니다. 고정된 관리자 계정이나 비밀번호는 없습니다. 토큰 실패 횟수는 분당 제한되며 이 컴퓨터와 Tailscale 기기를 따로 셉니다. tailnet에서 토큰을 찍어 봐도 이 컴퓨터의 로그인은 막히지 않습니다.
- 콘솔은 `Host` 헤더가 이 컴퓨터(`127.0.0.1`, `localhost`, `::1`)이거나 `admin.web.hosts`에 있는 이름인 요청에만 답합니다. 악성 웹페이지가 자기 도메인을 127.0.0.1로 돌려(DNS 리바인딩) 콘솔을 두드리는 것을 막습니다. 쓰기 요청은 같은 출처(Origin)와 CSRF 토큰을 모두 확인합니다.
- 로그인 링크 및 세션 쿠키는 타인에게 공유되지 않도록 주의하세요.
- 원격 서버를 운영할 때는 SSH 비밀번호 기반 로그인을 비활성화하고 공개키(Public Key) 기반 인증만 사용하도록 설정하는 것을 강력히 권장합니다.
- Tailscale을 쓰면 tailnet 접근 규칙이 서버에 닿게 허용한 모든 기기가 로그인 화면을 열 수 있습니다. 여럿이 쓰는 tailnet이면 Tailscale ACL로 좁히고, 콘솔에는 `tailscale funnel`을 쓰지 마세요.

## 키 및 자격증명 관리

| 참조 식별자 | 저장 위치 및 보관 방식 |
|---|---|
| `keychain:<계정>` | 시스템 자격 증명 저장소. **macOS Keychain** 또는 **Windows 자격 증명 관리자**(내 사용자 저장소의 `masamong/<계정>` 항목). Linux·FreeBSD에는 없습니다 |
| `file:<경로>` | 파일. macOS·Linux·FreeBSD에서는 소유자만 읽을 수 있고(`0600`), Windows에서는 ACL이 내 계정·SYSTEM·Administrators에게만 접근을 허용합니다. 내용은 평문이며 **암호화되지 않습니다** |
| `env:<변수명>` | 시스템 환경 변수 직접 참조 |

콘솔에서 입력한 키는 자격 증명 저장소가 있는 시스템(macOS, Windows)에서는 그 저장소에, 없는 시스템(Linux, FreeBSD)에서는 데이터 폴더의 `secrets/` 아래 파일(`file:` 참조)에 보관합니다. `MASAMONG_SECRET_STORE=file`을 설정하면 모든 시스템이 파일을 씁니다. 기존 `keychain:`·`file:` 참조는 어느 쪽이든 그대로 동작합니다. Windows 자격 증명 관리자는 Masamong을 실행하는 Windows 사용자에게 속하므로 예약 작업이나 서비스도 같은 사용자로 실행해야 키를 읽을 수 있습니다. 저장할 수 있는 값은 2,560바이트까지입니다. 더 긴 키는 데이터 폴더 ACL로 보호되는 `secrets/` 파일에 대신 저장하고 콘솔에 경고합니다. 프로그램이 따로 암호화하지는 않습니다. Linux·FreeBSD의 키 파일은 파일 권한으로만, macOS·Windows는 운영체제의 저장소나 ACL로 보호됩니다.

환경설정 파일(`config.yaml`), 시스템 로그, 백업 아카이브, 에러 스택 트레이스에는 **원문 API 키나 토큰이 기록되지 않고 참조 식별자만 보관**됩니다. Discord 봇 토큰 등이 예외적으로 로그나 메시지에 유입되더라도 마스킹 필터를 통해 가려집니다. 사용자 정의 HTTP 도구의 응답도 마찬가지로 걸러 냅니다. API가 되돌려 준 자격 증명은(원문, URL 인코딩, base64, JSON 이스케이프 형태) 모델이나 채팅에 닿기 전에 지워집니다. 이는 그 형태의 자격 증명 자체를 지우는 것이며, 원격 서비스가 값을 다른 방식으로 바꿔 돌려주면 알아볼 수 없습니다. 인증·디버그 필드를 돌려주는 API는 도구의 `http.pick` 목록으로 필요한 필드만 남기세요.

## 봇 동작 제어 및 안전 가드레일

- 봇은 사용자 피로도 방지를 위해 `@everyone`, `@here` 또는 무분별한 사용자/역할 멘션을 전송하지 않습니다.
- 초대 링크는 봇이 쓰는 권한만 요청합니다: 필수 4개(채널 보기, 메시지 보내기, 링크 첨부, 메시지 기록 보기)와 기능용 권장 3개(파일 첨부, 투표 만들기, 스레드에서 보내기). 관리자(Administrator) 권한은 요청하지 않습니다.
- **서버 승인**(`access.server_approval`, 기본 켜짐): 누가 봇을 새 서버에 초대해도 운영자가 콘솔에서 승인하기 전에는 그 서버의 메시지를 저장하거나 답하지 않습니다. 모르는 서버는 거절해 봇을 내보낼 수 있습니다.
- `/admin` 슬래시 명령은 Discord에서 "서버 관리" 권한이 있는 멤버에게만 보이며, 봇도 실행할 때 다시 권한을 확인합니다. 서버 관리자가 한 차단은 그 서버에만 적용됩니다.
- 콘솔 변경 기록에는 Discord에서 한 변경도 누가(표시 이름과 Discord ID), 어느 서버에서 했는지 남습니다. 이 기록은 로컬 DB에만 있으며 서비스 로그에는 사용자 ID를 쓰지 않습니다.
- `instance.expected_bot_id` 설정을 구성해 두면, 설정 실수로 다른 봇 토큰이 주입되었을 때 명령어 등록 및 대화 처리를 안전하게 거부합니다.
- 커스텀 HTTP 도구는 보안을 위해 HTTPS 프로토콜만 허용하며, URL 호스트 파라미터 변조(SSRF)를 원천 차단합니다.
- 도구 호출 주체 정보(사용자 식별자, 발신 채널 ID)는 내부 프로세스 컨텍스트에서만 바인딩되며, 외부 요청을 통해 위조할 수 없습니다.

## 대화 원문 처리 및 프라이버시 원칙

- **엄격한 채널별 기억 격리**: 각 Discord 채널은 해당 채널에서 발생한 대화와 명시적으로 매핑된 기억 블록만 조회할 수 있습니다. 타 서버, 타 채널, 또는 비공개 DM의 대화 기록이 자동으로 혼합되거나 노출되는 일은 없습니다.
- **수동 계정 병합 원칙**: 닉네임이나 표시 이름이 일치한다는 이유만으로 서로 다른 계정을 임의로 자동 병합하지 않으며, 계정 병합은 반드시 관리자가 콘솔에서 직접 확인 후 수행합니다.
- **원문 무결성 보존**: 외부에서 가져온 CSV 파일은 읽기 전용으로 안전하게 참조하며, 타임스탬프가 누락된 기록에 가상의 일시를 임의로 지어내지 않습니다.
- **대화 수집은 방마다 운영자가 켭니다(방 단위 opt-in)**: 전역 설정(`memory.capture: true`)과 채널별 설정(`capture: true`)이 모두 켜진 채널에서만 대화 기억을 수집합니다. 방 구성원이 한 사람씩 동의하는 방식이 아닙니다. 구성원 개인이 할 수 있는 일은 아래 "기능별 동의 체계"를 보세요.
- **웹 검색과 링크 읽기**: 인터넷 검색 도구는 검색어를 키가 있는 검색 서비스(Tavily·Linkup·Exa·Serper·Brave·TinyFish·카카오)로, 링크 읽기 도구는 링크 주소를 Jina Reader로 보냅니다. 링크 읽기는 운영자가 도구 화면에서 켜기 전까지 꺼져 있습니다(켤 때 확인 창). 구글 문서 공유 링크처럼 주소만 알면 열리는 링크는 내부 주소처럼 가려낼 수 없으니, 그런 링크가 오가는 방에서는 켜지 마세요. 페이지는 Jina가 가져오며 이 컴퓨터는 그 주소에 직접 접속하지 않습니다. localhost·사설 IP·`.local`·`.internal` 같은 내부 주소와 아이디·비밀번호가 든 주소는 어느 서비스에도 넘기지 않습니다.
- **외부 데이터 전송 투명성**: 기억 색인 및 검색 시 청크 본문이 사용자가 지정한 모델 공급자(임베딩, 요약, 재순위 API)로 전송됩니다. 해당 공급자의 데이터 보관 및 학습 배제 정책을 확인하세요. 키워드 기반 원문 검색(`messages search`)은 외부 전송 없이 로컬에서만 수행됩니다.
- **사용자 식별자 보호**: 도구 사용량 통계에는 사용자 ID를 단방향 해시로 변환하여 보관합니다. 단, 사용자에게 직접 DM을 전송해야 하는 개인화 기능(동의 내역, 운세, 공지 구독, 개인 환경설정)에 한해 Discord 고유 식별자를 있는 그대로 저장합니다. 이 값은 DB에서 **암호화되지 않습니다**. 운세를 위해 등록한 생년월일·시각·성별·출생지도 일반 DB 텍스트입니다. 콘솔 화면에서는 가려지지만 데이터 폴더나 백업을 읽을 수 있는 사람은 볼 수 있으므로, 아래의 폴더 권한과 디스크 암호화로 지키세요.
- **기능별 독립 동의 체계**: 운영자가 방의 수집을 켜면, 그 방 사람들의 대화 기억 수집과 먼저 말 걸기는 **각자 철회하기 전까지** 켜진 상태입니다(opt-out). `/privacy` 또는 `!개인정보 철회 기억`으로 언제든지 철회할 수 있습니다. 먼저 말 걸기의 동의 범위 이름은 "먼저 말 걸기"입니다(`!개인정보 철회 먼저말걸기`. `능동참여`, `끼어들기`, `참여`도 같은 뜻으로 받습니다). 기억 동의를 철회하면 그 사람의 저장된 대화를 영구 삭제합니다. 기억 저장을 안 하는 채널에서 봇이 이어 말하려고 들고 있던 대화 문맥 속 그 사람의 말, 콘솔 대화 기록과 참여 기록에 남은 메시지 본문, 그 사람이 남긴 답변 평가도 함께 지우며, 철회한 사람은 다시 수집하지 않습니다. 봇 답변은 Discord 채널에 그대로 보이므로 지우지 않습니다. 운세, 대학 공지, 편입 공지 기능은 명시적인 동의 절차(안내문 확인 후 동의 버튼 클릭)를 거쳐야만 동작합니다. 개인정보 정책 버전이 갱신된 경우 사용자는 재동의 절차를 거칩니다.
- **봇이 옮겨 적은 근거**: 새 근거는 원문의 복사본이 아니라 원문 메시지에 대한 **참조**(메시지 ID와 단방향 화자 참조)로 저장합니다. 지운 메시지나 철회한 사람의 말은 대화 문맥·저장된 메시지·검색에서 즉시 빠집니다. 대화 기록, 실험실·기억 검토, 평가 문항에 남은 복사본은 내구성 있는 백그라운드 작업이 지우며, 보통 1초보다 빨리 끝나고 수천 건을 한꺼번에 지울 때도 몇 초 안에 처리합니다. 중간에 종료되면 다음 시작에서 마저 끝냅니다. 이전 기록에 남은 발췌문도 남아 있는 ID나 특징적인 문장으로 찾아 지우며, 찾을 수 없는 부분은 아래 "아직 남는 것"에 적었습니다.
- **관리자 뷰 최소 노출**: 관리 콘솔에서는 특정 사용자가 어떤 기능을 구독 중인지만 확인할 수 있으며, 생년월일시나 사주 정보 등 민감한 개인 신상 데이터는 관리자 화면에도 마스킹되어 노출되지 않습니다.
- **수다왕 집계**: `/ranking`을 위해 날짜·서버·채널·사람별 **메시지 수**와 마지막으로 쓴 이름만 셉니다(`activity_counts`). 본문은 저장하지 않고, 봇·승인되지 않은 서버·기억 동의를 철회한 사람은 세지 않으며, 집계는 `retention.turn_days` 동안만 보관합니다.
- **원문 삭제·수정**: Discord에서 메시지를 지우거나 고치면, 그 채널이 기억을 저장하든 안 하든 봇의 대화 문맥·저장된 메시지·검색 인덱스에 즉시 반영됩니다. 콘솔 대화 기록과 참여 기록, 다른 사람의 기록에 근거로 인용된 복사본은 위의 백그라운드 작업이 지웁니다. 작업 중 종료되면 다음 시작에서 마무리합니다. 채널별 대화 문맥은 `retention.turn_detail_days`가 지나면 따로 지웁니다.
- **답변 피드백**: 봇 답변에 사람들이 단 반응과 **답변 평가** 결과로 저장하는 것은 다음뿐입니다. 어느 답변인지(대화 기록 ID), 누가 평가했는지의 단방향 해시, 좋음/별로, 고른 이유입니다. 메시지 본문과 Discord 사용자 ID는 저장하지 않습니다. 기억 동의를 철회한 사람과 차단된 사람의 평가는 남기지 않습니다. 평가는 `retention.turn_days`, 봇 메시지와 대화 기록의 연결은 `retention.turn_detail_days` 동안 보관합니다.
- **방 사이 격리의 마지막 확인**: 검색이 이미 채널 범위로 거른 기억을 답변 프롬프트에 넣기 직전에 한 번 더 확인합니다. 다른 방의 기억이 섞여 있으면 빼고 운영자에게 알립니다(정상이라면 일어나지 않는 일).
- **답변의 마지막 확인**: 답변을 보내거나 저장하기 전에, 봇 내부 표식(기억을 감싸는 구분자, 플래너 머리글, 시스템·보안 프롬프트 제목. 지원하는 모든 언어)이 들어 있는지 확인합니다. 들어 있으면 "답하지 못했다"는 일반 문구로 바꿉니다. 글자 그대로 확인하는 방식이라 지침을 그대로 읊는 경우는 막지만, 바꿔 말한 경우까지 알아보지는 못합니다.
- **장소 찾기**: 검색어("강남역 맛집")가 카카오 로컬 API로 갑니다.
- **수정·삭제·동의 철회**: 파생 기록은 저장할 때 같은 데이터베이스 트랜잭션에서 원문 참조도 함께 기록합니다. 철회·수정·삭제의 정리 의도와 식별자만 담은 tombstone은 로컬 원문을 변경하기 전에 같은 트랜잭션으로 저장합니다. 의도를 저장하지 못하면 로컬 변경도 적용하지 않습니다. 느린 답변이나 뒤늦은 쓰기가 지운 본문을 되살리지 못하게 하고, 삭제 뒤 끝난 답변의 대화 기록은 메시지와 근거를 비워 저장합니다. 정리 작업은 종료 뒤에도 남아 다음 시작에서 이어지며, native ID가 없는 관찰도 제한된 묶음으로 처리합니다.

### 아직 남는 것

- **찾을 수 없는 오래된 기록.** 누가 말했는지 기록하기 전에 쓴 행, 업그레이드 전에 이미 원문이 사라진 행, 아주 짧거나 흔한 메시지(12자 미만)는 사람이나 메시지에 항상 연결할 수는 없습니다. 삭제나 철회로 지워지지 않으며 `retention.turn_detail_days`가 지나면 저절로 사라지고, 운영자가 직접 지울 수도 있습니다.
- **봇이 한 답변**은 위에서 설명한 대로 Discord와 대화 기록에 남습니다.
- **원본 파일과 백업.** 올려 둔 가져오기 파일이나 다른 곳에 둔 원본, 관계없는 다른 인스턴스, 이전에 만든 백업은 고쳐 쓰지 않습니다. 지워 달라는 요청을 받은 대화가 거기에 들어 있다면 직접 지우세요.

프로젝트의 전체 데이터 처리 원칙은 [docs/RAW_DATA_POLICY.md](https://github.com/kim0040/masamong2/blob/main/docs/RAW_DATA_POLICY.md)를 참조하세요.

## 안전한 운영을 위한 권장 사항

- **macOS·Linux·FreeBSD**: 데이터 폴더는 소유자만 열 수 있게(0700) 만들고, 대화 DB·설정·키 파일은 0600으로 둡니다. 이전 버전이 만든 폴더나 DB가 다른 계정에게 열려 있으면 서비스가 시작할 때 자동으로 좁힙니다.
- **Windows**: 데이터 루트에 내 계정·SYSTEM·Administrators만 접근하는 보호된 ACL을 걸고 새 파일과 폴더가 이를 상속받게 합니다. 마이그레이션을 끝까지 마친 뒤에만 완료 표식을 기록합니다. 표식이 없거나 잘못되었거나 하위 항목 ACL 설정에 실패하면 다음 시작에서도 다시 훑고, 하위 ACL 문제가 해결될 때까지 `doctor` 확인 필요 항목에 계속 나옵니다. `--data-root`로 정한 폴더에도 적용됩니다. 데이터 루트 자체가 심볼릭 링크나 정션이면 그 대상 디렉터리를 보호합니다(다른 드라이브로 옮긴 폴더를 `mklink /J`로 연결한 경우 등). 루트 안쪽의 재분석 지점은 따라가지 않습니다. ACL을 걸 수 없는 드라이브에서는 데이터 폴더를 비공개로 만들 수 없어 경고하고, 다른 계정이 루트에 쓸 수 있으면 시작을 거부합니다. 자격 증명 관리자 항목은 이 폴더 밖에 있으며 Windows 사용자에게 속합니다.
- 이런 조치가 파일을 암호화하지는 않습니다. 노트북이라면 디스크 전체 암호화(FileVault, BitLocker, LUKS)도 켜 두세요. 대화 본문이 들어 있는 백업도 같은 방식으로 다루세요.
- 복수의 사용자나 서로 다른 목적의 봇을 운영할 때는 독립된 데이터 디렉터리(`--data-root`)를 지정하여 인스턴스를 물리적으로 분리하세요.
- 시스템 로그, `doctor` 진단 출력, 백업 아카이브를 외부에 공유하기 전에는 대화 원문이나 개인 식별 정보가 포함되어 있는지 반드시 검토하세요.
- 채널 참가자들에게 봇이 대화 내용을 기억하고 활용한다는 점을 공지하여 투명성을 유지하세요.

## 밖으로 나가는 연락

- **운영자 알림**(`alerts`): 운영자에게 보내는 Discord DM에는 문제 설명과 인스턴스 이름만 들어가고 대화 본문은 들어가지 않습니다.
- **서버 로그**(`guilds.<id>.log`): 메시지 삭제는 작성자·채널·시각과, `deleted_text`를 끄지 않았다면 내용과 첨부 파일 이름까지 올립니다. 마사몽 기억에서는 그대로 지우고, 내용은 그 서버 로그 채널의 글로만 남습니다. 오류는 채널과 원인만 적고 무엇을 물었는지는 적지 않습니다. 처음에는 꺼져 있고, 켜면 고른 채널(자동이면 이름이 `logs`인 채널)에 올라가니 그 채널은 서버 관리자만 보게 해 두세요.
- **새 버전 확인**(`updates.check`): 하루 한 번 GitHub API에 최신 릴리스를 묻습니다. 요청에는 프로그램 이름과 버전(User-Agent)만 들어가며, 끄면 보내지 않습니다.
- **업데이트 설치**(유지보수 → 지금 업데이트): 운영자가 누를 때만 내려받습니다. 파일은 이 저장소의 GitHub 릴리스에서만 받습니다. 압축 파일이 릴리스의 `SHA256SUMS`와 일치하고, 새 프로그램이 실행되어 기대한 버전을 보고해야 교체합니다. 교체 전에 백업합니다. 아직 서명하지 않은 파일이라, 내려받은 파일이 손상되지 않았다는 것까지만 확인합니다. 누가 만들었는지는 확인하지 않습니다([릴리스 체크리스트](https://github.com/kim0040/masamong2/wiki/릴리스-체크리스트)).
- **HTTP 도구**: 운영자가 정한 호스트에만 연결하고, 다른 호스트로 넘기는 리다이렉트는 따라가지 않습니다(키가 제3자에게 넘어가지 않도록).
- **공급자·도구 주소**는 글자가 아니라 해석한 URL로 검사합니다. HTTPS가 필요하고, 일반 HTTP는 `localhost`와 루프백 주소(`127.0.0.0/8`, `::1`)만 허용합니다(로컬 모델 서버 등). 아이디·비밀번호가 든 주소, `localhost.example.com` 같은 비슷한 호스트, 호스트 자리에 자리표시자가 있는 주소는 거절하고, 공급자가 다른 스킴·호스트·포트로 보내는 리다이렉트는 따라가지 않습니다.
- **복구 화면**: 복원·초기화·프로그램 업데이트가 끝나지 못하면 데몬은 DB를 열지 않은 채 현지화된 복구 안내를 띄웁니다([문제 해결](https://github.com/kim0040/masamong2/wiki/문제-해결)). `masamong open`과 트레이의 열기로 볼 수 있고, 현재 상태에서 쓸 수 있는 명령만 나옵니다. `masamong stop`은 인증된 중지 API로 유지보수 데몬을 종료합니다. 화면은 루프백 Host 이름에만 답하고 다른 출처의 쓰기 요청을 거절하며, 경로나 설정이 들어 있을 수 있는 원래 오류는 로그에만 남깁니다.

## 배포 파일 서명

릴리스 파일은 아직 코드 서명·공증을 하지 않습니다. 대신 `SHA256SUMS`로 받은 파일이 릴리스와 같은지 확인할 수 있습니다. 처음 실행할 때 macOS는 "확인되지 않은 개발자", Windows는 SmartScreen 경고를 띄울 수 있습니다. 우회 방법은 [설치](https://github.com/kim0040/masamong2/wiki/설치)를 참고하세요.
