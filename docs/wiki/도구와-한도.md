# 도구와 한도

**한국어** | [English](https://github.com/kim0040/masamong2/wiki/Tools-and-Limits)

Masamong이 제공하는 다양한 도구(날씨, 주가/환율, 웹 검색, 실시간 투표, 기억 검색 등)는 **기능별 활성화/비활성화, 채널별 맞춤 제어, 정밀한 호출 한도 설정, 노코드 커스텀 HTTP 도구 확장**을 완벽히 지원합니다. 자연어 대화, 접두사 명령어(`!`), 슬래시 명령어(`/`), CLI, 웹 콘솔 등 어떤 경로로 호출하더라도 일관된 게이트웨이 파이프라인을 거치므로, 도구를 비활성화하면 모든 경로에서 안전하게 차단되며 사용량 한도 역시 동일하게 엄격히 적용됩니다.

### 인터넷 검색의 깊이, 페이지 읽기, 비용

모델이 `search.web`을 부를 때마다 **깊이**를 고릅니다. `quick`은 값 하나(가격, 날씨, 점수, 날짜)만 있으면 되고 설명이 필요 없을 때만, `standard`(기본)는 일반 질문, `deep`은 요약·비교, 여러 면이 있는 "왜"·"어떻게 그렇게 됐어" 질문, "자세히"·"더 찾아봐" 요청, 앞선 답이 부실했다는 되물음에 씁니다. 깊은 검색은 말을 바꾼 `queries`를 1~3개 함께 보낼 수 있고, 이 질의는 본 질의와 같은 서비스에서 돌립니다(요청을 따로 보내야 하는 서비스는 그중 2개를 돌립니다). 서비스는 `web_search.order`에서 서로 대안입니다. 답한 첫 서비스의 결과가 답이 되고, 서비스끼리 결과를 섞지 않습니다.

| 깊이 | Exa | Linkup | Tavily | Brave | TinyFish | 카카오 | Serper |
|---|---|---|---|---|---|---|---|
| quick | instant | flash | fast | 웹 | 한 쪽 | 다음 웹 | 구글 한 쪽 |
| standard | auto | standard | basic, 청크 포함 | 웹 + 추가 요약문 | 한 쪽 | 다음 웹 | 구글 한 쪽 |
| deep | deep-lite + `additionalQueries` | deep | advanced, 청크 포함 | LLM 컨텍스트(페이지에서 뽑은 본문) | 한 쪽 | 다음 웹 + 다음 블로그 | 구글 한 쪽 |

- **주제.** 모델은 언론 보도를 찾을 때만 `topic=news`, 논문·연구를 찾을 때 `topic=research`를 주고, 공고·모집요강·채용·일정·가격·기록·사람·장소 같은 나머지는 일반 검색으로 찾습니다(학교·기관의 공식 안내는 검색어에 `site:도메인`). 논문 검색은 서비스마다 다릅니다. Exa는 `category: research paper`, TinyFish는 `domain_type=research_paper`(저자·학술지·연도, 최근 것만 원하면 그 해부터), Serper는 구글 학술검색(`/scholar`)을 씁니다. Tavily는 학술 사이트(arXiv, DBpia, KCI, RISS 등)를 먼저 찾되 나머지 웹도 찾고(`include_domains_mode: prefer`), Linkup·Brave·카카오는 검색어에 "논문"(영어면 "paper")을 붙입니다. 논문 검색은 순서를 바꾸지 않습니다.
- **검색어 정리.** 봇을 부르는 이름(`instance.bot_names`, 예: "마사몽")은 검색어에서 뺍니다("마사몽 젠슨황 근황" → "젠슨황 근황"). 이름만 있는 검색어는 그대로 둡니다. 결과에는 물어본 검색어가 그대로 남습니다. 같은 사이트에서 제목과 요약문이 같은 결과는 주소가 달라도 하나로 합칩니다.
- **제한 시간.** 한 서비스는 quick 8초, standard 10초, deep 15초(Linkup deep은 45초)를 받습니다. 검색 하나는 시도하는 서비스를 모두 합쳐 8 / 15 / 50초이고, 남은 시간이 2초보다 적으면 다음 서비스에 묻지 않습니다.
- **페이지.** 대화 턴은 위쪽 결과의 본문을 읽습니다. standard는 `web_search.read_pages`(기본 3), deep은 `web_search.deep_pages`(기본 6)이며 각각 최대 10, quick은 읽지 않습니다. Exa·Linkup·Tavily·Brave는 결과와 함께 본문을 주므로 따로 읽지 않고, TinyFish·Serper·카카오 결과(그리고 서비스 본문이 300자 미만인 결과)는 페이지 읽기 서비스(`web_search.fetch`: 자동, `tinyfish`, `jina`, `off`)로 읽습니다. 발췌는 페이지당 최대 1,500자(deep은 2,000자)입니다. 페이지 읽기는 늦어도 standard 5초, deep 8초에 끝나고, 두 쪽이 들어오면 나머지는 2.5초만 더 기다립니다. `/search`·`!검색` 명령, 명령에 대한 답, 예약 작업, 시세의 검색 대체는 페이지를 읽지 않습니다. 로그인이 필요한 페이지(네이버·다음 카페)와 공개되지 않은 주소는 요청하지 않습니다. Jina 키가 없으면 분당 20회로 제한되어 검색 하나가 1쪽(deep은 2쪽)만 읽습니다.
- **읽지 못한 페이지.** 막혔거나 로그인이 필요했던 호스트는 한 시간 동안 건너뛰고, 두 번 시간 초과가 난 호스트도 같습니다(네이버 블로그 같은 블로그 플랫폼은 세 번). 페이지를 읽으면 그 호스트의 기록이 지워집니다. 이 기록은 프로세스 안에만 있어 재시작하면 잊습니다.
- **하루 읽기 상한.** `web_search.fetch_daily_limit`(기본 800, 최대 5,000)은 하루에 읽는 페이지 수이고, 다 쓰면 그날 나머지는 요약문만 씁니다. TinyFish Fetch는 하루 1,000 URL까지 무료입니다.
- **비용.** 검색은 도는 동안 낼 수 있는 최대 금액을 잡아 둡니다. 검색 순서의 모든 서비스에 대해, 그 깊이의 정가(deep은 보내는 요청 수만큼)를 더한 값입니다. 비용을 알려 주지 않는 서비스도 정가로 셉니다. 잡아 두는 금액은 공개 가격보다 조금 높게 잡았습니다: Exa 0.005 / 0.008 / 0.015(quick / standard / deep), Linkup 0.0055 / 0.0055 / 0.055, Tavily 0.008 / 0.008 / 0.016, Brave 0.005, Serper 0.001(요청당)이고 TinyFish·카카오는 0입니다. 무료 한도: Exa 월 $10 크레딧, Linkup 월 $20, TinyFish 검색 하루 12,000회, TinyFish Fetch 하루 1,000 URL. 깊은 검색은 잡아 두는 금액이 크기 때문에 답변당 예산(`limits.per_request_budget_usd`) 기본값을 $0.15로, 답변당 외부 호출(`limits.max_external_attempts`) 기본값을 10으로 올렸습니다. 이미 있는 설치는 설정 파일의 값을 그대로 쓰므로, 깊은 검색이 건너뛰어지면 직접 올리세요([설정 레퍼런스](https://github.com/kim0040/masamong2/wiki/설정-레퍼런스#limits)).
- **병렬.** 도구 루프 한 라운드의 검색(과 다른 조회)은 동시에 돕니다. [동시 처리와 성능](https://github.com/kim0040/masamong2/wiki/동시-처리와-성능)을 보세요.
- **답변.** 답변 프롬프트의 도구 결과에는 3,500자를 줍니다(페이지 발췌가 있으면 12,000자, 깊은 검색 뒤에는 20,000자). 깊은 답변은 평소의 1.5배 길이까지 쓸 수 있고, 물어본 면을 정리한 종합으로 끝내며 출처는 문장 안에서 짧게 밝히고 불확실한 점은 그렇다고 말합니다. 이유나 상황을 묻는 질문에는 일반 검색 답변도 결과에 나온 구체적인 사실을 덧붙입니다. 턴 기록에는 페이지 발췌를 200자까지만 남깁니다.
- **"아직 찾고 있어요" 안내.** `chat.progress`(도구 화면): `deep`(기본)은 깊은 검색이나 두 번째 검색 라운드가 시작될 때 알림 없는 짧은 답글을 올리고, `slow`는 일반 검색 턴이 12초가 지나도 답하지 못했을 때도 올리며, `off`는 올리지 않습니다. 안내는 답을 보내기 전에 지우며 기억에 저장하거나 끼어들기 계산에 넣지 않습니다. 서버의 관리용 봇이 삭제를 기록할 수 있습니다.
- **콘솔.** **도구 → 인터넷 검색**(`search.web` 화면)의 "페이지 읽기" 카드에서 검색당 페이지 수, 깊은 검색의 페이지 수, 페이지 읽기 서비스, 하루 상한을 바꿉니다.

### 반복 알림과 대화 줄

- **반복**: "매일 아침 8시에 약 먹으라고 알려줘", "매주 월·수 9시 스탠드업", "매월 31일", "6시간마다"처럼 요청합니다. 규칙은 매일, 선택한 요일의 매주, 매월 며칠(짧은 달은 마지막 날), N시간마다(1~48시간)이며 끝(`until` 날짜나 횟수)은 선택입니다. 한 번짜리 알림과 같은 확인 절차를 거치고, 확인 카드에 반복 내용("매일 08:00")이 표시됩니다. Discord `/remind`에는 선택 항목 `repeat`(매일·매주·매월)가 있고, 요일이나 날짜는 입력한 시간에서 가져옵니다.
- **시간 계산**: 알림에 저장된 시간대의 벽시계 기준이라 서머타임이 바뀌어도 08:00은 08:00입니다. 각 회차는 최대 한 번만 발송됩니다. 다음 회차는 지금 회차를 가져가는 같은 단계에서 예약되므로, 중간에 멈춰도 중복 발송이나 반복 중단이 생기지 않습니다(발송 도중 끊긴 한 회차는 '불명'으로 표시되고 반복은 이어집니다). 꺼져 있다가 돌아오거나 `grace_min`이 반복 간격보다 길면 `grace_min` 안에 든 가장 최근 회차만 보내고 더 오래된 회차는 건너뛰며, 몰아서 보내지 않습니다. 마지막 회차는 Discord가 거절하면 일회성 알림처럼 최대 세 번 다시 시도합니다. DM은 방해 금지 시간이 끝난 뒤에 갑니다.
- **관리**: 취소·일시 정지·재개는 반복 전체에 적용됩니다. 본인은 `/reminders`(취소·일시 정지·재개 버튼), 운영자는 콘솔 **서버·방 → 방 → 예약 알림**과 **사람·권한 → 사용자**에서 합니다. 반복 알림의 시간을 바꾸면 규칙은 유지한 채 다시 확인을 받습니다.
- **한도** (`tools.reminders.propose.defaults`): `max_repeating`(1인당 반복 알림 10개), `max_repeating_room`(채널당 30개). 기존 `max_active`(20), `max_days`(366), `grace_min`(30)도 함께 적용됩니다.
- **대화 줄**: "그거 알려줘"처럼 모호하게 대화로 요청하면 최근 대화 최대 3줄(줄당 220자, 전체 700자, 작성자 이름과 본문)을 알림과 함께 보관했다가 알림이 갈 때 짧은 머리말 아래에 보여 줍니다(반복 알림은 첫 회차에만 보여 주고 곧바로 지웁니다). 요청한 사람의 대화(봇이 그 사람 대화로 판단한 줄과 최근 10분 안의 본인 발언)만, **기억 저장이 켜져 있고 기억을 쓰는 채널**에서만, 기억 동의를 철회한 사람의 줄은 제외하고 가져옵니다. 알림이 가기 전에 채널의 저장이나 기억 사용이 꺼지면 줄은 보내지 않고 버립니다. 원본 메시지가 삭제·수정되거나 작성자가 기억 동의를 철회하거나 알림이 끝나면, 늦어도 30일 뒤에는 함께 지워집니다. 모델이 줄을 직접 넣을 수 없고, 명령이나 콘솔로는 붙일 수 없습니다.

### 재난 알림 (지진·특보 자동 공지)

구 봇처럼 지진과 기상특보를 **먼저** 채널에 알립니다. 한국만 다루고, 기상청 키와 Discord 연결이 있어야 합니다. 한국 밖에서 설정한 새 인스턴스는 `disasters`와 `notices`가 꺼진 채 시작합니다([설정 레퍼런스](https://github.com/kim0040/masamong2/wiki/설정-레퍼런스#features)).

- **지진**: 1분마다 확인. 기본은 국내 규모 4.0 이상, 해외 7.0 이상이며 "국내 영향 없음" 통보는 올리지 않습니다. 72시간·150 km 안에서 이어지는 지진은 같은 사건으로 보고 처음 올린 메시지를 고쳐 갱신합니다.
- **특보**: 5분마다 확인. 육상 경보는 전국, 주의보는 지정한 지역만, 바다 특보는 켰을 때만 알리고, 해제도 알립니다.
- 처음 켜면 그 시점을 기준으로 삼아 지난 소식을 몰아서 올리지 않습니다.
- **켜고 끄기**: 관리 콘솔 **도구 → 특보·지진 → 운영** 탭에서 전체·특보·바다 특보 스위치와 규모 기준·주의보 지역을 정합니다. 채널별로는 **방 → 답장** 탭의 "재난 알림" 스위치로 끕니다. 상태(`disasters.alerts`)는 쉬는 이유(꺼짐·기상청 키 없음·Discord 미연결·보낼 채널 없음)를 보여 줍니다.

개인화 기능(운세/공지)의 세부 파라미터는 `tools.<id>.defaults` 설정을 통해 유연하게 조정할 수 있습니다. (예: 일일 운세 조회 제한 `daily_limit`, 아침 브리핑 사전 생성 시간 `lead_min`, 공지 크롤링 주기 `collect_every_hours`, 사이트별 요청 쿨다운 `host_interval_ms` 등) 수집 대상 게시판 목록은 코드가 아닌 데이터 파일로 관리되며, 기본 카탈로그(`internal/features/notices/catalog.json`)를 `<data-root>/notices/catalog.json` 경로에 복사하여 원하는 게시판을 자유롭게 추가하거나 수정할 수 있습니다.

API 키가 등록되지 않은 도구는 값을 지어내지 않고 지금은 안 된다고만 말한 뒤 대화를 이어 갑니다(명령이었다면 대화로 이어받음, [문제 해결](https://github.com/kim0040/masamong2/wiki/문제-해결)). `!도움말`은 지금 답할 수 있는 도구만 안내합니다. 현재 도구별 등록 상태는 `masamong tools list` 명령어 또는 관리 콘솔의 **도구** 메뉴에서 확인할 수 있습니다. 준비 상태는 서버가 한 번 판단합니다(`tools.list`의 `ready`·`ready_reason`): 키가 필요한 서비스(`no_key`), 도구가 쓰는 모델 역할(`needs_model`·`model_key_missing`, 예: 이미지 생성은 `image` 역할), 기억 색인(`needs_reindex`·`embed_model_changed`·`no_messages`), 직접 켜야 하는 도구(`opt_in`), 연습 모드에서 쓸 수 없는 도구(`practice_unavailable`). 선택 도구의 키가 없는 것은 홈 알림으로 띄우지 않고 도구 화면에만 표시합니다.

**비용·한도** 화면(통계·비용 › 비용·한도)의 한도 프리셋은 모든 도구의 사람당·방당 하루 한도와 연속 호출 대기를 한 번에 채웁니다(여유 50·300·0초, 보통 20·120·3초, 엄격 8·40·10초. 이미지 생성은 더 적게, 대화 답변은 더 넉넉하게). 하루 전체 한도(예: 이미지 50회)는 그대로 두며, 저장 막대에서 저장해야 적용됩니다.

### 외부 서비스 약관

도구가 부르는 외부 API는 마사몽의 MIT 라이선스와 별개로 각 회사의 약관을 따릅니다(2026-10-01에 공식 약관 확인).

| 서비스 | 도구 | 알아 둘 것 |
|---|---|---|
| Finnhub | 주가 | 개인용. 받은 데이터를 다른 사람과 공유하려면 Finnhub의 서면 승인 필요 |
| ExchangeRate-API | 환율 | 데이터 재배포 금지, 본인 용도로만 |
| Open-Meteo | 해외 날씨, 국내 예비 | 무료 API는 비상업용만. CC BY 4.0이라 날씨 카드에 `Open-Meteo.com · CC BY 4.0`을 표시 |
| 기상청 | 국내 날씨·특보·지진 | 출처 표시(카드 하단) |
| 카카오 | 장소·검색 | Kakao Developers 약관과 하루 쿼터 |

Open-Meteo가 이 빌드에서 모르는 시간대 이름을 보내면 예보는 `utc_offset_seconds`를 사용하며, 이 값도 없으면 UTC를 씁니다.

여럿이 보는 방에 주가·환율을 올리는 것은 "공유"에 해당할 수 있습니다. 혼자 쓰는 방이 아니면 약관을 확인하고 필요하면 그 도구를 끄세요. 정리와 남은 일은 저장소의 [추후 작업](https://github.com/kim0040/masamong2/blob/main/docs/BACKLOG.md).

## 콘솔에서 시험하고 기본값 정하기

도구 화면의 **시험** 탭과 **설정 → 기본 파라미터**는 도구마다 받는 입력을 폼으로 보여 줍니다(입력 목록은 서버의 도구 정의 `internal/tools`에서 옵니다). JSON이 필요하면 **JSON 직접 입력**으로 바꿀 수 있고, **예시 넣기**가 그 도구 형식의 예시를 채워 줍니다.

## 도구 활성화 및 비활성화

```bash
# 특정 도구를 전역에서 완전히 비활성화
masamong tools configure --id search.web --enabled off

# 자연어 대화 중 자동 호출은 막고, !투표 명령어 전용으로만 허용
masamong tools configure --id polls.create --chat off

# 명령어 접두사 호출은 막고 자연어 대화 맥락에서만 호출 허용
masamong tools configure --id weather.query --commands off

# 명령어 별칭(Alias) 등록 및 기본 매개변수 설정
masamong tools configure --id weather.query --aliases "날씨,w,weather"
masamong tools configure --id weather.query --defaults '{"region":"부산"}'

# 특정 도구 구성을 시스템 기본값으로 복원
masamong tools configure --id search.web --enabled default

# 특정 Discord 채널에서만 특정 도구 끄기
masamong tools configure --id search.web --guild_id <서버ID> --channel_id <채널ID> --enabled off
```

전역 기능 번들 스위치(`features.search: false` 등)를 비활성화하면 해당 카테고리에 속한 모든 도구가 일괄 비활성화됩니다.

## 세분화된 사용량 한도 제어

```bash
# 웹 검색 도구에 대해 전체 일일 300회, 사용자당 일일 20회, 10초 쿨다운 설정
masamong tools configure --id search.web --per_day 300 --per_user_per_day 20 --cooldown_sec 10

# 봇 대화 응답 자체에 대해 사용자당 일일 200회, 3초 쿨다운 설정
masamong tools configure --id chat.respond --per_user_per_day 200 --cooldown_sec 3
```

| 한도 정책 필드 | 설명 (0으로 지정 시 무제한) |
|---|---|
| `per_day` | 인스턴스 전체의 일일 총 호출 한도 (CLI 및 백그라운드 호출 포함) |
| `per_user_per_day` | 특정 Discord 사용자 1인의 일일 호출 한도 |
| `per_channel_per_day` | 특정 Discord 채널 1곳의 일일 호출 한도 |
| `cooldown_sec` | 동일 사용자의 연속 호출 간 최소 재사용 대기 시간(초) |

"하루"의 기준은 설정된 시간대(`i18n.timezone`) 기준 자정(00:00)입니다. 모든 사용량 카운터는 SQLite 데이터베이스에 영속 기록되므로 서비스 데몬 재시작이나 설정 리로드 후에도 안전하게 유지됩니다. 사용자의 프라이버시 보호를 위해 사용자 ID는 안전한 단방향 해시로만 저장됩니다.

도구 사용 한도에 도달한 경우 사용자 언어에 맞추어 정중하고 친근하게 안내합니다. 대화 응답 코어(`chat.respond`) 한도, 월간 비용 예산, 일시 중지, 처리 지연 때문에 답변이 멈추면 말을 건 사람에게 그 사람의 언어로 짧은 안내 한 줄만 보냅니다. 사람·방마다 5분에 한 번만 보내므로 바쁜 방이 안내로 도배되지 않습니다. 답변을 꺼 둔 방은 조용합니다.

### 시스템 전역 리소스 및 예산 한도

| 설정 키 | 설명 |
|---|---|
| `limits.monthly_budget_usd` | 이번 달 예산 계산액이 이 한도를 초과하면 대화 응답을 자동으로 일시 중단 (기본값: $10.00). **비용·한도** 화면이나 `masamong usage reset`으로 지금부터 다시 계산할 수 있고 이번 달에는 되돌릴 수 있습니다. 일별 기록과 제공자 사용량·키 한도는 그대로이며 다음 달에는 자동으로 새로 시작합니다 |
| `limits.max_concurrent_turns` | 동시 처리 가능한 최대 대화 생성 요청 수 (기본값: 8) — [동시 처리와 성능](https://github.com/kim0040/masamong2/wiki/동시-처리와-성능) |
| `providers.<id>.daily_limit` | 외부 API 공급자별 일일 최대 요청 횟수 제한 |
| `memory.turn_budget_usd` | 단일 대화 턴에서 소모 가능한 최대 기억 검색/재순위 예산 여유분 |
| `memory.index_budget_usd` | 1회 백그라운드 대화 색인 작업 시 최대 지출 허용 예산 한도 |

> [!TIP]
> 상시 응답 모드(`always`) 채널을 운영하는 경우, 악의적인 반복 호출을 방지하기 위해 `chat.respond`에 `cooldown_sec: 3`, `per_user_per_day: 200` 설정을 적용하는 것을 강력히 권장합니다.

## 노코드 커스텀 HTTP 도구 확장

표준 JSON 응답을 반환하는 HTTPS RESTful API라면, 코드 작성이나 빌드 없이 간단한 YAML 설정만으로 새로운 도구를 즉시 추가할 수 있습니다. 플래너 LLM이 도구 설명과 매개변수를 자동으로 이해하여 적절한 상황에 호출하며, `aliases`를 지정하면 접두사 명령어(`!명령어`)로도 직접 사용할 수 있습니다.

```yaml
tools:
  lotto.latest:                        # 도구 식별자: 영문소문자.영문소문자 규칙
    description: "로또 당첨번호 조회. parameters.round(회차 번호, 모르면 생략)"
    route: "로또 번호 및 당첨 결과 문의 시 lotto.latest"  # (선택) 플래너 의도 분석 라우팅 힌트
    aliases: [로또]                      # 명령어 별칭 (!로또)
    params:
      - {name: round, required: false}
    http:
      url: "https://api.example.com/lotto?round={round}&key={credential}"
      credential_ref: env:LOTTO_API_KEY
      headers: {Accept: application/json}
      timeout_sec: 10
      max_chars: 3000                  # 모델 프롬프트에 주입할 응답 본문의 최대 글자 수 상한
      pick: [draw_no, numbers, date]   # (선택) JSON 응답 중 필요한 특정 키만 추출
    limits: {per_day: 200, cooldown_sec: 5}
```

안전한 운영을 위한 내장 보안 가드레일:
- URL은 설정을 불러올 때 해석한 주소로 검사합니다. HTTPS만 허용하고, 로컬 디버깅용으로 `localhost`와 루프백 주소(`127.0.0.0/8`, `::1`)에만 일반 HTTP를 허용합니다. 아이디·비밀번호가 든 주소, `localhost.example.com` 같은 비슷한 호스트, 호스트 자리의 자리표시자는 거절합니다.
- URL 호스트(도메인) 부분에는 파라미터 변수를 삽입할 수 없으므로, LLM이 의도치 않은 임의의 외부 서버로 요청을 탈취(SSRF)할 수 없습니다. 리다이렉트는 따라가지 않습니다.
- 전달되는 파라미터 값은 자동으로 URL 인코딩되며, 사전 선언되지 않은 템플릿 변수(`{variable}`)는 설정 로드 시점에 거부됩니다.
- 인증 자격증명(`credential_ref`) 원문은 시스템 로그나 사용자 대화 에러 메시지에 절대 노출되지 않습니다.
- **성공한 응답도 걸러 냅니다.** API가 자격 증명을 되돌려 보내면(값, 키, 배열 어디든, 원문·URL 인코딩·base64·JSON/유니코드 이스케이프 형태) 모델, 채팅, 대화 기록으로 가기 전에 지웁니다. 이는 그 형태의 자격 증명 자체를 잡아내는 것이며 원격 서비스가 다른 방식으로 바꾼 데이터는 알아보지 못합니다. 인증·디버그 필드를 돌려주는 API는 `pick`으로 필요한 필드만 남기세요.
- 8자보다 짧은 키는 평범한 응답 글자까지 지울 수 있어 가리기 작업에서 제외하며, 로그에 경고를 남깁니다. 더 긴 키를 사용하세요.

등록된 커스텀 도구는 관리 콘솔의 **도구 → 시험 실행** 탭이나 CLI 명령어(`masamong tools test --id lotto.latest --input '{"round":1}'`. 따옴표를 벗겨 버리는 PowerShell에서는 `--input-file query.json`, [CLI 명령어](https://github.com/kim0040/masamong2/wiki/CLI-명령어#json-입력과-powershell) 참고)를 통해 사전에 정상 동작 여부를 안전하게 검증할 수 있습니다. (테스트 실행 역시 사용량 한도 카운터에 정상 반영됩니다.)
