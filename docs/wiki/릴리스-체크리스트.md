# 릴리스 체크리스트

**한국어** | [English](https://github.com/kim0040/masamong2/wiki/Release-Checklist)

새 버전을 사람들에게 내놓기 전에 거치는 순서입니다. 자동 검사로 확인할 수 있는 것과 실제 환경에서만 확인할 수 있는 것을 나눴습니다.

## 1. 자동 검사

| 확인 | 방법 | 통과 기준 |
|---|---|---|
| 테스트·정적 분석 | `CI=true go test ./... -count=1`, `go vet ./...` | 전부 통과 |
| 콘솔 | `make ui` 후 `git status`에 `ui/dist`·`locales/ui` 변경 없음, `npm run check -- --fail-on-warnings` | 경고 0 |
| Windows | 릴리스 커밋의 `ci` `windows` 작업(`go vet`, Go 테스트, 콘솔 빌드, Python 테스트)과 릴리스 워크플로의 Windows 스모크 테스트. ZIP을 `SHA256SUMS`와 대조하고 설정·시작·`status`·`doctor`(Go와 호스트 시간대 파일을 숨긴 채 시간대가 불러와져야 함)·`stop`을 실행 | 초록 |
| 전체 CI | GitHub **Actions → ci → Run workflow** (동시성 검사, 45초 부하, 모든 배포 대상 빌드, 라이선스) | 초록 |
| 장시간 부하 | **Actions → soak → Run workflow** (기본 45분) | `-strict` PASS: 고루틴·파일 누수 없음, 오류 1% 미만, DB 무결성 ok |
| 검색 parity | 검색 동작을 바꾼 릴리스만. [기억 운영 문서](https://github.com/kim0040/masamong2/blob/main/docs/memory-operations.md) 2절 | 근거·excerpt·날짜 일치 |

평소 `main` 푸시는 빠른 검사만 돕니다([개발 가이드](https://github.com/kim0040/masamong2/wiki/개발-가이드)). 전체 검사는 릴리스 태그를 올릴 때 자동으로도 돌지만, 태그 전에 한 번 수동으로 돌려 두면 태그를 다시 찍을 일이 없습니다.

GitHub Actions를 쓸 수 없으면 같은 항목을 로컬에서 대신합니다. 전체 CI 대신 패키지별 `CI=true go test -count=1 -p 1`, 좁힌 `go test -race`, 배포 대상 교차 빌드(`scripts/release.sh`), 웹 UI를 뺀 빌드(`go build -tags noweb ./cmd/...`), 라이선스 감사(`python3 scripts/license_audit.py`)를 돌립니다. 장시간 부하는 `soak` 워크플로와 같은 조건인 `GOMAXPROCS=1 go run ./tools/loadtest -seed 20000 -duration 45m -rate 6 -dims 1024 -sample 30s -config-every 60s -strict -report soak.md`로, Windows 항목은 Windows 컴퓨터에서 직접 확인합니다. 손으로 릴리스하는 방법은 [개발 가이드](https://github.com/kim0040/masamong2/wiki/개발-가이드)의 릴리스 절에 있습니다.

## 2. 실제 환경 시험 (1주)

자동 검사는 가짜 Discord와 가짜 모델로 돕니다. 실제 Discord·실제 모델 키·실제 대화로만 드러나는 문제를 보려면 **테스트용 봇**으로 며칠 운영해 봅니다. 운영 중인 봇과 같은 토큰을 쓰면 두 봇이 함께 답하니 반드시 따로 만듭니다.

### 준비

1. Discord Developer Portal에서 테스트용 애플리케이션과 봇을 만들고 **Message Content Intent**를 켭니다.
2. `./start-test.command --reset`으로 격리된 테스트 인스턴스를 띄웁니다(데이터 `~/.masamong-try`). Windows에서는 `powershell -ExecutionPolicy Bypass -File .\start-test.ps1 -Reset`(데이터 `%USERPROFILE%\.masamong-try`).
3. 첫 설정에서 OpenRouter 키와 테스트 봇 토큰을 넣습니다. 키를 넣으면 콘솔이 바로 실제로 확인합니다.
4. 테스트 서버에 봇을 초대하고 **서버·방 → 서버 승인**에서 승인, 쓸 채널의 응답·기억 수집을 켭니다.
5. **사람·권한**에서 내 Discord ID를 운영자로 추가하고, 같은 화면의 **운영자 알림 → 테스트 알림 보내기**로 DM이 오는지 봅니다.
6. **설정 → limits → 월 예산**을 작게(예: 5달러) 걸어 둡니다.

### 매일 볼 것 (5분)

- 홈 알림 목록과 운영자 DM: 새로 생긴 문제가 있는지
- **대화 기록**: 오류·무응답 비율. 무응답은 이유(멘션 없음, 한도, 일시 정지…)가 모두 설명되는지
- **사용량**: 하루 비용이 예상 범위인지
- **로그 → 가동 이력**: 비정상 종료가 있었는지, 있었다면 이유

### 일부러 해 볼 것

| 시험 | 방법 | 기대 결과 |
|---|---|---|
| 비정상 종료 | `kill -9 <서비스 PID>` (`masamong status`의 `pid`. Windows: `Stop-Process -Id <PID> -Force`) | 1–2초 뒤 다시 뜸, 가동 이력 "비정상 종료", 운영자 DM |
| 네트워크 끊김 | Wi-Fi를 1–2분 끄기 | Discord 다시 연결, 그 사이 메시지를 **놓친 메시지 채우기**가 가져옴 |
| 키 거절 | 연결 화면에서 일부러 틀린 키 저장 | "키 거절됨" 표시와 운영자 DM, 봇은 답하지 않음 |
| 백업 | 유지보수에서 백업 → 검증 → 복원 미리보기 | 검증 통과, 미리보기에 리비전 비교 |
| 재부팅 | 자동 시작 켜고 컴퓨터 재시작 | 로그인 후 서비스와 봇이 다시 동작 |
| 서비스 종료 | 콘솔 **서비스 종료** | 콘솔이 종료 화면으로 바뀌고 테스트 창도 닫힘 |
| Windows 업데이트 | 서비스와 트레이 아이콘이 떠 있는 Windows 컴퓨터에서 **유지보수 → 지금 업데이트**(또는 `install.ps1`)를 연달아 두 번 | 트레이 아이콘과 서비스가 "파일 사용 중" 오류 없이 교체되고 두 번 모두 성공하며 `masamong doctor`가 새 버전을 보고함 |
| 업데이트·복원 중단 | 임시 인스턴스에서 복원이나 업데이트 도중 서비스를 강제 종료한 뒤 다시 시작 | 다음 시작이 스스로 마무리하거나 되돌림. 안 되면 복구 화면이 뜨고 [문제 해결](https://github.com/kim0040/masamong2/wiki/문제-해결#콘솔에-복구-필요가-뜰-때-유지보수-모드)의 순서로 정리됨 |

### 답변 품질 기준선

**실험실**에서 실제로 물어볼 만한 질문 50개 이상을 던지고 답마다 좋음/나쁨을 판정합니다. 그다음 **평가 실행**을 한 번 눌러 기준선을 남깁니다. 이후 검색이나 모델을 바꾼 릴리스는 같은 평가를 다시 돌려, 좋음으로 판정한 근거를 계속 찾는지(유지율)와 나쁨이 고쳐졌는지를 비교합니다.

### 통과 기준 (예시)

- 오류로 끝난 대화 1% 미만, 무응답은 모두 이유가 설명됨
- 비정상 종료 0회, 또는 있었다면 자동 복구와 알림이 확인됨
- 알림 목록의 문제는 모두 운영자 DM으로도 옴
- 하루 비용이 예산 안

## 3. 태그와 배포

1. 버전을 정합니다(`vMAJOR.MINOR.PATCH`). 설정이나 DB 형식이 바뀌면 MINOR 이상을 올립니다.
2. `git tag vX.Y.Z && git push origin vX.Y.Z` → `release` 워크플로가 전체 검사, 모든 대상 빌드, `SHA256SUMS`, 설치 시뮬레이션을 거쳐 GitHub Release를 만듭니다.
3. 릴리스 노트에 바뀐 점, 설정 변경, 알려진 문제를 적습니다. 배포 파일은 아직 서명하지 않으므로 [설치](https://github.com/kim0040/masamong2/wiki/설치)의 첫 실행 경고 안내를 링크합니다.

## 4. 운영 인스턴스 올리기와 되돌리기

1. **먼저 백업**: 유지보수 → 백업 (또는 `masamong backup create`) → 검증.
2. **유지보수 → 지금 업데이트**(또는 새 버전 설치 스크립트 실행 → `masamong restart`) → `masamong doctor`.
3. 콘솔 홈에 새 알림이 없는지, 봇이 테스트 채널에서 답하는지 확인합니다.

DB는 시작할 때 새 형식으로만 바뀝니다(되돌리는 변환 없음). 이전 버전으로 돌아가려면 이전 설치 파일을 다시 설치하고 **올리기 전에 만든 백업**으로 복원합니다. 그 사이에 쌓인 대화는 Discord의 **놓친 메시지 채우기**가 최근 7일까지 다시 가져옵니다.
