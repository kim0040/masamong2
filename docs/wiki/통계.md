# 통계

**한국어** | [English](https://github.com/kim0040/masamong2/wiki/Statistics)

마사몽은 이 설치가 한 일의 하루 합계를 자기 데이터베이스에 모아 두어, 어떻게 쓰이고 비용이 얼마나 드는지 볼 수 있게 합니다. **프로그램이 이 통계를 어디로도 보내지 않습니다.** 문제를 알리거나 내 설치가 어떻게 돌아가는지 나누고 싶다면, 이 합계로 작은 파일을 만들어 보낼지 말지를 직접 정할 수 있습니다.

## 무엇을 모으고, 어디에 남는가

합계만 하루 단위로 모읍니다(하루는 인스턴스 시간대를 따릅니다).

| 영역 | 세는 것 |
|---|---|
| 대화 | 결과별 턴 수(답함, 일시 중지, 한도 초과 등), 응답 시간, 비용 |
| 모델 호출 | 역할·모델·제공자 계열별 호출 수, 토큰, 비용, 오류, 예비 모델 사용 |
| 도구 | 도구별 호출 수, 결과 상태, 오류 종류, 가드 판정 |
| 답장 | 보낸 조각 수, 재시도, 끝까지 보내지 못한 답장 |
| 피드백 | 평가와 암묵적 반응(종류별) |
| 먼저 말 걸기·대화 | 모드·상태별 판단, 이름 부르기, 이어 말하기, 스레드 |
| 알림·작업 | 상태별 건수, 알림이 얼마나 늦게 나갔는지, 작업 결과 |
| 활동 | 하루 메시지 수, 활동한 방 수·사람 수(메시지가 수집되는 사람만) |
| 작업(Action) | 콘솔·명령줄·Discord에서 실행한 작업의 이름, 출처, 결과 |

합계에는 **메시지 내용, 이름, Discord ID, 키, 주소가 들어 있지 않습니다.** 직접 정한 이름(내가 만든 모델, 직접 만든 HTTP 도구)은 이 설치와 콘솔에만 남고, 내보내는 파일에는 들어가지 않습니다. 하루 중 시간대별 활동은 콘솔에서만 쓰입니다.

합계는 봇이 이미 보관하는 기록(대화 턴, 모델 호출·도구 장부, 피드백, 알림, 작업)에서 만들며, 기간이 지나도 지우지 않습니다. 끝난 날은 나중에 다시 계산하지 않으므로, 합계의 바탕이 된 기록이 정리되어도 합계는 그대로입니다. 사람이 동의를 철회하면 그 사람의 기록은 지워지지만 합계는 그대로입니다. 합계는 사건 수를 셀 뿐 특정 사람을 가리키는 값이 없고, 끝난 날은 다시 계산하지 않아 철회 뒤에 숫자가 움직이지도 않습니다. 작업 횟수는 묶어서 기록하므로, 비정상 종료 시 마지막 몇 분 치는 잃을 수 있습니다.

콘솔의 **통계·비용 › 통계**에서 볼 수 있습니다.

## 수집 끄기

`config.yaml`에서 `stats.enabled: false`로 하거나, 콘솔의 **설정**(*통계* 항목)에서 **통계 모으기**를 끕니다. 그러면 새 통계를 모으지 않습니다. 이미 모은 값은 남아 있고 계속 내보낼 수 있으며, 내보내기 카드에는 수집이 꺼져 있다고 표시됩니다. 다시 시작할 필요는 없습니다.

`retention`의 `ledger_days`, `pending_days`, `context_days`는 별개입니다. 합계의 바탕이 되는 기록과, 확정되지 않은 알림 같은 회원 내용을 얼마나 오래 보관할지 정합니다. [설정 레퍼런스](https://github.com/kim0040/masamong2/wiki/설정-레퍼런스)를 보세요.

## 내보내기 파일에 들어 있는 것

내보내기는 **주 단위** 합계를 담은 JSON 파일 하나입니다. 하루 합계만으로 만들며, 수집이 꺼져 있어도 만들 수 있습니다.

- `schema`, `generated_at`(날짜가 아니라 `2026-W47` 같은 주).
- `install`: 무작위 설치 ID, 프로그램 버전, 운영체제, CPU 구조, 기기 규모 등급(`small`, `medium`, `large`), 이 설치를 처음 본 주.
- `period`: 담긴 주. 주는 UTC 기준 ISO 번호이며 통째로만 담기고, 아직 끝나지 않은 주(마지막 날로부터 이틀이 지나야 끝난 것으로 봅니다)는 빠집니다.
- `settings`: 설치 구성을 스위치(켬/끔), 정해진 목록의 선택지, 범위로 바꾼 개수(`1`, `2-5`, `6-20`, `21-100`, `100+`)로 나타냅니다. 예를 들어 기억 수집 여부, 검색 방식, 먼저 말 걸기 모드, 백업 주기, 설정된 서버·페르소나·제공자 수, 쓰는 제공자 계열입니다.
- `weekly`, `totals`: 지표와 주별(그리고 전체 기간) 행. 행마다 지표 이름, 구분 항목, 건수가 있고, 일부는 합계(토큰, 비용, 시간)와 응답 시간 분포도 있습니다.

개인정보 규칙은 이렇게 적용됩니다.

- **일별·시간별 행이 없고, 날짜도 어디에도 없습니다.** 주만 나옵니다.
- **활동은 뭉뚱그립니다.** 메시지 수는 한 자리 유효숫자로(1,456 → 1,000), 활동한 방과 사람은 범위로 나옵니다.
- **재난·기상 알림 행은 없습니다.**
- **적은 건수는 합칩니다.** 한 주에 5건 미만인 회원 관련 행(도구, 평가, 알림, 먼저 말 걸기, Discord에서 온 작업)은 이름을 붙이지 않고 `other` 행에 더합니다. 모델이 스스로 부른 도구는 도구 행에만 세고 작업 행에는 넣지 않습니다. 모델 오류, 시간, 비용, 작업은 센 그대로 나옵니다.
- **모든 이름은 정해진 목록에서만 나옵니다.** 기본 목록에 없는 모델은 만든 곳의 `other` 또는 `custom`으로 나옵니다(파인튜닝·프록시 ID에는 회사 이름이 들어갈 수 있습니다). 직접 만든 도구는 `custom_http`, 제공자는 계열(`openrouter`, `openai`, `gemini`, `anthropic`, `compatible`, `custom`)로, 그 밖의 것은 `other`로 나옵니다.
- **설정에는 이름이 없습니다.** 서버·방 이름이나 ID, 페르소나 이름·내용, 호스트 이름, URL, 키, 시간대는 들어가지 않습니다.

파일에는 메시지 내용, 이름, Discord ID, 서버·방 이름, 직접 정한 모델·제공자·도구 이름, 주소, 키, 페르소나 내용이 **들어 있지 않습니다.**

적은 건수를 합치면 날짜가 붙은 한 번의 행동이 드러나지 않을 뿐, 아주 활발한 한 사람이 익명이 되는 것은 아닙니다. **보내기 전에 파일 전체를 읽어 보세요.**

### 설치 ID

ID는 무작위이며 처음 내보낼 때 만들어집니다. 같은 설치에서 나온 파일끼리 알아보는 데만 쓰입니다. **공개 이슈에 붙인 파일은 공개**이고, ID가 같으면 그 파일들이 서로 연결됩니다. 연결을 끊으려면 새 ID를 만드세요(콘솔의 **설치 ID 새로 만들기** 버튼, 명령줄에서는 `--reset-id`). 통계 자체는 바뀌지 않습니다.

## 파일 보내는 방법

1. 콘솔의 **통계·비용 › 통계**에서 **통계 내보내기** 카드를 찾습니다.
2. 기간을 고르고 **파일 만들기**를 누릅니다. 저장될 파일 전체가 그대로 화면에 나옵니다.
3. 내용을 읽어 보고 **파일 내려받기**로 저장합니다.
4. 직접 보냅니다. 예를 들어 이슈에 첨부하거나(공개된다는 점을 기억하세요), 요청한 사람에게 따로 보냅니다. 프로그램이 대신 보내 주지는 않습니다.

명령줄에서는 이렇게 합니다.

```
masamong stats export --from 2026-09-01 --to 2026-11-15 --file stats.json
```

`--from`과 `--to`는 날짜이고 주 단위로 맞춰집니다(기본은 끝난 최근 12주). `--file`은 파일을 쓸 위치이며, 생략하면 명령의 JSON 결과 안에 파일이 담겨 나옵니다. `--reset-id`는 먼저 새 설치 ID를 만듭니다.
