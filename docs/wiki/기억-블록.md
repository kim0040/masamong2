# 기억 블록

**한국어** | [English](https://github.com/kim0040/masamong2/wiki/Memory-Blocks)

Masamong은 과거 대화 내용을 기억하여 "그때 어디 가기로 했었잖아", "지난달에 얘기했던 그 영화"처럼 자연스럽게 맥락을 살려 대답합니다. 기억 데이터는 독립된 **기억 블록(Memory Block)** 단위로 안전하게 관리되며, 채널마다 어떤 기억 블록을 참조할지 사용자가 직접 지정합니다.

## 기억 데이터의 출처

| 출처 | 수집 및 등록 방식 |
|---|---|
| Discord 실시간 대화 | 전역 설정(`memory.capture: true`) 및 채널별 설정(`capture: true`)이 활성화된 방의 대화를 실시간 수집 |
| 카카오톡 대화 기록 | 카카오톡 '대화 내용 내보내기' CSV 파일을 관리 콘솔에서 업로드하여 색인 |
| Discord 원문 보관본 | `imports start --source raw` CLI 명령어를 통해 대화 원문 아카이브 색인 |

실제 사람이 작성한 텍스트와 타임스탬프가 확인된 메시지만 기억 데이터베이스에 저장됩니다. 업로드된 원본 파일은 읽기 전용으로 안전하게 보존되며, 동일한 파일을 중복 업로드하더라도 고유 관찰 ID를 통해 중복 저장을 원천 방지합니다.

## 카카오톡 CSV 가져오기 (콘솔)

관리 콘솔의 **기억 블록(`/blocks`)** 메뉴에서 CSV 파일을 선택하면 다음 단계로 색인이 진행됩니다:

1. **파일 검증 및 미리보기** — 포맷, 대화방명, 기준 시간대, 기간 범위, 메시지 건수 및 중복 여부 확인. UTF-8(바이트 순서 표시 BOM 유무 모두)과 CP949(Excel 재저장 파일) 인코딩을 자동 지원하고, Windows(CRLF) 줄바꿈과 따옴표로 묶인 여러 줄 메시지도 읽으며, 따옴표가 어긋난 손상 행은 자체 복구 엔진을 통해 안전하게 보정합니다. 파일은 통째로 올리지 않고 스트림으로 읽으며, 미리보기는 창을 닫으면 멈춥니다.
2. **블록 메타데이터 입력** — 식별하기 쉬운 블록 명칭과 관리용 메모 작성
3. **예상 비용 및 시간 산출** — 색인 작업에 소요될 예상 시간, 모델 API 비용, 최대 허용 예산 한도 확인
4. **백그라운드 색인 실행** — 청크(리프 블록) 분할 → 임베딩 벡터 생성 → (활성화 시) 단락 요약 생성. 실시간 진행률, 남은 시간, 누적 비용을 확인하고 언제든 취소하거나 실패 항목만 재시도할 수 있습니다. 서비스 데몬이 재시작되더라도 중단된 지점부터 이어서 진행됩니다.
5. **채널 매핑** — `/blocks?view=channels` 화면에서 해당 기억 블록을 조회할 Discord 채널을 연결합니다.

### 크기 제한과 중단

가져오기는 크거나 이상한 파일이 메모리를 다 쓰지 못하게 제한을 둡니다.

- **제한**: 파일은 최대 **1 GiB**, 메시지 필드 하나는 최대 **64 KiB**, 논리적인 행 하나는 최대 **256 KiB**입니다. 제한을 넘는 파일은 그 제한을 알려 주는 메시지와 함께 거절합니다(제한을 넘는 콘솔 업로드는 거절하고 받다 만 파일을 지웁니다). 더 큰 내보내기는 날짜별로 나눠서 가져오세요.
- **다시 가져오기**: Kakao CSV 행의 안정 ID는 방·시각·화자·본문과 같은 시각에 같은 내용이 나온 순번으로 만듭니다. 같은 메시지도 다른 메시지 사이에 끼어 있으면 별도 행으로 보존합니다. 파일을 편집해 다시 넣어도 그대로인 행은 알아보며, 저장된 별칭으로 업그레이드 전 행도 찾고 CSV와 오프라인 원문 가져오기도 중복 없이 처리합니다. 한 시각 그룹에 안전하게 추적할 수 없을 만큼 서로 다른 메시지가 많으면 방과 기간별로 파일을 나누라는 안내와 함께 가져오기를 거절합니다.
- **배치**: 메시지는 최대 256건 또는 약 2 MiB 단위의 배치로 기록합니다. 배치 하나는 전부 성공하거나 전부 취소됩니다. 가져오기가 실패하거나 취소되면 진행 중이던 배치는 되돌리고, 이미 기록한 배치는 남습니다.
- **다시 시도**: **같은, 바뀌지 않은 파일**을 다시 가져오면 안전하게 이어집니다. 메시지마다 고정된 ID가 있어서 이미 저장된 것은 건너뛰고 나머지만 추가합니다. 결과에는 커밋한 수와 건너뛴 수가 나옵니다(`atomicity: batch`, `resume: same_file`). 그사이 내용이 바뀐 파일은 다른 파일이니 미리보기를 확인하세요.
- 가져오기나 미리보기를 **취소**하면, DB가 실시간 메시지를 쓰느라 바쁠 때도 바로 멈춥니다.

## CLI를 통한 가져오기 및 색인

```bash
# 1. 카카오톡 CSV 데이터 가져오기 등록
masamong imports start --source kakao_csv --path friends.csv --room kakao:friends --label "친구방" --timezone Asia/Seoul

# 2. 색인 소요 비용 및 시간 사전 점검 (Dry Run)
masamong memory blocks prepare --source_room kakao:friends --dry_run true

# 3. 예산 한도를 지정하여 백그라운드 색인 시작
masamong memory blocks prepare --source_room kakao:friends --budget_usd 0.50

# 4. 등록된 블록 목록 및 고유 ID 조회
masamong memory blocks list

# 5. 특정 Discord 채널에 기억 블록 연결
masamong channels view attach --guild_id <서버ID> --channel_id <채널ID> --block_id <블록ID>
```

## 일괄 처리(Batch) 모드

색인을 **지금 바로** 돌리는 대신, 제공사에 **일괄 작업(batch job)** 으로 맡기는 방식입니다. 블록 화면과 가져오기 마법사의 준비 단계에서 **지금 실행**과 **일괄 처리 (반값)** 중에서 고릅니다. 한 번의 사전 점검으로 두 가격이 함께 나오고, "이 블록 기본 방식으로 저장"을 누르면 그 블록은 앞으로 고른 방식으로 시작합니다(예산 기본값과 같은 방식).

- **비용**: 일괄로 맡길 수 있는 부분(임베딩·요약)이 정가의 약 절반입니다.
- **시간**: 보통 몇 분에서 몇 시간, 길어도 약 24시간 안에 끝납니다(호스트에 따라 48~96시간까지). 그동안 블록은 "제공사의 일괄 처리를 기다리는 중 (n건, 보낸 시각)"으로 표시되고, 끝나면 결과를 자동으로 받습니다. 서비스를 다시 시작해도 이어집니다.
- **지원 제공사**: OpenAI, Anthropic(요약 등 대화 모델만), Google Gemini, OpenRouter, NanoGPT(대화 모델만). CometAPI, OpenGateway, 직접 입력한 OpenAI 호환 호스트 등은 일괄을 지원하지 않아 바로 실행됩니다. 일괄로 맡길 수 없는 부분과 실패한 부분은 일괄이 끝난 뒤 자동으로 바로 처리합니다.
- **멈추는 것**: 그 채널의 Discord 자동 갱신은 일괄이 제공사에 있는 동안 멈춥니다. 다른 블록의 색인에는 영향이 없습니다.
- **취소**: **작업(Jobs)** 화면이나 블록 화면에서 취소하면 제공사의 일괄 작업도 취소합니다. 이미 끝난 분량은 비용이 청구되고 저장됩니다. 취소가 바로 끝나지 않으면(OpenRouter처럼 취소가 없는 곳 포함) 블록은 "이미 보낸 일괄 처리를 마저 받는 중"으로 남아, 제공사에 남은 분량을 끝까지 받아 저장합니다. 그동안 같은 일을 바로 처리로 다시 하지 않습니다.
- **전송 실패**: 제공사가 일괄 전송을 거부하면 작업은 실패로 끝나고, 정가로 바로 처리하지 않습니다(모델이 일괄을 지원하지 않는 경우만 바로 처리). 전송에 대한 답이 끊겨 접수 여부를 알 수 없으면 이중 결제를 막으려고 블록을 멈춰 둡니다. 제공사 콘솔의 Batch 목록을 확인한 뒤 블록 화면의 **일괄 처리 버리기**로 정리하세요.
- 같은 블록의 일괄이 이미 제공사에 있으면 새로 보내지 않고 그 결과를 이어서 받습니다("이 블록의 일괄 처리가 이미 전송돼 있어…").

```bash
# 사전 점검 (일괄 가격이 batch_usd로 함께 나옴)
masamong memory blocks prepare --source_room kakao:friends --dry_run true --mode batch

# 일괄로 시작 / 이 블록의 기본 방식으로 저장
masamong memory blocks prepare --source_room kakao:friends --mode batch
masamong memory blocks update --source_room kakao:friends --mode batch
```

## 색인 파이프라인의 동작 원리

- **청크(리프 블록) 분할**: 대화 흐름을 방 단위로 묶어 **메시지 8개 또는 30분 이상의 공백**을 기준으로 개별 청크(Leaf)로 분할합니다.
- **임베딩 및 요약 생성**: 각 청크마다 의미 검색을 위한 벡터 임베딩을 생성하며, 요약 옵션이 켜져 있는 경우 단락 요약과 요약 임베딩을 함께 만듭니다. (토큰 비용의 대부분은 요약 생성에서 발생하므로, 비용을 절감하려면 `memory.summaries: false`로 설정하고 순수 임베딩 검색으로 운영할 수 있습니다.)
- **증분 캐싱**: 이미 색인이 완료된 청크는 캐시를 재사용하며, 내용이 변경되거나 새롭게 추가된 청크만 비용 효율적으로 갱신합니다.
- **실시간 대화 버퍼링**: 실시간 수집 채널의 최신 청크는 메시지 8개가 채워지거나 30분간 대화가 없을 때까지 '열린 상태'로 유지되어 임베딩을 유보하며, 이 기간의 최근 대화는 프롬프트의 최근 대화 문맥(Context)에 직접 주입됩니다.
- **주기적 백그라운드 색인**: 데몬은 `memory.index_interval_min`(기본 10분) 주기마다 새로운 대화가 유입된 채널을 탐색하여 색인을 이어가며, 회당 `memory.index_budget_usd`(기본 $1.00) 지출 한도를 초과하지 않습니다.
- **장애 복구 보장**: API 공급자 오류, 스토리지 지연, 예산 한도 도달 등으로 색인이 일시 중단된 대화방은 다음 주기에서 안전하게 이어서 처리됩니다. 대기 큐는 영속 저장소에 보존되어 재부팅 후에도 작업이 누락되지 않습니다.
- **무중단 인덱스 교체**: 색인 설정을 변경하더라도 기존 인덱스는 중단 없이 조회되며, 새 설정의 색인 작업이 백그라운드에서 완료되는 즉시 자연스럽게 교체됩니다.

## 검색 전략 설정 (`memory.retrieve`)

설정 파일의 `memory.retrieve` 옵션을 통해 상황에 맞는 검색 방식을 선택할 수 있습니다:

| 모드 | 동작 방식 |
|---|---|
| `auto` (기본값) | 키워드(Lexical)와 벡터(Semantic) 하이브리드 검색을 결합하고, 점수가 모호한 경우에만 재순위(Rerank) 모델을 선별 호출 |
| `hybrid` | 키워드 + 벡터 하이브리드 검색만 수행 (재순위 모델 미호출, 빠른 속도 및 비용 최적화) |
| `rerank` | 모든 검색 후보에 대해 항상 재순위 모델을 실행하여 최적의 정확도 확보 |
| `off` | 기억 검색 파이프라인 비활성화 |

> [!TIP]
> 재순위 API가 장애로 응답하지 않으면 하이브리드 결과로 대체하고, 기억 검색 전체가 실패하더라도 기본 컨텍스트만으로 답변을 생성하므로 대화 서비스가 중단되지 않습니다.

## 기억 검색 검증 및 정정

```bash
# 특정 채널 맥락에서 기억 검색 근거 및 연관도 점수 점검
masamong memory search --guild_id <서버ID> --channel_id <채널ID> --query "캠핑 어디 가기로 했지"

# LLM 호출 없이 순수 키워드로 대화 원문 검색 (비용 발생 없음)
masamong messages search --rooms kakao:friends --query "텐트" --top_k 20

# 실제 채널에 전송하지 않고 가상 답변 결과 사전 테스트
masamong chat --guild_id <서버ID> --channel_id <채널ID> --message "요즘 누가 제일 바빠?"
```

관리 콘솔의 **기억 탐색(`/memory`)** 메뉴에서는 검색된 모든 기억의 원문 근거를 투명하게 열람할 수 있으며, 왜곡된 기억을 직접 **정정**하거나 **검색에서 제외**할 수 있습니다. 또한 동일 인물의 서로 다른 닉네임(카카오톡 이름, Discord 계정명)을 수동으로 **계정 병합**하여 일관된 맥락을 유지할 수 있습니다.

## 페르소나 및 응답 스타일 가이드

Masamong은 딱딱한 보고서 봇이 아니라 친근한 대화 상대입니다.

- 기억을 인용할 때는 "대화 기록에 따르면 ~입니다"와 같은 기계적인 표현 대신 "그때 ~했잖아", "~였던 걸로 기억해"처럼 일상적인 대화 톤을 유지합니다.
- 기억이 흐릿하거나 찾을 수 없는 경우 무리하게 지어내지 않고 자연스럽게 넘기거나 위트 있게 답변합니다.
- "누가 텐트 챙기기로 했지?"처럼 **누가 무엇을 했는지**는 기억에 있을 때만 말합니다. 없으면 아무도 후보로 올리지 않고(묻는 사람이나 봇 자신을 찍는 것도 추측), 기억 안 난다고 한 뒤 방에 아는 사람이 있는지 묻습니다.
- 단, 타인에게 피해를 줄 수 있는 민감한 사생활 정보(연애, 건강, 금전, 법적 문제 등)는 절대 임의로 지어내지 않으며, 날씨나 시세와 같은 도구 데이터는 왜곡 없이 정확하게 전달합니다.

- 타 서버, 타 채널, 또는 비공개 DM의 대화 기록이 자동으로 통합되거나 상호 노출되지 않습니다.
- 표시 닉네임이 같다는 이유만으로 사용자를 자동 병합하지 않으며, 계정 병합은 반드시 관리자의 수동 확인을 거칩니다.
- 상세한 보안 정책은 [보안과 개인정보](https://github.com/kim0040/masamong2/wiki/보안과-개인정보) 문서를 참조하세요.
