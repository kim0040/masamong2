# 설정 레퍼런스

**한국어** | [English](https://github.com/kim0040/masamong2/wiki/Configuration-Reference)

설정은 데이터 폴더의 `config.yaml` 한 파일이며, 모든 변경은 리비전으로 DB에 기록됩니다. 보통은 콘솔 **설정** 화면이나 명령(`channels configure`, `tools configure` 등)으로 바꾸고, 파일을 직접 고친 뒤에는 `masamong config apply --file config.yaml --base_revision N`으로 적용합니다(검증 → 리비전 기록 → 재시작 없이 반영).

`--base_revision`은 내가 고치기 시작한 시점의 리비전입니다. 더 새로운 리비전을 덮어쓰지 않도록 막는 값이라, 그사이 콘솔이나 다른 터미널, Discord 관리 명령으로 바꾼 내용이 사라지지 않습니다. 번호는 시작할 때 쓰는 같은 명령에서 얻습니다. `config show`는 `revision`을, `config diff`와 `config validate`는 `base_revision`을 출력합니다. 이 값 없이 적용하면 리비전 0과 비교해서 `CONFIG_CONFLICT`가 납니다(새 인스턴스에서는 "expected 1 got 0"). 현재 리비전을 읽어서 다시 실행하라는 신호입니다.

```bash
masamong config show                      # 현재 설정. 아래에 넘길 번호가 "revision"
masamong config diff --file new.yaml      # 바뀌는 항목 (base_revision도 함께 출력)
masamong config validate --file new.yaml
masamong config apply --file new.yaml --base_revision 3
masamong config rollback --revision 12
masamong config changes                   # 변경 기록
```

스크립트에서는 JSON에서 번호를 바로 꺼냅니다.

```bash
rev=$(masamong config show --output json | python3 -c "import sys,json; print(json.load(sys.stdin)['output']['revision'])")
masamong config apply --file new.yaml --base_revision "$rev"
```

```powershell
$rev = (masamong config show --output json | ConvertFrom-Json).output.revision
masamong config apply --file new.yaml --base_revision $rev
```

> **키는 설정에 값으로 넣지 않습니다.** `env:이름`, `file:경로`, `keychain:계정` 참조만 씁니다([보안과 개인정보](https://github.com/kim0040/masamong2/wiki/보안과-개인정보)).

## instance

| 키 | 기본값 | 설명 |
|---|---|---|
| `id` | setup 때 정함 | 인스턴스 이름 |
| `data_dir` | 데이터 폴더 | 자동 기록 |
| `bot_names` | `[마사몽, masamong]` | 봇을 부르는 이름. 첫 이름이 프롬프트에 쓰임 |
| `expected_bot_id` | `""` | 이 봇 ID가 아닌 토큰으로 연결되면 명령 등록 거부 (토큰 실수 방지). 콘솔이 토큰을 저장한 뒤 Discord에서 읽어 채움(`masamong discord check --apply`) |

## admin

| 키 | 기본값 | 설명 |
|---|---|---|
| `web.enabled` | `true` | 관리 콘솔 켜기 |
| `web.bind` | `127.0.0.1:8787` | 콘솔 주소. **loopback만 허용**, 원격은 `masamong connect` 또는 아래 `web.hosts` 사용 |
| `web.hosts` | `[]` | `127.0.0.1`/`localhost` 외에 콘솔이 응답할 이름(최대 8개, 포트·경로 없이). 이 컴퓨터의 프록시가 넘겨 주는 이름용이며 보통 `tailscale serve`의 tailnet 이름. 콘솔은 여전히 loopback에서만 수신하고, 목록에 없는 이름은 거절. 화면 및 접속 설정에서 한 번에 추가 |

## i18n

| 키 | 기본값 | 설명 |
|---|---|---|
| `default_locale` | `en` | 서버·채널 설정이 없을 때 답변 언어 |
| `fallback_locale` | `en` | 번역이 없을 때 |
| `bundled_locales` | `[en, es, ja, ko, zh-Hans]` | 불러올 언어 |
| `timezone` | `Asia/Seoul` | 하루 한도·통계·백업 시각의 기준. `Asia/Seoul` 같은 IANA 이름이어야 합니다. 프로그램이 시간대 데이터베이스를 자체로 갖고 있어서 Go나 시스템 사본이 없는 Windows에서도 이름이 통합니다. 모르는 이름은 조용히 UTC로 취급하지 않습니다. `masamong doctor`와 홈의 확인 필요 목록에 표시됩니다. 방의 `naive_timezone`이 틀리면 색인은 인스턴스 시간대를 사용하고 해당 방을 경고에 표시합니다. 사람이나 알림에 저장된 시간대가 틀리면 대체값을 쓰기 전에 로그에 남깁니다 |
| `polite_default` | 새 인스턴스는 `true` | 말투를 고르지 않은 방이 반말 친구(`friendly_ko`, `friendly_ja`) 대신 다정한 존댓말(`warm_ko`, `warm_ja`)로 시작합니다. 이 키가 생기기 전에 만든 인스턴스는 키가 없어서 켤 때까지 **반말을 그대로 씁니다**. **설정 → 새 방은 존댓말로 시작** 또는 `polite_default: true`로 켭니다 |

## providers

외부 공급자. 키는 공급자 ID, 값은 다음 필드입니다.

| 필드 | 설명 |
|---|---|
| `kind` | `openai_compat`(모델), `kma`, `open_meteo`, `finnhub`, `exchangerate`, 웹 검색 `tavily`·`linkup`·`exa`·`serper`·`brave`·`tinyfish`·`kakao_search`, 링크 읽기 `jina_reader` |
| `base_url` | API 주소 (OpenAI 호환이면 어떤 호스트든 가능: OpenRouter, OpenAI, Gemini, 자체 서버 등). HTTPS여야 합니다. 일반 HTTP는 같은 컴퓨터의 모델 서버를 위해 `localhost`와 루프백 IP(`127.0.0.0/8`, `::1`)에만 허용합니다. 아이디·비밀번호가 든 주소와 `localhost.example.com` 같은 비슷한 호스트는 거절하고, 다른 스킴·호스트·포트로 가는 리다이렉트는 따라가지 않습니다 |
| `api` | `openai_compat`만. 호스트 종류 `openrouter`·`openai`·`gemini`·`anthropic`(Messages API, 주소 무관)·`compatible`. 비우면 `base_url`의 호스트로 판별합니다. 테스트 서버나 다른 회사의 Anthropic 형식 주소처럼 주소로 알 수 없을 때 적습니다 |
| `credential_ref` | 키 참조 |
| `daily_limit` | 하루 호출 한도 (재시작해도 유지) |
| `disabled` | 끄기 |
| `byok_only` | OpenRouter 전용 선택 옵션(미설정 = 보통 경로). 모델 계열(모델 이름의 `/` 앞부분)을 그 계열의 대화 요청만 보낼 업스트림 공급자 하나에 연결하고, 다른 곳으로 넘기지 않습니다. `{anthropic: anthropic}`이면 `anthropic/*`는 Anthropic으로만 갑니다. OpenRouter에 내 Anthropic 키를 넣고(BYOK, 공유 용량 사용 안 함) 쓰면 그 모델은 내 키로만 돌고, 키가 실패하면 OpenRouter 크레딧 대신 그 역할의 대체 모델이 답합니다. 비용 집계에는 업스트림 청구액도 들어갑니다. 콘솔 OpenRouter 카드에 Claude용 스위치가 있습니다 |

기본 공급자: `openrouter`(모델), `kma`(기상청), `openmeteo`(키 없는 날씨), `finnhub`(주가), `exchangerate`(환율), `kakao`·`tavily`·`linkup`·`exa`·`serper`·`brave`·`tinyfish`(웹 검색). 이 목록이 생기기 전에 만든 인스턴스는 콘솔 **연결 → 공급자 추가**에서 더합니다. 링크 읽기(`jina`, Jina Reader)는 설정에 없어도 키 없이 기본으로 동작하고, 키를 쓰려면 공급자로 추가합니다.

업그레이드 전 커밋한 공급자나 HTTP 도구 주소를 새 URL 정책이 거절해도 데몬은 멈추지 않습니다. 해당 공급자나 도구를 끄고, 로그와 `doctor`의 확인 필요 항목에 어떤 설정이 거절되었는지 표시합니다. 주소를 고친 뒤 다시 켜세요. 새 설정은 계속 엄격하게 검사하며 올바르지 않으면 적용을 거절합니다.

호스트 종류마다 다른 점은 어댑터가 알아서 맞춥니다.

| | OpenRouter | OpenAI | Gemini | CometAPI | NanoGPT |
|---|---|---|---|---|---|
| 추론 조절 | `reasoning: {effort}` | `reasoning_effort` | `reasoning_effort` | `reasoning_effort` | `reasoning_effort` |
| 출력 길이 | `max_tokens` | `max_completion_tokens` | `max_tokens` | `max_tokens` | `max_tokens` |
| 키 확인 | `GET /key` | `GET /models` | `GET /models` | `GET /models` | 역할 모델에 1토큰 요청(모델 목록이 키 없이 열림) |
| 재정렬(rerank) | 있음 | 없음 | 없음 | 없음 | 있음(한 번에 문서 1,024개까지, 넘으면 나눠 보냄. 원래 점수는 0~1로 바꿈) |
| 이미지 | 대화 API(modalities) | `/images/generations` | 네이티브 `generateContent` | 대화 API, 본문의 마크다운 data URI | `/images/generations`(대화 API를 거절하면 바꿔 묻고 기억) |
| 비용 | 응답에 포함 | 공식 가격표 | 공식 가격표 | 참고 단가 | 모델 목록의 가격(`?detailed=true`) |

모델이 받지 않는 생각 강도는 요청을 보내기 전에 받는 강도 중 가장 가까운 것으로 바꿉니다. 강도 목록은 모델 목록(OpenRouter의 `reasoning.supported_efforts`, NanoGPT의 `reasoning_efforts`)에서 가져오고, 목록에 없으면 호스트 문서를 따릅니다. OpenAI의 GPT-6 Astra·GPT-6.1 Sol과 Gemini 3.x/4에는 `none`이 없어서 `none`은 가장 낮은 강도로 보냅니다. OpenAI 자체 호스트의 GPT-6 Astra·GPT-6.1 Sol·GPT-6.1 Terra는 도구를 Responses API로만 받습니다. 마사몽은 아직 이 API를 쓰지 않으므로 이 모델들은 도구 없이 답합니다.

잔액이나 지출 한도를 다 쓴 경우(OpenAI `credit_balance_exhausted`와 지출 한도, NanoGPT `*_usd_limit`, OpenGateway `budget_exceeded`, `limit_source`가 붙은 OpenRouter 403)와 호스트가 연결할 수 없는 모델(`model_not_found`, 503으로 와도 같음)은 다시 시도하지 않고 바로 대체 모델이 답합니다. 호출 빈도 제한은 지금처럼 기다렸다가 다시 시도합니다. 콘텐츠 필터 때문에 온 OpenRouter 403은 키를 거절된 것으로 표시하지 않고 대체 모델로 넘깁니다.

**역할 채우기**가 OpenRouter 모델을 추천할 때는 이미지 출력을 지원하는 목록 항목을 이미지 모델로 인식하며, 대화 역할에는 넣지 않습니다.

CometAPI와 NanoGPT는 **연결 → 공급자 추가**에서 바로 고를 수 있고(`providers add --host cometapi`), 추천 모델 규칙도 따로 있습니다(CometAPI 임베딩은 기억 레시피를 측정한 `qwen3-embedding-8b`). 가격표가 없는 공급자의 모델은 **참고 단가**를 씁니다: 같은 모델 이름(마지막 `/` 뒤, `:변형` 제외)을 OpenRouter 공개 목록(키 없이 하루 한 번)에서 찾고, 이미지 모델은 이미지 출력 단가(`image_output`)로 셉니다. CometAPI는 공식가의 약 80%를 청구하므로 참고 단가는 예산을 안전한 쪽으로 잡습니다. 어디에도 단가가 없는 모델을 쓰면 홈에 "단가를 모르는 모델" 알림이 뜹니다(월 예산이 그 비용을 막지 못하기 때문).

**Anthropic(Messages API).** `api: anthropic`은 주소와 상관없이 Anthropic의 Messages API를 그대로 씁니다. Anthropic 공식 주소(`https://api.anthropic.com/v1`)와 다른 회사의 Anthropic 형식 주소(`https://<호스트>/anthropic`) 모두 됩니다. `/v1`이 없으면 붙이고, `…/v1/messages`까지 넣었으면 잘라 씁니다. 요청은 `{base}/v1/messages`로 `x-api-key`·`anthropic-version`과 함께 보냅니다. `api.anthropic.com`이 아닌 호스트에는 키를 `Authorization: Bearer`로도 보냅니다. 그 헤더만 읽는 곳이 있기 때문입니다. 생각 강도는 모델 기능 정보에 따라 `thinking`과 `output_config.effort`로 보냅니다. 기능 정보는 모델 목록을 새로 읽을 때와 공급자를 테스트할 때 읽습니다. 테스트는 결과를 먼저 보여 주고, 그다음 목록에 없는 역할 모델마다 `GET /v1/models/{id}`로 한 번 물어봅니다. 대화 호출은 먼저 묻지 않습니다. 아무것도 모르는 모델에는 적응형 생각을 보냅니다. 호스트가 이를 거절하면 토큰 예산을 정한 생각을 보내 보고, 그것도 거절하면 생각 필드를 뺍니다. 호스트가 거절한 필드는 빼고 기억합니다. 이 기억은 그 공급자의 모든 호출에 한 시간 동안 쓰입니다. 모델 목록이 그 모델에 대해 새로운 정보를 주거나, 공급자 설정을 바꾸거나, 키를 저장하거나, 공급자를 테스트하면 그 전에라도 지웁니다.

| 생각 강도 | 생각을 끌 수 있는 모델(Haiku 5.5) | 도구 호출 사이에만 생각(Sonnet 5.5) | 항상 생각(Opus 5.5) | 예산형 생각(Haiku 4.5) |
|---|---|---|---|---|
| `none`, `minimal` | `thinking: disabled` | `thinking: between_tools` | `thinking` 없이 강도 `low` | `thinking: disabled` |
| `low` … `max` | `thinking: adaptive` + `output_config.effort` | 같음 | 같음 | `thinking: enabled`와 토큰 예산(1024–16384) |

생각할 출력 여유는 호출의 한도 위에 따로 줍니다(`low` 1024부터 `max` 16384토큰까지). 도구를 쓰는 동안 서명된 생각 블록은 바꾸지 않고 그대로 돌려보냅니다. Anthropic 형식 모델이 한 번 답한 뒤에는 도구 목록과 시스템 프롬프트도 그 턴이 끝날 때까지 그대로 둡니다. 턴 중에 닫힌 도구도 목록에 남고, 부르면 "지금은 쓸 수 없음"으로 답합니다. 예비 모델이나 다른 호스트가 이어받으면 다른 모델·호스트가 만든 생각 블록은 빼고 보냅니다. `temperature`는 받는다고 정해 둔 Claude 모델(`hosts.json`의 Claude 4.6 이하)에만, 생각하지 않는 호출에서 보냅니다. Anthropic 형식 호스트의 다른 모델은 다른 회사 모델까지 모두 기본 온도로 답합니다. 예산형 생각 모델(Haiku 4.5)이 도구를 쓰는 중에 다른 모델·호스트의 차례를 이어받으면 그 차례는 생각 없이 답합니다. 마지막 답에 생각 블록이 없으면 이 모델이 요청을 거절하기 때문입니다. 지출 한도에 닿았거나 크레딧 잔액이 부족하다는 답은 한도 소진으로 보고 그 역할의 예비 모델이 답합니다. 프롬프트 캐시는 아직 보내지 않습니다. 호스트가 캐시 사용량을 알려 주면 캐시 읽기는 입력 단가의 0.1배, 캐시 쓰기는 1.25배로 셉니다. Anthropic 형식의 모델 목록이 없는 호스트도 연결 테스트는 통과합니다("목록 없음"). 이때는 **변경**에서 모델 이름을 직접 넣으세요. 키는 역할이 그 호스트를 쓰게 된 뒤 1토큰 답으로 확인합니다. 모델이 거절하면(`stop_reason: refusal`) 그 역할의 예비 모델이 답합니다.

모델마다 받지 않는 옵션(예: Gemini 3.8 Flash는 `reasoning_effort: minimal`을, OpenAI 추론 모델은 `temperature`를 거부)이 있으면 그 옵션을 빼고 한 번 다시 보내고, 그 모델에서는 그 형태를 기억합니다. 의도 파악(`planner`)이나 답변(`response`) 모델이 실패하면(모델 없음, 과부하, 시간 초과, 생각하다 출력 한도 소진) 다른 쪽 모델이 같은 요청을 한 번 받습니다. 설정은 따로 없습니다. 공식 가격표는 `internal/providers/openai/hosts.json`에 확인 날짜와 함께 있으며, 운영자가 입력한 단가가 늘 먼저입니다.

## models

역할별 모델. 역할: `response`, `planner`, `summary`, `embed`, `rerank`, `image`(이미지 생성 도구. 비우면 이미지 생성은 "설정되지 않음"으로 답함), `vision`(선택: 멤버가 보낸 사진을 읽는 모델). `vision`을 정하면 답변 모델이 사진을 받는 모델이어도 이 모델이 모든 사진을 설명하고, 답변 모델은 그 설명을 글로 받습니다. 이 모델이 실패하거나 거절하면 예전 방식으로 갑니다. 비워 두면 답변 모델이 사진을 받을 때는 사진을 그대로 받고, 아니면 `planner` 모델, 그다음 `response` 모델이 설명합니다. `image`와 `vision`은 비워 둘 수 있고, 역할 표에 **비우기** 버튼이 있습니다.

| 필드 | 설명 |
|---|---|
| `provider` | `providers`의 ID |
| `model` | 모델 이름 |
| `dimensions` | 임베딩 차원 (`embed`만). 기본 `1024`, `0` = 모델 전체 폭 |
| `price_in_per_mtok`, `price_out_per_mtok` | 100만 토큰당 USD. 공급자가 비용을 알려 주지 않을 때 계산에 사용 |
| `timeout_seconds` | 한 번 호출의 제한 시간(초). 0 = 기본(`planner` 30, `response` 90), 그 밖에는 5–600. 넘거나 빈 답이 오면 다른 대화 모델로 넘김. 콘솔 **연결 → 모델 → 단가 설정** |
| `effort` | 대화 역할(`response`, `planner`, `summary`, `vision`). 생각하는 모델이 한 번 답하기 전에 얼마나 생각할지: `none`, `minimal`, `low`, `medium`, `high`, `xhigh`, `max`. 비우면 `low`. 우선순위는 표 아래에 있습니다. 콘솔 **연결 → 모델 → 단가 설정** |
| `fallbacks` | 대화 역할. 역할 모델이 실패하면 차례로 묻는 모델 최대 3개(`provider`, `model`, 선택 `price_in_per_mtok`·`price_out_per_mtok`·`timeout_seconds`·`effort`). 예비 모델의 `effort`는 그 모델에서 역할의 값을 대신하고, 비우면 역할의 값을 따릅니다. 콘솔 **연결 → 모델 → 예비 모델** |

**생각 강도 우선순위**

1. 역할의 호출은 그 역할의 `effort`로 요청합니다(비우면 `low`). 예비 모델에 `effort`가 있으면 그 값으로 요청합니다.
2. 일부 호출은 일부러 생각 없이 보냅니다. 의도 파악 모델의 이름 부름·참조·이어 말하기 판단, 기억의 한 줄 요약과 요약 역할의 정리 글, 운세가 그렇습니다. 출력 한도가 짧아서 생각에 다 쓰일 수 있기 때문입니다. 역할의 `effort`가 비어 있으면 `none`으로 요청합니다. 값을 정하면 이 호출도 생각하지만 `low`를 넘지 않고, 생각할 출력 여유를 더 받습니다. 요약 역할의 `effort`는 그 일 자체의 강도라서 정한 그대로 씁니다. 자기 `effort`가 없는 예비 모델은 답하는 역할의 규칙을 그대로 따릅니다.
3. 그다음 호스트와 모델에 맞춥니다. 모델 목록상 생각하지 않는 모델에는 필드를 보내지 않습니다. 모델이 받지 않는 강도는 바로 아래 강도로 낮추고, 한 번만 로그에 남깁니다. `xhigh`·`max`는 Gemini와 이를 거절하는 호스트에서 `high`가 됩니다(한 번 거절되면 기억). OpenAI·OpenRouter는 `xhigh`까지 받으므로 `max`는 `xhigh`가 됩니다.

콘솔 표시는 모델 목록에서 옵니다. 목록에 정보가 있으면 **생각 지원**이나 **생각 없음**이라고 표시합니다(Anthropic 기능 정보, OpenRouter `supported_parameters`, NanoGPT 상세 목록, Gemini 네이티브 목록). 정보가 없으면(OpenAI 목록, CometAPI) **확인 안 됨**으로 표시합니다. 모델이 받지 않는 강도는 고를 수 없게 흐리게 보입니다. 예산형 생각 모델(Claude Haiku 4.5)은 강도 필드가 없지만 `low`부터는 강도마다 토큰 예산이 달라서 모든 강도를 고를 수 있습니다.

Anthropic에서 `low`는 이제 강도 `low`의 적응형 생각입니다. 쉬운 질문에도 조금 생각할 수 있어서, 전혀 생각하지 않던 예전보다 출력 토큰과 시간이 조금 늘 수 있습니다. 이때 생각할 출력 여유는 가장 작은 1024토큰입니다. 생각을 끄려면 `none`으로 두세요.

재정렬이 없는 공급자(OpenAI, Gemini)를 `rerank`에 두거나 재정렬 공급자에 키가 없으면, 기억 검색은 재정렬 없이 융합 순위로 답합니다(콘솔이 역할 표에 표시). 역할마다 공급자를 따로 둘 수 있어서, 예컨대 대화·임베딩은 Gemini, 재정렬만 OpenRouter로 쓸 수 있습니다. 역할 표의 **변경**을 누르면 고른 공급자(같은 창에서 다른 공급자로 바꿀 수 있음)의 모델 목록에 사진 입력·도구 배지, 문맥, 100만 토큰당 입력/출력/캐시 가격이 나오고, 검색과 가격·문맥 정렬이 되며, `vision`에서는 목록이 알려 줄 때 사진을 받는 모델만 보입니다(OpenAI·Gemini처럼 이름만 주는 목록은 알려 주지 않아 모두 보이고 안내가 붙습니다). `response`·`planner`에서는 목록이 "도구 없음"이라고 한 모델에 표시가 붙고, 가격이 없는 목록은 "가격 정보 없음"이라고 말합니다.

콘솔 **연결**에서 공급자 카드의 **추천 모델로 채우기**를 누르면 그 공급자 목록에서 역할마다 가장 최신 정식 모델을 골라 보여 주고, 체크한 역할만 한 번에 바꿉니다(고르는 규칙도 `hosts.json`에 있고, OpenRouter는 기본 역할마다 규칙이 있습니다). 공급자가 돌려준 모델 중 규칙에 맞는 것이 하나도 없으면 채울 모델이 없으니 `picks`가 빈 목록인 채로 성공하고, 창에는 아래의 가성비 대안만 보입니다(그중에서 고르거나 직접 고르세요). 가성비 대안도 하나도 없을 때만 이유("응답된 모델 중 지원되는 추천 규칙에 맞는 모델이 없습니다.")와 함께 실패하니, 그때는 직접 고르세요. 같은 창에는 역할마다 **가성비 대안**도 최대 3개 나옵니다(대화 역할은 문맥 32k 이상 채팅 모델, `response`·`planner`는 목록이 알려 주면 도구 지원, `vision`은 사진 입력(이름만 주는 OpenAI·Gemini 목록은 이를 알려 주지 않으니 `hosts.json`이 사진을 받는 것으로 아는 모델을 꼽아 둡니다), `embed`는 임베딩 모델, `image`는 이미지 생성 모델). 공급자 가격으로 (입력×3 + 출력)/4(100만 토큰당)를 계산해 싼 순서이며, 그 역할의 추천 규칙에 나오는 계열이 먼저 나오고 계열마다 한 모델(가장 새 세대, 즉 같은 주 버전 중 가장 싼 것)만 보여 줘서 가능하면 상위 3개가 서로 다른 계열입니다. 가격은 청구 계산과 같은 순서로 읽습니다: 공급자 목록, 공식 가격표, 공개 참고 목록(출처가 표시됨). 가격을 모르는 모델, `:free`·`:batch` 같은 변형, `…-latest` 별칭, 미리보기·실험 모델은 뺍니다. **이 모델로**는 그 역할 하나만 바꿉니다(기억이 색인된 동안은 임베딩을 여기서 바꾸지 않습니다. 역할 표에서 바꾼 뒤 **기억 블록**에서 다시 색인하세요). 이미 색인된 기억이 있으면 임베딩은 기본으로 빠지고, 체크하면 다시 색인할 양과 예상 비용을 보여 줍니다(`include_embed`, `reindex`; 저장소의 `docs/memory-operations.md`).

`embed` **모델**을 바꾸면 기억을 다시 임베딩해야 합니다(콘솔이 예상 비용을 보여 줌). 이전 모델의 벡터는 캐시에 남겨 두므로 원래 모델로 되돌릴 때는 비용이 들지 않습니다.

`dimensions`의 기본은 **1024**입니다(2026-10-13부터). 실제 대화 기록 세 세트로 재 보니 재순위가 있으면 4096과 검색 품질이 같았고, 메모리는 21~27% 적게 쓰며, 속도와 비용은 같았습니다(임베딩 요금은 토큰 단위). 앞부분만 잘라 써도 되게 학습된(Matryoshka) 모델만 자릅니다. 목록과 모델별 전체 폭은 `hosts.json`의 `embed_widths`에 있습니다(qwen3-embedding 8b·4b·0.6b, OpenAI text-embedding-3 large·small, gemini-embedding-001·gemini-embedding-2). 목록에 없는 모델은 항상 전체 폭입니다. 목록에 있고 전체 폭이 1024보다 큰 임베딩 모델을 고르면 1024가 됩니다. **추천 모델로 채우기**는 적용 결과 재순위 모델이 없게 되면 전체 폭을 제안합니다(재순위가 없으면 1024가 대화 흐름 질문 120개 중 5개를 덜 찾았습니다). 다만 작은 기기(hostprofile `small`)는 1024를 유지합니다. 직접 적은 `dimensions` 값은 자동으로 바꾸지 않습니다.

`dimensions`를 **줄이면**(예: 4096 → 1024, 콘솔 **연결** 또는 `masamong models embed-width`) 다음 로드 때 저장된 벡터의 앞부분만 남겨 그 자리에서 바꾸므로 비용이 들지 않습니다. 준비된 기억 블록은 ready 그대로이고 채널에 붙인 연결도 유지되며, 벡터 메모리와 디스크가 비율만큼 줄어듭니다. 콘솔은 전체 폭보다 작은 1024와 2048만 제안합니다. 1024보다 좁히면 메시지 벡터 공간도 바뀌어 모든 메시지를 다시 임베딩해야 하기 때문입니다. 다시 **늘리려면** 전부 다시 임베딩해야 합니다(콘솔이 먼저 예상치를 보여 줌). 디스크에는 고른 폭으로만 저장하므로, 나중에 넓히려면 원문 메시지로 다시 임베딩합니다.

## limits

| 키 | 기본값 | 설명 |
|---|---|---|
| `profile` | `lite` | 프로필 이름 |
| `monthly_budget_usd` | `"10.00"` | 이번 달 모델 비용 상한. 넘으면 답하지 않음. Usage 화면이나 `masamong usage reset`으로 이번 달 계산을 지금부터 다시 시작할 수 있으며, 일별 기록과 제공자 사용량·키 한도는 바뀌지 않습니다. 달은 UTC 기준(한국 시간으로는 매월 1일 오전 9시에 새 달) |
| `per_request_budget_usd` | `"0.03"` | **답변당 예산.** 답변 하나가 이만큼 쓰면 남은 도구와 기억 검색은 건너뜀. 답변 자체(한 모델이 실패했을 때 대신 답하는 다른 대화 모델 포함)는 함. 혼자 이보다 비싼 단계(그림)는 막지 않고, 그 뒤 단계만 건너뜀 |
| `max_external_attempts` | `6` (1–20) | **답변당 외부 호출 수**(모델 호출, 도구, 기억 검색). 넘으면 위와 같이 남은 도구와 기억 검색을 건너뜀. 건너뛴 단계는 대화 기록에 남음 |
| `budget_alert_percent` | `80` | 콘솔이 예산 경고를 시작하는 비율 |
| `max_concurrent_turns` | `8` (1–64) | **동시에 실행하는 답변 수.** [동시 처리와 성능](https://github.com/kim0040/masamong2/wiki/동시-처리와-성능) |

모델 호출은 시작할 때 호출 수를 예약하고 완료할 때 비용을 더합니다. 답변당 돈 한도가 있으면 선택 작업의 한도 판단은 실행 중인 모델이 끝날 때까지 취소 가능한 상태로 기다립니다. 돈을 쓰는 도구도 끝난 뒤 다음 호출을 판정합니다. 서로 다른 도구는 최대 4개까지 함께 실행하고, 같은 도구의 호출은 모델 순서대로 실행합니다. 공급자의 동시 요청 상한은 공급자 종류·기본 호스트·자격 증명 해시로 공유해 설정 재로드 뒤에도 이어지며 초당·분당 호출 수를 보장하는 제한은 아닙니다.

| `message_vectors` | `true` (설정이 없으면 켜짐) | **메시지 단위 검색.** 닫힌 조각 안의 메시지(글자·숫자 6자 이상, ㅋㅋ·이모지·문장부호는 세지 않음)를 하나씩 따로 임베딩하고, 질문과 가까운 메시지의 조각을 검색 후보에 한 줄 더 얹어 긴 조각에 묻힌 한 줄짜리 사실도 찾습니다. MRL 모델은 메시지당 최대 512차원으로 저장해 int8 벡터 데이터 약 0.5KB와 메모리가 들고, MRL 목록 밖 모델은 설치의 실제 leaf 폭을 써 더 늘 수 있습니다(명시 폭이 없으면 전체 폭). 공간 이름에는 실제 숫자 폭을 넣고 leaf 폭이 바뀌면 다시 임베딩하며, 폭을 아직 모르면 대기합니다. 메시지 벡터는 임베딩 캐시에 중복 저장하지 않으며 글자·숫자 6자 이상인 메시지만 대상입니다(실제 대화의 3분의 1~60% 정도). 측정 뒤 기본으로 켰습니다(카카오 A 질문 R@5 65%→75%, 흐름 질문은 그대로, 메시지 3~4만 개에 색인 비용 1센트 미만). `false`를 쓰면 끄고, 꺼져 있는 동안 검색은 달라지지 않습니다. 업데이트 순간에는 임베딩하지 않습니다. 폭 변경은 다음 색인 또는 블록 준비·`memory reindex`에서 `index_budget_usd` 안에 다시 만들며, 재임베딩 중 검색은 메시지 벡터를 일부 끈 것과 같습니다(진단의 `pending_messages:N`, 폭 표시). 콘솔은 다시 켜기 전에 메시지 수·토큰·비용·시간·벡터 payload 저장량을 예상합니다([기억 블록](https://github.com/kim0040/masamong2/wiki/기억-블록)) |
| `naive_timezone` | `Asia/Seoul` | 시간대 없는 시각(카카오)을 읽을 시간대 |
| `index_budget_usd` | `"1.00"` | 배경 색인 한 번의 비용 한도 |
| `turn_budget_usd` | `"0.05"` | 대화 한 번의 재순위 여유 |
| `index_interval_min` | `10` | 배경 색인 주기(분) |
| `index_workers` | `8` | 색인 한 번이 동시에 보내는 임베딩·요약 요청 수(1–256). 임베딩 호스트가 429를 자주 돌려주면 낮추고, 대량 첫 색인을 빨리 끝내려면 높인다 |
| `languages` | `[ko]` | 기억 언어 (토크나이저·조사·요약 프롬프트) |
| `agent_prompt` | `""` | 모든 채널 공통 추가 지시 |
| `leaf_split` | `time_gap` | 조각 나누기: `time_gap`(8개/30분) 또는 `fixed`(8개) |
| `person_aliases` | `{}` | 같은 사람의 다른 이름 연결 (사람이 직접 지정) |

| `episodes` | `on` | `on` · `off`. 답할 때 관련된 방 사건을 최대 3개(약 1,200자) 넣고, 근거 줄은 지금 원문에서 다시 읽음 |

## chat

| 키 | 기본값 | 설명 |
|---|---|---|
| `tool_mode` | `loop` | 답할 때 도구를 고르는 방식(2026-10-11 실키 회귀 세트에서 더 정확해 `loop`가 기본). `planner`: 기억 플래너의 계획이 도구를 정함. `shadow`: 플래너가 그대로 고르고, 네이티브 도구 루프는 옆에서 무엇을 불렀을지만 기록(대화 기록의 `tool_shadow`). `loop`: 도구 루프가 네이티브 tool calling으로 고름(최대 3회, 모든 호출은 같은 검사와 한도를 거침). 플래너는 기억 검색만 정함. 도구를 받지 않는 모델이면 그 답은 `planner`로 처리. 도구 화면에서도 바꿀 수 있음 |
| `loop_final` | `tools` | 도구 루프가 모델에게 한 번 더 묻지 않고 끝나는 때. `tools`: 한 라운드의 호출이 전부 결과 하나로 답이 되는 도구(`weather.query`, `finance.fx`, `finance.quote`, `places.search`)이고 전부 원하는 값을 찾았을 때. 실패, 빈 결과, 부분 결과, 검색으로 대신한 시세는 계속 묻는다. `search`: 위에 더해 `search.web`이 본문 있는 결과 3건 이상을 찾았을 때. 단, 모델이 `depth: deep`으로 검색했거나 메시지에 링크가 있으면 묻는다. `off`: 항상 묻는다. 결과를 보고 다음 호출을 정하는 요청("날씨 보고 갈 곳 찾아줘")은 첫 도구로 끝날 수 있으니, 그런 요청이 잦으면 `off`로 둔다 |
| `vision` | `auto` | 이미지 이해. `auto`: 봇을 부를 때 함께 보낸 사진(답장한 메시지·전달한 메시지의 사진 포함, 한 번에 3장까지)만 읽음. 사진을 먼저 올리고 따로 부르면 2분 안의 바로 앞 사진을, 부른 뒤 45초 안에 사진만 따로 보내면 그 사진을 같은 요청으로 읽음. 답변 모델이 사진을 받으면 직접 보여 주고, 받지 않으면 다른 대화 모델이 2~4문장으로 설명해 메시지에 넣음. `off`: 읽지 않음. 그 밖의 방 사진은 보지 않고 사진은 저장하지 않음. 도구 화면에서도 바꿀 수 있음 |

## dm

```yaml
dm:
  allow: members
  per_user_per_day: 30
  per_day: 100
```

| 키 | 기본값 | 의미 |
|---|---|---|
| `allow` | `members` | DM 대화를 허용할 사람. `members`: 운영자 또는 봇이 현재 참여하고 서비스가 허용된 서버의 구성원. `operators`: 운영자만. `off`: DM 대화 끔. 전역 차단된 사용자는 응답하지 않음 |
| `per_user_per_day` | `30` | 사람별 하루 DM 대화 턴 한도. `0`: 기본값, `-1`: 제한 없음, 그 외 `1`–`10000` |
| `per_day` | `100` | 인스턴스 전체 하루 DM 대화 턴 한도. `0`: 기본값, `-1`: 제한 없음, 그 외 `1`–`100000` |

DM에서는 멘션 없이 대화할 수 있고 나눠 보낸 메시지는 한 턴으로 합칩니다. `!`·슬래시 명령어는 DM 대화를 꺼도 계속 동작하며, 답을 주지 못한 `!` 도구 명령은 DM 대화가 허용된 경우 대화로 이어집니다. DM 한도는 `tools.chat.respond` 한도·월 예산·동시 실행 한도와 함께 적용되고, 거절된 요청은 차감하지 않습니다. 카운터와 사람별 거절 알림(허용 정책 및 한도 종류마다 하루 한 번)은 재시작해도 유지되며 `i18n.timezone`의 자정에 초기화됩니다.

서버 멤버 여부는 Discord 상태와 REST 조회로 확인하며 별도 privileged intent는 추가하지 않습니다(REST 허용 캐시 10분, 거절 캐시 1분). DM은 인스턴스의 기본 페르소나와 미설정 방의 전역 도구 설정을 사용하고, 답 언어는 서버 방처럼 메시지의 언어를 따릅니다. 최근 대화는 DM별 단기 문맥으로만 보관하고 서버·방 기억 검색, 기억 블록 수집·색인, 방 말투 분석, 스레드 제안, 이모지 반응, 후속 발화 창, 먼저 끼어들기는 사용하지 않습니다. 보관 기간과 개인 기억 삭제·동의 철회는 DM 문맥에도 적용됩니다.

## guilds

서버 ID → 서버 설정, 채널 ID → 채널 정책.

```yaml
guilds:
  "123456789012345678":
    locale: ko
    channels:
      "234567890123456789":
        respond: mention          # always | mention | command | off
        persona_ref: friendly_ko
        rules: "근거 언급하지 마"
        capture: true
        memory_use: "on"
        memory_view:
          blocks: [kakao:friends]
        tools: {search.web: false}
```

### 채널 대화 설정

채널마다 `channels.<id>`에 봇과의 대화가 어떻게 흘러갈지도 둡니다(채널 화면 **동작 → 대화**). 비워 둔 키는 표의 첫 값을 씁니다. 스레드는 따로 설정하지 않으면 부모 채널의 설정·기억 범위·일시정지·저장을 그대로 따르고, 비공개 스레드는 따로 떨어진 채널로 봅니다.

| 키 | 값 | 설명 |
|---|---|---|
| `name_call` | `addressed` · `always` · `off` | 멘션이나 답장 없이 봇 이름만 들어간 메시지. `addressed`: 작은 분류기가 "봇에게 한 말"과 "봇에 대한 말"을 가려 앞의 경우만 답함(애매하면 답하지 않음). `always`: 이름이 들어가면 모두 호출. `off`: 이름만으로는 부르지 않음 |
| `attribution` | `on` · `structural` · `off` | 답할 때 볼 최근 줄. `on`: 부른 사람의 대화와, 분류기가 가리킨다고 본 줄. `structural`: 부른 사람의 대화만. `off`: 최근 줄 전부 |
| `conversation.follow` | `off` · `reply_only` · `window` | **실험 기능.** 태그 없이 이어 말하기. `reply_only`: 봇 메시지에 답장한 경우. `window`: 답한 뒤 점수로 판단하는 창. `off`여도 판단은 기록 |
| `conversation.follow_window_sec` | `0` (= 90, 최대 600) | 창이 열려 있는 시간. 봇이 질문했으면 60초 더 |
| `conversation.follow_max_untagged` | `0` (= 12) | 태그 없이 연달아 답하는 횟수 상한. 넘으면 다시 태그가 필요 |
| `conversation.thread` | `offer` · `auto_task` · `off` | 길어진 1:1 대화에 답 아래 버튼으로 스레드를 제안. 버튼은 채널의 누구나 누를 수 있고, 누른 사람도 스레드 대화 상대가 됨(**여기서 계속**은 질문한 사람만). `auto_task`(실험)는 도구를 3개 이상 쓴 작업이면 스스로 엶. `off`는 이 방에서 스레드 이어가기를 끔: 새 제안과 자동 열기가 멈추고, 끄기 전에 나온 버튼을 눌러도 스레드가 열리지 않으며(누른 사람에게만 알림), 이미 열린 봇 스레드에서도 태그 없이 답하지 않고 방의 일반 응답 규칙을 따름. 사람이 직접 만든 스레드에는 영향 없음. 서버 단위 기본값은 없어 방마다 정함. 제안이 계속 아무에게도 받아들여지지 않으면 그 방은 쉼: 열린 스레드 없이 무시·거절된 제안이 두 번 이어진 뒤 6시간, 이후 한 번 더 무시될 때마다 두 배(12시간, 24시간 …)로 쉬고 최대 7일이며, 스레드가 하나 열리면 처음부터 다시 셈. 쉬는 기간은 대화 기록(`conversation_log`)에서 읽으므로 재시작해도 유지되고, 콘솔 방의 활동 기록에는 "제안이 계속 무시돼 쉬는 중"(`skip_backoff`)이 대화당 한 번 남음 |
| `conversation.thread_follow` | `participants` · `all` | 봇이 연 스레드에서 태그 없이 답할 사람: 질문한 사람·스레드 버튼을 누른 사람·스레드에서 봇을 부른 사람, 또는 `all`이면 모두(다른 사람에게 한 말은 두고 봄) |
| `conversation.thread_idle_close_min` | `0` (= 30) | 조용한 시간이 이만큼 지나면 봇이 스레드에서 물러남(분) |
| `conversation.thread_recap` | `plan` · `always` · `off` | 스레드가 끝날 때 부모 채널에 짧은 정리: 계획·결정이 나왔을 때만, 항상, 안 함 |
| `conversation.reply_shape` | `bubbles` · `trim` · `plain` | `bubbles`: 짧은 문단 두세 개를 잠시 간격을 두고 나눠 보내고, 아주 긴 답은 앞부분과 "더 보기" 버튼. `trim`: "더 보기" 버튼만. `plain`: 쓴 그대로 |
| `conversation.banter` | `off` · `shadow` · `on` | **실험 기능.** 누군가 봇을 두고 장난스럽게 말하면 한 줄이나 이모지로 받아침. 진짜 불만에는 안 함, 시간당 한 줄 2번·이모지 4번까지, 👎를 받으면 2시간 동안 한 줄은 쉼. `shadow`는 했을 상황만 기록 |
| `logging.level` | `ops` · `errors` · `off` | 콘솔이 대화를 얼마나 남길지. `ops` 전부, `errors` 실패한 대화의 글만, `off` 글은 남기지 않음(ID·시간·도구·비용은 남음). 봇에 대한 말일 뿐인 메시지도 같은 기준을 따르고, 이름 호출 판단(`about_bot`, `unsure` 등)을 함께 남김 |

이 기능들의 판단(이름 부름, 이어 말하기, 스레드 제안, 받아치기)은 본문 없는 기록(`conversation_log`, `retention.turn_days` 동안 보관)에 남고, 대화 카드가 요약해 보여 줍니다. 실제 운영 데이터로 기본값을 맞추는 데 씁니다.

## tools

도구별 설정. 자세한 내용은 [도구와 한도](https://github.com/kim0040/masamong2/wiki/도구와-한도).

```yaml
tools:
  chat.respond:
    limits: {per_user_per_day: 200, cooldown_sec: 3}
  weather.query:
    defaults: {region: 부산}
    aliases: [날씨, w]
  search.web:
    enabled: false
```

## features

기능 묶음 스위치: `weather`, `disasters`, `finance`, `search`, `polls`, `images`, `fortune`, `notices`, `summaries`. `false`면 그 기능의 도구가 모두 꺼집니다.

`disasters`(기상청)와 `notices`(한국 대학)는 한국만 다룹니다. 설정 마법사의 언어가 한국어가 아니고 브라우저 시간대도 `Asia/Seoul`이 아닌 새 인스턴스는 둘 다 `false`로 시작하고, 브라우저가 시간대를 보내지 않았으면 `UTC`를 씁니다. 이미 쓰던 인스턴스의 설정은 그대로입니다.

## disaster_alerts

지진·특보를 묻지 않아도 채널에 알리는 기능. 기상청 키와 Discord 연결이 필요합니다.

```yaml
disaster_alerts:
  enabled: true                 # 전체 스위치 (기본 켜짐)
  earthquake_min_domestic: 4.0  # 국내 지진 규모 기준 (0–10)
  earthquake_min_overseas: 7.0  # 해외 지진 규모 기준
  warnings: true                # 기상특보 (경보는 육상 전국)
  warning_regions: [부산, 서울] # 주의보는 이 지역 이름이 든 것만

guilds:
  "<서버 ID>":
    channels:
      "<채널 ID>":
        disaster_alerts: "off"  # 이 채널만 끄기 (비우면 켜짐)
```

## personas

사용자 정의 말투. 내장 말투(`friendly_ko`, `friendly_en`, `warm_ko`, `warm_ja` 등)에 더해 추가할 수 있습니다. 말투를 고르지 않은 방은 그 방 언어(서버 `guilds.<id>.locale` → `i18n.default_locale`)의 기본 말투를 씁니다. `i18n.polite_default`가 켜져 있으면 한국어는 `warm_ko`, 일본어는 `warm_ja`, 아니면 `friendly_<tag>`입니다. `warm_ko`·`warm_ja`는 존댓말(해요체, です・ます)이고 `friendly_ko`·`friendly_ja`는 반말 프리셋으로 그대로 고를 수 있습니다. 내장 말투는 삭제 대신 숨길 수 있습니다(항목을 지우면 다시 나타남). 한국어 방을 반말 기본으로 두려면 `warm_ko`를 숨기면 됩니다.

```yaml
personas:
  calm_ko:
    locale: ko
    label: 차분한 말투
    style: "짧고 차분하게, 반말로 답한다."
  friendly_en:
    hidden: true   # 내장 말투 숨기기 (항목을 지우면 복원)
```

## retention

오래 운영하면 대화마다 쌓이는 운영 기록(대화 기록 상세, 진단 기록, 사용량 카운터, 질문 임베딩 캐시)이 DB를 계속 키웁니다. 매일 한 번 **오래된 사용량 기록 정리(`usage_gc`)** 예약 작업이 아래 기간이 지난 기록을 조금씩 나눠 지웁니다. 단위는 일, `0`은 기본값, `-1`은 영구 보관입니다. **기억(수집한 메시지·조각·요약)은 기간으로 지우지 않습니다.**

| 키 | 기본값 | 대상 |
|---|---|---|
| `turn_days` | `400` | 대화 기록 행 (통계·보고서용 요약) |
| `turn_detail_days` | `30` | 대화 기록의 상세(메시지·답변·근거). 지나면 요약 행만 남음. 채널별 대화 문맥(봇이 이어서 말할 때 보는 최근 대화)도 이 기간이 지나면 지움 |
| `trace_days` | `30` | 진단 trace |
| `audit_days` | `400` | 변경 기록, 채널 설정 기록 |
| `usage_days` | `14` | 사용자·채널별 도구 사용량 카운터 (한도 계산에는 오늘 것만 필요). 도구별 일일 합계는 `turn_days` 동안 보관 |
| `image_days` | `14` | 이미지 생성 도구가 만든 파일 (`<data-root>/images/`) |
| `query_cache_days` | `7` | 질문 임베딩 캐시 (설정한 차원으로 저장: 4096차원에서 질문 1개당 약 8 KB, 1024차원에서 2 KB. 같은 질문이 다시 오는 일이 드묾). 모델을 바꿀 때 남겨 둔 조각·요약 벡터는 되돌릴 때 비용을 아끼므로 지우지 않음 |

```yaml
retention:
  turn_detail_days: 14
  trace_days: 7
```

콘솔 **작업 → 예약 작업**에서 마지막 실행 결과와 지운 행 수를 보고 바로 실행할 수 있습니다(`masamong schedules run --id usage_gc`). 데몬이 시작된 뒤 5분 후 첫 실행, 이후 24시간마다 실행합니다.

## participation

먼저 말 걸기 전체 스위치와 한도입니다. 채널은 `guilds.<g>.channels.<c>.participation`(`off`·`collect`·`shadow`·`conservative`. `collect`는 모델을 부르지 않고 끼어들 만했던 순간과 그 뒤 일을 본문 없이 기록)으로 따로 켜며, 둘 중 엄격한 쪽을 따릅니다. 숫자는 shadow 기록을 보고 조정할 가설값입니다.

| 키 | 기본값 | 설명 |
|---|---|---|
| `enabled` | `false` | 전체 스위치 |
| `mode` | `off` | 채널이 쓸 수 있는 최대 방식 |
| `wait_sec` | `0` (= 45) | 질문이 답 없이 이만큼 지나야 판단 |
| `cooldown_sec` | `0` (= 180, 최소 120) | 한 채널에서 다시 말하기까지 |
| `per_hour` · `per_day` | `0` (= 3 · 10) | 채널당 말하는 횟수 |
| `judge_per_hour` | `0` (= 12) | 채널당 판단(모델 호출) 횟수 |
| `quiet_start` · `quiet_end` | 없음 | 끼어들지 않는 시간 (`i18n.timezone`) |
| `min_score` | `0` (= 0.7) | 판단 점수 기준 (확률이 아닌 순위 점수) |
| `shadow_drafts` | 켬 | shadow에서도 할 말을 써서 기록 (판단마다 모델 호출 한 번 더) |

## access

Discord 관리 명령(`/admin`, `!관리`), 무시할 사람, 봇이 동작할 서버. 콘솔 **사람·권한**과 **서버·방 → 서버 승인**에서도 바꿉니다.

| 키 | 기본값 | 설명 |
|---|---|---|
| `operators` | `[]` | 어느 서버에서든 관리 명령을 쓸 수 있는 Discord 사용자 ID. 승인 대기 서버에서도 명령을 쓸 수 있음 |
| `guild_admins` | `true` | 서버 소유자와 서버 관리 권한이 있는 사람이 자기 서버에서 관리 명령을 쓸 수 있는지 |
| `blocked_users` | `[]` | 모든 서버에서 봇이 메시지·명령·버튼에 반응하지 않는 사용자 ID. 대화 맥락으로 저장은 계속됨(멈추려면 본인이 기억 동의 철회) |
| `server_approval` | `true` | 켜면 승인한 서버(`servers`)와 방을 설정한 서버에서만 동작. 새로 초대된 서버는 승인 전까지 저장·답변 없음 |
| `servers` | `[]` | 운영자가 승인한 Discord 서버 ID. 이 기능 이전부터 봇이 있던 서버는 첫 연결 때 한 번 자동으로 추가됨 |

서버별 차단은 `guilds.<서버 ID>.blocked_users`에 저장됩니다. 그 서버의 관리자가 `!관리 차단 @이름`으로 추가하고, 콘솔 **서버·방**에서 해제할 수 있습니다.

**서버별 엄격한 기억 옵션**(`guilds.<서버 ID>.privacy`, 모두 기본 `false`. 친구 서버용 봇이라 기본은 자유롭게 기억):

| 키 | 기본값 | 하는 일 |
|---|---|---|
| `own_card_only` | `false` | 답에 부른 사람의 사람 카드만 쓰고, 같은 대화의 다른 사람 카드는 쓰지 않음 |
| `no_hearsay` | `false` | 다른 사람이 그 사람에 대해 한 말은 답이 보는 방 기억에서 뺌(사건 항목, 그런 사람을 가리키는 사건 제목, 방 상태 화제 포함) |
| `no_sensitive` | `false` | 사실이 카드 항목이 되기 전에 분류기가 확인하고, "기억해"도 민감한 내용(건강·연애·돈·종교·정치·가족·법 문제)은 거절. 확인 비용은 `memory.derived_budget_usd`에서 쓰고 사실마다 결과를 저장. 방 사건과 방 상태는 분류하지 않음 |
| `card_channel_only` | `false` | 카드 항목은 근거가 모두 나온 채널(과 그 스레드)에서만 씀 |

이 옵션과 상관없이 서버가 다르면 다른 사람이고, 원문 삭제나 동의 철회는 파생 기억까지 지우며, 로그에는 본문·ID를 남기지 않습니다. 누구나 **나에 대한 정리**(`!개인정보 철회 나분석`)를 철회할 수 있습니다. 그러면 내 카드가 지워지고 다시 만들지 않으며, 내 말을 인용한 방 말투 메모는 쓰지 않게 되고, 방 말투 분석에서도 내 말이 빠집니다. "기억해"로 남긴 내 사실은 대화 기억이라 남습니다.

**서버 로그**(`guilds.<서버 ID>.log`): 서버에서 생긴 일을 그 서버의 로그 채널에 올립니다. 이전 마사몽이 `logs` 채널에 올리던 기능입니다. 콘솔 **서버·방 → 서버 로그**에서 정하고, **시험 글 보내기**로 도착하는지 확인합니다(CLI `serverlog test --guild_id G`).

| 키 | 기본값 | 하는 일 |
|---|---|---|
| `channel` | 미설정(꺼짐) | 로그 채널 ID, 또는 `auto`(서버에 이름이 `logs`인 텍스트 채널이 있으면 그 채널). 미설정이나 `off`면 끔: 서버에 원래 있던 `#logs` 채널에 묻지 않고 글이 올라가지 않도록 직접 켜야 합니다 |
| `deletes` | `true` | 메시지 삭제: 누가, 어느 채널에, 언제 쓴 메시지인지 올림. 봇 메시지와 로그 채널 자체의 삭제는 빼고, 한꺼번에 여러 개 지우면 한 건으로 묶음. 작성자는 게이트웨이가 기억하는 최근 메시지(채널당 100개)나 저장된 메시지에서 찾고, 없으면 알 수 없음으로 표시 |
| `deleted_text` | `true` | 지워진 메시지의 내용과 첨부 파일 이름도 올림(마사몽이 최근에 봤거나 저장한 메시지만). 마사몽 기억에서는 그대로 지워지고, 내용은 로그 채널의 글로만 남음. `false`면 누가·어디에·언제만 올림 |
| `problems` | `true` | 답을 못 한 경우, 서비스 문제로 검색 같은 도구가 실패한 채 답한 경우(일부 오류), 예약 알림·예약 작업·재난 알림을 못 올린 경우, 봇이 글을 올릴 권한이 없는 채널. 같은 채널의 같은 문제는 15분에 한 번만 올림 |

한 서버에는 10분에 최대 20건까지 올리고, 넘친 건수는 다음 기록에 적습니다. 모든 답변이 일시정지됐거나 승인을 기다리는 서버에는 올리지 않습니다. Discord가 로그 채널을 거절하면 그 서버의 로그는 30분 쉽니다.

## alerts

문제가 생기면 운영자(`access.operators`)에게 Discord DM을 보냅니다. 콘솔 **유지보수 → 운영자 알림**에서 켜고 끄고 테스트합니다.

| 키 | 기본값 | 설명 |
|---|---|---|
| `discord` | `true` | 운영자 DM으로 알림. 운영자가 없으면 아무것도 보내지 않음 |
| `min_severity` | `warn` | 보낼 문제의 심각도. `warn`(주의 이상) 또는 `danger`(심각한 문제만) |

- 보내는 것: 콘솔 알림 목록(홈·알림 메뉴)에 **새로** 생긴 항목. 예: 예약 백업 실패, 키 거절, 예산 80%·소진, 실패한 작업, 봇 권한 회수, 승인 대기 서버, 비정상 종료 뒤 자동 재시작
- 보내지 않는 것: 운영자가 직접 한 일(전체 일시 정지, 재시작 대기), Discord 연결 끊김(그 사이엔 DM도 갈 수 없음), 정보 수준 항목
- 5분마다 확인하고, 새 항목만 한 메시지로 묶어 보냅니다. 같은 문제는 다시 보내지 않습니다. 1시간 안에 사라졌다 다시 생긴 문제도 다시 보내지 않고, 심각한 문제가 하루 넘게 이어지면 한 번 더 보냅니다.
- 메시지에는 문제 설명과 인스턴스 이름만 들어갑니다. 대화 본문은 넣지 않습니다.
- 운영자가 서버 멤버의 DM을 막아 두었으면 전달되지 않습니다. 콘솔에 이유가 표시됩니다.
