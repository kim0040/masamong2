# Discord 연결 가이드

**한국어** | [English](https://github.com/kim0040/masamong2/wiki/Connecting-Discord)

## 1. Discord 봇 애플리케이션 생성

1. [Discord Developer Portal](https://discord.com/developers/applications)에 접속하여 **New Application**을 클릭하고 새 애플리케이션을 생성합니다.
2. 좌측 메뉴의 **Bot** 탭으로 이동한 뒤 **Reset Token**을 클릭하여 봇 토큰(Bot Token)을 발급받습니다. (토큰은 발급 시 단 한 번만 조회 가능하므로 즉시 복사해 둡니다.)
3. 동일한 **Bot** 탭 화면 하단의 **Privileged Gateway Intents** 섹션에서 **Message Content Intent** 토글을 켭니다. (봇이 멘션 감지, 접두사 명령어(`!`), 실시간 대화 기억 수집을 위해 메시지 본문을 읽으려면 반드시 필요합니다.)
## 2. 관리 콘솔에 봇 자격증명 등록

관리 콘솔의 **연결 → Discord** 메뉴(또는 첫 설정의 Discord 단계)에서 복사한 봇 토큰을 넣고 Discord 활성화 스위치를 켭니다. 애플리케이션 ID는 복사하지 않아도 됩니다: 토큰을 저장하면 콘솔이 Discord에 저장된 토큰으로 직접 물어서(`GET /applications/@me`, `masamong discord check`) 봇 이름과 ID를 채우고(`instance.expected_bot_id`), 개발자 포털에서 **Message Content Intent**가 켜져 있는지도 보여 줍니다. 설정은 메시지 읽기를 쓰는데 포털에서 꺼져 있으면 Discord가 연결을 거부하므로(종료 코드 4014) 빨간 안내와 포털 링크가 나옵니다. 토큰이 거절되면 포털에서 **Reset Token**으로 새로 받으라고 안내합니다. 설정을 저장한 뒤 서비스 데몬을 재시작하면 Discord Gateway에 자동으로 연결됩니다. 등록된 봇 토큰은 macOS에서는 Keychain에, Windows에서는 자격 증명 관리자에, Linux·FreeBSD에서는 데이터 폴더의 소유자 전용 키 파일에 보관됩니다(파일은 권한으로 보호할 뿐 암호화하지 않습니다). 설정 파일에는 `keychain:`, `file:`, `env:` 형태의 참조 식별자만 남습니다([보안과 개인정보](https://github.com/kim0040/masamong2/wiki/보안과-개인정보)).

**첫 연결이 실패하면**: 게이트웨이 시작 중 READY나 RESUMED 전까지 `masamong doctor`는 `discord: pending`(`gateway_connecting`)을 보여 줍니다. Discord나 네트워크에 닿지 못하면(불안정한 네트워크, Discord 장애) 서비스가 처음에는 1초 간격으로, 최대 30초 간격까지 늘려 가며 연결될 때까지 스스로 계속 시도합니다. 재시작할 필요가 없습니다. `doctor`는 `gateway_retrying`과 함께 시도 횟수, 마지막 오류, 다음 시도 시각을 보여 줍니다. 토큰 거절이나 Message Content Intent 누락(종료 코드 4014)은 다릅니다. Discord의 답이 바뀌지 않으므로 재시도하지 않고 `doctor`에 `discord: error`(`gateway_start_failed`)를 표시합니다. **연결**에서 토큰을 고치고 Developer Portal에서 Intent를 켠 뒤 재시작하세요. 나중에 끊긴 연결은 스스로 이어 붙고, 알림·운세·공지·운영자 알림도 재시작 없이 계속됩니다.

`config.yaml` 설정 파일에서 직접 환경 변수로 주입하려면 다음과 같이 작성합니다:

```yaml
discord:
  enabled: true
  token_ref: env:MASAMONG_DISCORD_TOKEN   # 환경 변수 또는 콘솔이 생성한 keychain:/file: 참조
  command_prefix: "!"
  register_commands: true                 # 시작 시 슬래시 명령어 자동 등록
  message_content: true                   # Discord Developer Portal의 Message Content Intent 활성화 필수
  guild_ids: []                           # 비워둘 경우 전역(Global) 등록, 서버 ID 지정 시 해당 길드에 즉시 등록
instance:
  expected_bot_id: ""                     # 지정 시 다른 봇 토큰과의 불일치 발생 시 명령어 등록을 안전하게 거부
```

## 3. Discord 서버에 봇 초대

관리 콘솔의 **초대 링크**(연결, 서버·방 → 방 → 권한·초대, 첫 설정의 Discord 단계)로 봇을 서버에 추가합니다. 링크는 봇이 실제로 쓰는 권한만 요청하고 관리자(Administrator) 권한은 요청하지 않습니다. 방 화면에서 만든 링크는 그 서버가 미리 선택되어 권한을 다시 줄 때 편합니다.

| 권한 | 구분 | 필요한 이유 |
|---|---|---|
| View Channel (채널 보기) | 필수 | 채널을 보고 메시지를 받음 |
| Send Messages (메시지 보내기) | 필수 | 답변과 알림 발송 |
| Embed Links (링크 첨부) | 필수 | 도구 결과 카드 |
| Read Message History (메시지 기록 보기) | 필수 | 답장과 앞뒤 문맥 |
| Attach Files (파일 첨부) | 권장 | 이미지 생성 결과 올리기 |
| Create Polls (투표 만들기) | 권장 | `/투표` |
| Send Messages in Threads (스레드에서 보내기) | 권장 | 스레드 안에서 답하기 |

필수 권한이 없으면 그 방에서 답하지 못하고, 권장 권한이 없으면 해당 기능만 동작하지 않습니다. 역할이나 채널 설정이 바뀌어 봇이 필수 권한을 잃으면 홈에 경고가 뜨고, **서버·방 → 방 → 권한·초대** 탭에서 부족한 권한을 볼 수 있습니다(`masamong channels permissions --guild_id <서버ID> --channel_id <채널ID>`).

### 서버 승인

누군가 초대 링크로 봇을 모르는 서버에 넣어도 운영자 모르게 동작하지 않도록, 새로 초대된 서버는 **승인 대기** 상태가 됩니다(`access.server_approval`, 기본 켜짐).

- 승인 대기 서버에서는 메시지를 저장하지도, 관찰하지도, 답하지도 않습니다. 슬래시 명령에는 "승인을 기다리는 중" 안내만 보내고 `!` 명령은 조용히 무시합니다. 개인정보 동의 철회와 봇 운영자(`access.operators`)의 명령은 예외입니다.
- 콘솔 **서버·방**의 "서버 승인" 카드와 홈 경고에서 **승인**하거나 **거절하고 나가기**(봇이 서버를 떠남, 설정과 기억은 유지)를 고릅니다. 승인한 서버는 **승인 취소**로 다시 대기 상태로 돌릴 수 있습니다.
- 방을 설정해 둔 서버는 자동으로 승인된 것으로 봅니다. 이 기능이 생기기 전부터 봇이 있던 서버는 처음 연결될 때 한 번 자동 승인되고, 변경 기록에 경로 "자동"으로 남습니다.
- 스위치를 끄면 초대된 모든 서버에서 동작합니다.

## 4. 채널별 응답 및 기억 정책 설정

관리 콘솔의 **서버·방** 메뉴(또는 CLI의 `masamong channels configure`)에서 채널별로 세부 정책을 설정합니다:

| 설정 항목 | 설정값 옵션 | 동작 설명 |
|---|---|---|
| 응답 정책 `respond` | `mention` · `always` · `command` · `off` | 봇이 어떤 조건에서 대화에 응답할지 결정 |
| 대화 수집 `capture` | 활성화 / 비활성화 | 채널의 대화를 기억 데이터베이스에 실시간 수집할지 여부 (전역 `memory.capture` 활성화 필요) |
| 기억 검색 `memory_use` | `on` · `off` | 대화 답변 생성 시 과거 기억 블록을 검색하여 반영할지 여부 |
| 페르소나 `persona_ref` | `warm_ko`, `friendly_ko`, `friendly_en` 등 | 채널별 맞춤 말투 및 **기본 답변 언어** 지정. 비워 두면 그 언어의 기본값을 씁니다(`warm_ko`·`warm_ja`는 존댓말. [언어 설정](https://github.com/kim0040/masamong2/wiki/언어-설정) 참고) |
| 추가 규칙 `rules` | 텍스트 지시문 | 해당 채널에만 특화된 추가 시스템 프롬프트 지시문 |
| 기억 블록 `memory_view.blocks` | 블록 ID 목록 | 해당 채널에서 함께 조회할 과거 대화 기억 블록 매핑 |
| 도구 설정 `tools` | 도구별 활성/비활성 | 특정 도구의 채널별 활성화 오버라이드 |

```bash
# 채널 설정 CLI 예시
masamong channels configure --guild_id 123456789 --id 987654321 --respond mention --capture true --persona_ref friendly_ko
```

> [!IMPORTANT]
> **채널 격리 원칙:** 각 채널은 해당 채널 자체의 실시간 대화와 명시적으로 매핑된 기억 블록만 조회할 수 있습니다. 타 채널, 타 서버, 또는 개인 DM의 대화 기록이 자동으로 섞여 노출되는 일은 절대 발생하지 않습니다.

## 5. 지원 명령어 목록

### 슬래시 명령어 (Slash Commands)

| 슬래시 명령어 | 기능 설명 |
|---|---|
| `/weather` | 현재 날씨 및 예보 조회 (국내는 기상청, 해외는 Open-Meteo 연동) |
| `/alerts` | 기상특보 및 지진 재난 문자 정보 조회 (자동 공지는 콘솔에서 켜고 끔) |
| `/places` | 맛집·카페·가게 찾기 (카카오맵, 카카오 REST 키 필요) |
| `/ranking` | 이 채널 수다왕: 오늘·이번 주·이번 달·전체 메시지 수 순위 |
| `/quote` | 국내/해외 주식 실시간 시세 조회 (Finnhub API 키 필요) |
| `/fx` | 주요 통화 환율 정보 조회 |
| `/search` | 인터넷 검색 (Tavily·Linkup·Exa·Serper·Brave·TinyFish·카카오 중 하나의 키 필요) |
| `/poll` | 해당 채널에 인터랙티브 Discord 투표 임베드 생성 |
| `/summary` | 채널의 최근 대화 내용 핵심 3줄 및 결정 사항 요약 (대화 수집 채널 전용) |
| `/image` | 자연어 프롬프트를 통한 고품질 이미지 생성 (`image` 모델 연동 필요) |
| `/fortune`, `/fortune-register`, `/zodiac` | 오늘의 사주 운세, 생년월일시 등록, 별자리 운세 (개인정보 동의 필수. 채널에는 3줄 요약만 출력, 상세 풀이는 본인 전용 DM/임시 메시지로 전송) |
| `/notices`, `/notices-register`, `/transfer` | 대학 공지사항 조회, 알림 등록, 최신 편입 공지 조회 (공지 구독 시 동의 필수) |
| `/remind`, `/reminders` | 자연어 일정 알림 예약 (버튼을 통한 본인 확인 후 등록), 예약된 알림 조회 및 취소 |
| `/privacy` | 기억 저장, 운세, 공지, 선제적 개입 기능에 대한 개인정보 동의 현황 확인, 동의 및 철회 관리 |
| `/mysettings` | 개인 맞춤 설정: 기본 날씨 지역, 시간대, 야간 방해 금지 시간, 선호 언어 설정 |
| `/admin` | 이 채널의 봇 운영: 일시 중지·재개, 응답 방식, 대화 저장 켜기·끄기, 먼저 말 걸기, 이 서버에서 사용자 차단·해제 (서버 관리 권한자에게만 보임) |
| `/status` | 봇 시스템 상태 점검 (요청자 본인에게만 표시되는 에페머럴 메시지) |
| `/help` | 지금 쓸 수 있는 명령어 안내. 등록되어 있고 도구가 준비된 슬래시 명령, Message Content Intent와 명령 접두사가 켜졌을 때만 내 언어의 `!` 명령, "답변 평가" 메뉴 항목을 보여 줍니다 |

도구를 비활성화하면 해당하는 슬래시 명령어가 Discord 클라이언트 메뉴에서 자동으로 제외되도록 즉시 재동기화됩니다.

### 접두사 명령어 (`!`) (Message Content Intent 필요)

`!날씨 서울`, `!특보`, `!시세 AAPL`, `!환율 USD`, `!검색 마사몽`, `!투표 점심 메뉴 투표 | 김밥, 라면`, `!요약`, `!알림 내일 오후 3시 회의`, `!알림목록`, `!운세`, `!운세등록 1995-05-15 14:30 남 서울`, `!이번달운세`, `!올해운세`, `!구독 08:00`, `!공지`, `!편입`, `!개인정보`, `!내설정`, `!관리`, `!도움말` 형태로 직관적인 명령 호출을 지원합니다. 명령어 트리거 키워드는 하드코딩되지 않고 `locales/` 다국어 리소스에서 관리되므로 언어별 확장이 유연합니다.

봇은 멘션·답글·이름으로 부른 사람에게만 거절 안내를 보냅니다. 안내 문구는 예산 같은 내부 사정을 드러내지 않는 중립적인 표현이며, 채널당 분당 최대 1회, 같은 사람에게는 채널마다 5분에 1회까지입니다. 접두사나 슬래시 명령이 시간 초과되어도 Discord 연결이 살아 있으면 마지막 현지화 오류 카드를 보냅니다.

### 자연스러운 일상 대화 호출

응답 모드가 `mention`인 채널에서 "마사몽, 내일 부산 날씨 어때?", "저번에 우리가 가기로 했던 카페 이름이 뭐였지?"처럼 자연스럽게 봇의 이름을 부르면, 플래너 LLM이 의도를 스스로 파악하여 최적의 도구와 기억을 연동한 뒤 친근한 친구 말투로 답변합니다. 인식되는 봇 호출 이름은 설정의 `instance.bot_names`에서 자유롭게 지정할 수 있습니다.

**끊어 보낸 메시지는 한 번에 답합니다.** "마사몽" / "내일 날씨 어때?"처럼 끊어 보내도 질문이 묻히지 않습니다.
- 이름이나 멘션만 있는 메시지("마사몽", "@마사몽", "야 마사몽~")를 받으면 바로 답하지 않고, 같은 사람이 같은 채널에 이어 보내는 메시지를 최대 10초 기다립니다. 이어 보낸 메시지에는 이름이 없어도 됩니다.
- 내용이 있는 메시지는 1.5초 동안 이어지는 조각을 모아 한 번에 답합니다. 모든 메시지에 답하는 방(`always`)도 같습니다.
- 다른 사람의 메시지는 섞지 않습니다. 한 질문을 20초보다 오래 붙잡지 않습니다.

### DM으로 대화하기

봇에게 DM을 보내면 멘션이나 이름 없이 바로 대화합니다. 날씨·검색·알림·운세 같은 도구도 서버에서처럼 씁니다. 끊어 보낸 메시지는 위와 같이 한 번에 답합니다.
- **누가 쓸 수 있나:** 기본값은 봇이 일하는 서버(승인된 서버)의 멤버와 운영자입니다. 관리 콘솔에서 "운영자만" 또는 "끄기"로 바꿀 수 있습니다. 대화가 열려 있지 않은 사람에게는 하루 한 번 짧은 안내만 보냅니다. `!`·슬래시 명령은 DM 대화를 꺼도 그대로 동작합니다.
- **한도:** 기본은 한 사람당 하루 30번, DM 전체 하루 100번입니다. 관리 콘솔에서 바꾸거나 제한 없음으로 둘 수 있습니다. 한도에 닿으면 종류별로 하루 한 번 안내하고, `i18n.timezone`의 자정에 초기화됩니다. 대화 답장 한도·월 예산도 함께 적용됩니다.
- **분리:** DM은 서버·채널 기억을 검색하지 않고, DM 내용도 서버 기억에 들어가지 않습니다. 최근 몇 번의 대화만 DM 안의 문맥으로 기억합니다.
- 스레드 제안, 이모지 반응, 먼저 말 걸기는 DM에서 쓰지 않습니다. 설정 키는 [설정 레퍼런스의 `dm`](https://github.com/kim0040/masamong2/wiki/설정-레퍼런스#dm)에 있습니다.

### 서버 관리자의 `!관리` 명령

서버 소유자와 "서버 관리" 권한이 있는 멤버(`access.guild_admins`, 기본 허용), 그리고 봇 운영자가 쓸 수 있습니다. 결과는 본인에게만 보이고, 모든 변경은 콘솔 변경 기록에 **누가·어느 서버에서·Discord로** 바꿨는지 남습니다.

| 명령 | 하는 일 |
|---|---|
| `!관리` | 이 채널의 상태(동작·응답 방식·기억·대화 저장·먼저 말 걸기·이 서버 차단 수) |
| `!관리 정지` / `!관리 재개` | 이 채널에서 봇 일시 중지·재개 |
| `!관리 응답 호출` | 응답 방식: 항상·호출·명령·끄기 |
| `!관리 기억 끄기` | 이 채널의 대화 저장 켜기·끄기 |
| `!관리 먼저말걸기 기록만` | 먼저 말 걸기: 끄기·기록만·말하기(켜기). 인스턴스 설정보다 더 많이 허용할 수는 없음. `끼어들기`, `능동참여`, `참여`도 그대로 쓸 수 있음 |
| `!관리 차단 @이름` / `!관리 해제 @이름` | 이 서버에서만 그 사람의 메시지·명령·버튼을 무시. 봇, 본인, 봇 운영자는 차단할 수 없음 |

## 6. 실시간 인터랙티브 투표

`/poll` 명령어나 자연어 대화("다들 점심 뭐 먹을지 투표 만들어줘")를 통해 생성된 투표는 Discord 네이티브 컴포넌트로 렌더링됩니다. 여러 사용자가 **동시에 투표 버튼을 클릭하더라도 단일 트랜잭션 락을 통해 모든 표가 누락 없이 안전하게 합산**됩니다.

## 7. 응답 품질 및 처리 원칙

- 답변을 생성하는 동안 사용자 경험을 위해 Discord "입력 중(Typing)..." 상태를 자연스럽게 유지하며, Discord 단일 메시지 한도(2,000자)를 초과하는 긴 답변은 문맥 단락을 고려하여 깔끔하게 분할 전송합니다.
- 불필요한 알림 피로도를 방지하기 위해 봇은 사용자 멘션이나 `@everyone`, `@here` 호출을 전송하지 않습니다.
- 한도·예산·일시 정지·처리 지연으로 대화를 거절할 때는 **봇을 부른 사람에게만** 그 사람의 언어로 중립적인 안내 한 줄을 보냅니다. 예산이나 한도를 안내 문구로 공개하지 않습니다. 안내는 채널당 1분에 한 번, 같은 채널의 사람당 5분에 한 번으로 제한합니다. 답변을 꺼 둔 방과 차단된 사람에게는 아무것도 보내지 않습니다. 상세한 사유는 관리 콘솔의 **대화 기록** 화면에서 확인할 수 있습니다.
- 멤버가 쓴 명령의 입력이 잘못되면(잘못된 날짜, 빠진 항목 등) 카드가 그 사람의 언어로 평범한 문장으로 알려 줍니다. 명령 시간이 초과되어도 Discord에 연결할 수 있으면 현지화한 오류 카드를 보냅니다. 허용된 운영자와 서버 관리자는 오류 코드도 카드에서 볼 수 있습니다. 원래 기술 오류와 경로는 로그에 남습니다.
- 서비스에 멈추라는 지시가 내려지면 답변과 카드 전송도 바로 멈추므로, 긴 답변이 멈춘 뒤에 반쯤만 올라가는 일이 없습니다.
- 결과 카드는 Discord 임베드 명세(제목 256자, 본문 4,096자, 필드 25개, 전체 6,000자)에 맞춰 안전하게 자르고 포맷팅합니다.
- **답변 피드백은 채팅창을 어지럽히지 않습니다.** 봇은 자기 답변에 이모지를 달지 않습니다.
  - 사람들이 **스스로** 봇 답변에 단 반응만 조용히 셉니다. 👍 ❤️ 😂 🔥 등은 좋음, 👎 ❌ 😕 등은 별로로 보고, 그 밖의 반응은 무시합니다.
  - 봇 답변을 길게 누르거나 우클릭하면 나오는 **앱 → 답변 평가**로 좋음/별로를 남길 수 있습니다. 별로를 고르면 이유도 고를 수 있습니다(선택). 이 창은 누른 사람에게만 보입니다.
  - 결과는 콘솔 **대화 기록**의 해당 대화에 👍/👎로 표시됩니다. 반응을 읽는 권한(Guild Message Reactions)은 특별 권한이 아니라 개발자 포털에서 따로 켤 것이 없습니다.
- 개인 신상과 관련된 운세 및 공지 브리핑은 사생활 보호를 위해 DM 또는 본인 전용 임시 메시지로만 전송되며, 사용자가 DM 수신을 거부한 경우 무리하게 채널에 공개하지 않고 발송 실패 로그만 안전하게 기록합니다.

## 8. 먼저 말 걸기 (선제적 개입)

채널 참가자들의 대화 맥락을 파악하여 봇이 먼저 유용한 도움을 주는 기능으로, 기본값은 비활성화되어 있습니다. 전역 스위치(`participation`)와 채널별 설정의 **먼저 말 걸기** 옵션을 모두 켜야 활성화됩니다.

- **기록 전용 모드 (Shadow)**: 봇이 개입할 가치가 있는지 내부적으로만 평가하고 개입할 문장을 시스템 로그에만 기록합니다. 채널에는 메시지를 보내지 않으므로, 관리 콘솔에서 개입 품질을 먼저 모니터링할 때 유용합니다.
- **능동 개입 모드 (Conservative)**: 엄격한 판단 기준을 통과했을 때만 1~2문장의 짧고 정중한 답변으로 자연스럽게 개입합니다.
- **주요 개입 감지 대상**: 일정 시간(기본 45초) 동안 아무도 답변하지 않은 사실 질문, 일시가 명확히 지정된 약속 일정. 약속 감지 시 "일정 알림을 등록해 드릴까요?" 카드를 띄워 버튼을 누른 사용자에게만 개별 알림을 예약합니다.
- **안전한 사전 필터링**: 모델을 호출하기 전에 코드 레벨에서 봇을 직접 부른 메시지, 특정인 간의 사적인 대화, 차단된 사용자, 능동 개입 동의를 철회한 사용자(`/privacy`), 쿨다운 시간(기본 180초), 일일 빈도 제한(시간당 3회, 일일 10회)을 사전에 엄격히 걸러냅니다.
- 판단 대기 시간 도중 다른 참가자가 먼저 답변을 달거나 대화 흐름이 전환된 경우 봇은 끼어들지 않고 즉시 침묵합니다.

## 9. 메시지 수정·삭제 반영 및 부재 중 대화 동기화

- 사용자가 기존 메시지를 **수정하면** 기억 데이터베이스의 내용도 즉시 함께 갱신되며, 메시지를 **삭제하면** 기억 인덱스에서도 즉시 제거됩니다. 백그라운드 색인이 다시 돌기 전이라도 삭제된 메시지는 검색 결과에서 즉각 제외됩니다.
- 봇 서비스가 오프라인이었던 동안 채널에 발생한 대화는 재접속 시 **최대 최근 7일분까지** 자동으로 누락분을 동기화합니다(`memory.backfill_days`). (동기화된 과거 대화에 대해 뒤늦게 답변을 달지는 않습니다.)
- 기억 저장 동의를 철회한 사용자(`/privacy`)의 대화는 실시간 수집에서 제외되며, 기존에 수집된 데이터도 안전하게 파기됩니다. 차단된 사용자의 경우 응답만 거부하며 채널 문맥 보존을 위한 대화 수집은 유지됩니다.
