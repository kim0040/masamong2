마사몽 시스템 지도

마사몽은 Go 프로그램 두 개로 돕니다. 데몬 masamongd는 늘 켜져서 Discord 대화와 관리 화면을 맡고, masamong은 데몬을 켜고 끄거나 명령을 실행하는 손잡이입니다. 모든 데이터는 내 컴퓨터의 SQLite 파일 하나에 들어갑니다.

들어오는 길은 셋, 처리는 하나Discord, 관리 콘솔, CLI가 모두 같은 application Action을 부릅니다.
답 하나 = 모델 두 번플래너가 계획을 세우고, 도구와 기억을 거쳐 답변 모델이 말합니다.
기억은 방 단위로 잠김이 방과 연결한 기억 블록만 찾고, 답 직전에 범위를 한 번 더 확인합니다.

답 하나가 나오기까지

차례를 기다리고 한도를 확인한 다음, chat.Runtime.Answer가 모델을 두 번 부릅니다. 단계 순서는 코드의 실행 순서 그대로입니다.

들어오기application · Gateway
  1. 1
    방 차례 기다리기같은 방은 한 번에 하나씩, 도착 순서대로. 실행 1개와 대기 4개를 넘으면 건너뛰고, 말을 건 사람에게 "대화가 밀리고 있어요" 한 줄(사람·방마다 5분에 한 번)
  2. 2
    빈 자리 기다리기전체 동시 답변은 max_concurrent_turns(기본 8)까지
  3. 3
    한도 · 예산 확인차례가 온 뒤에 확인하므로 몰려와도 예산을 함께 넘지 못함. 한도·예산·일시 중지로 거절되면 그 사람의 언어로 짧은 안내 한 줄(5분에 한 번), 답을 꺼 둔 방은 조용함
생각하기chat.Runtime.Answer
  1. 4
    플래너 모델JSON 계획: 기억이 필요한지, 어떤 도구를, 언제·누구 이야기인지
  2. 5
    도구 실행실행 가능한 단계만. 값이 빠진 단계는 needs_input으로 남김
  3. 6
    기억 검색이 방과 연결된 블록만. 결과는 범위를 한 번 더 확인
  4. 7
    답변 모델페르소나 · 방 규칙 · 도구 결과 · 기억 근거로 친구처럼 답
내보내기Gateway
  1. 8
    보내고 기록먼저 답에 봇 내부 표식(구분자 · 플래너 머리글 · 시스템 프롬프트 제목)이 없는지 글자 그대로 확인하고, 있으면 일반 안내 문구로 바꿈. 그다음 Discord로 전송(요청 컨텍스트에 묶여 서비스가 멈추면 남은 조각을 보내지 않음), 턴 기록(단계별 이유 · 비용 · 시간) 저장
플래너가 실패하면기억 없이 답합니다. "전부 검색"으로 바뀌지 않습니다.
기억 검색이 실패하면기억 없이 답하고, 기억에 없는 일은 지어내지 않습니다.
도구가 답을 못 주면오류 카드 대신 대화로 이어 갑니다. Discord 답의 제한 시간은 180초입니다.
Discord에 닿지 못하면첫 연결은 1초에서 30초까지 간격을 늘려 가며 스스로 다시 시도합니다(토큰 거절은 한 번에 멈춤, doctor가 재시도 중인지 영구 실패인지 알려 줌). 끊겼다 이어진 세션(RESUMED)에서는 예약 전송 관문을 다시 엽니다.

아무도 말하지 않을 때

데몬이 혼자 하는 일

데몬은 시작할 때 RunScheduler와 RunMemoryWorker를 하나씩 띄웁니다. 실패한 회차는 로그에 남기고 다음 회차에 다시 돕니다. 서비스가 맡은 일(기억 워커 · 스케줄러 작업 · 먼저 말 걸기 후보 · 가격·공지 갱신 · 기억 블록 작업)은 모두 서비스 수명에 등록되어 있습니다. Discord의 READY·RESUMED 핸들러도 같은 작업 수용 잠금 아래 등록합니다. 종료하면 새 핸들러 수용을 닫고 이미 받은 이벤트와 답변·명령을 기다린 뒤 색인(은퇴 타이머 포함)과 DB 연결을 닫습니다. 열기에 실패했을 때도 같은 경로로 정리합니다.

복원 · 초기화 · 업데이트는 같은 저널 형식과 같은 복구 엔진을 씁니다. 단계마다 기록하므로 중간에 죽어도 다음 시작이 이어 가거나 되돌립니다. 지우기를 시작한 초기화만 되돌릴 수 없습니다. 감시 프로세스도 다음 자식을 띄우기 전에 프로그램 저널을 정리합니다.

저장소는 SQLite 하나뿐

TiDB 코드는 남아 있지만 internal/storage/settings.go의 TiDBEnabled = false가 막고 있습니다. 2026-09-28 결정입니다. 새로 만든 표도 SQLite DDL만 있습니다.

기능 하나 = Action 하나

  • 새 기능은 catalog에 Action을 등록하고 application에서 구현합니다.
  • 콘솔, CLI, Discord 명령은 그 Action을 부르기만 합니다.
  • 화면 코드에서 DB를 직접 열지 않습니다.

검색을 바꾸면 두 곳을 같이

  • Python 샌드박스에서 비교한 다음 Go memory/*에 옮깁니다.
  • parity_test.go로 두 쪽 결과가 같은지 확인합니다.
  • 콘솔 화면을 바꾸면 npm run build 결과인 ui/dist도 커밋합니다.
