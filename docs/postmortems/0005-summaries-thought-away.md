# 0005: 요약 모델이 생각하느라 출력 한도를 다 써서 요약 5만 개가 빈칸이 됨

상태: 해결 (2026-10-14). 운영 이전 직후 임베딩·요약 작업 비용이 예상의 3배를 넘어 조사하다 발견했습니다.

## 30초 요약

운영 이전에서 요약 모델을 `deepseek/deepseek-v4.1-flash`로 바꿨습니다. 요약 호출은 출력 한도 120토큰에 "생각은 조금만"(`reasoning.effort=low`)을 보냈는데, 이 모델은 `low`에서도 120토큰을 모두 생각에 써 버리고 본문 없이 `finish_reason=length`로 끝났습니다. 색인기는 빈 요약을 "조각 앞 180자"로 대신 채웠고, 이 대체문을 그 본문의 요약으로 캐시에 저장했습니다. 호출 기록에는 성공으로 남아 대시보드에서는 요약이 잘 쌓이는 것처럼 보였습니다. 약 $4.3을 쓰고 요약 50,989개가 대체문이 됐습니다. 교훈: **생각하는 모델에 짧은 출력 한도를 줄 때는 생각을 끄거나, "빈 본문 + 한도 도달"을 실패로 다뤄야 합니다. 대체값은 결과처럼 저장하지 않습니다.**

## 영향

- 운영 인스턴스의 닫힌 조각 기준 대체문 요약 50,989개, 실제 요약 437개(카카오 두 방과 디스코드 방 7개). 기억 검색은 조각 벡터로 계속 동작했지만 요약 줄기(summary stream)는 조각 첫머리를 다시 넣은 것과 같아 효과가 없었습니다.
- 비용: 2026-10-13 요약 호출 40,406건 약 $4.25. 호출당 완성 토큰이 정확히 120이었습니다(전부 생각).
- 같은 원인: 운세 생성(`max_tokens` 900)이 빈 답으로 실패했고, 방 상태 추출 9건이 빈 답, 방 기억 갱신이 `stopped_by=error`로 멈췄습니다.

## 경과

- 2026-10-13: 이전 운영 서버의 키와 모델로 운영 인스턴스를 세웠습니다. 요약 역할이 `deepseek-v4.1-flash`가 됐습니다.
- 2026-10-14 01:00 전후: OpenRouter 키 사용량이 봇 기록보다 많다는 의문이 생겼습니다. 기록을 다시 보니 일치했고, 대신 요약 비용이 추정(가격표 기준 $0.32)의 3배로 나갔습니다.
- 같은 요청을 직접 보내 보니 `effort=low`, `max_tokens=120`에서 `reasoning_tokens=120`, 본문 0자, `finish_reason=length`가 두 번 연속 나왔습니다. `effort=none`에서는 생각 0토큰, 본문 68자, 비용은 약 절반이었습니다.
- 진행 중이던 색인 작업 8개를 모두 취소하고, 운영 DB를 읽기 전용으로 세어 대체문 규모를 확인했습니다.

## 원인

- 요약 호출(`internal/memory/engine/indexing.go`)은 샌드박스 recipe를 옮기며 `Effort: "low"`, `MaxTokens: 120`을 썼습니다. 샌드박스의 요약 모델은 생각하지 않는 모델이라 `low`가 의미가 없었고, 이 조합이 안전한지는 모델에 따라 달랐습니다.
- `normalizeSummary`는 빈 본문을 조각 앞 180자로 바꿨고, 호출이 성공했으므로 `PutSummaryText`가 이 값을 `(모델, 본문)` 키로 캐시했습니다. 다음 패스는 캐시를 그대로 써서 다시 돌려도 고쳐지지 않았습니다.
- 호출 기록은 오류가 없으면 성공(`class=""`)으로 남겼습니다. 빈 답도 성공으로 보였습니다.

## 왜 놓쳤나

- 테스트의 가짜 공급자는 항상 본문을 돌려줬습니다. "본문 없이 한도 도달"이라는 응답 모양 자체가 테스트에 없었습니다.
- 모델을 바꿀 때 요약 결과를 한 건도 눈으로 확인하지 않았습니다. 진행률과 비용만 보였고 둘 다 정상처럼 움직였습니다.
- 비용 추정은 가장 싼 공급자 가격을 썼고, 실제 라우팅은 3~4배 비싼 공급자로 갔습니다. 추정과 실제의 차이가 "가격 차이"로 설명돼 버려 원인을 늦게 봤습니다.

## 추가한 안전장치

- 요약 호출은 생각을 끕니다(`Effort: "none"`). 샌드박스(`experimental/rag-leaf-parent/engine.py`)도 같이 바꿨습니다.
- 모든 채팅 호출: 생각을 요청했는데 본문·도구 호출 없이 `finish_reason=length`로 끝나면, 생각 없이 한 번 더 묻고 두 호출 비용을 합칩니다(`internal/providers/openai/openai.go`, `TestThinkingThatUsesTheWholeBudgetIsAskedAgainWithout`).
- 빈 답은 대체문으로 저장하지 않고 다음 패스에 다시 요약합니다. 호출 기록에는 `empty`로 남기고, 모든 답이 비면 패스가 `provider_error`로 멈춥니다(`TestEmptySummaryIsLeftForTheNextPass`). 캐시에 남은 대체문은 무시되고, 진짜 요약이 나오면 덮어씁니다.
- 한 번만 도는 마이그레이션이 대체문 요약과 그 캐시를 지워 다음 패스가 다시 요약하게 합니다(`migrateFallbackSummaries`, `TestFallbackSummariesAreClearedOnce`).

## 교훈

- 생각하는 모델의 `low`는 상한이 아닙니다. 짧은 출력이 필요한 호출은 생각을 끄거나 한도 도달을 실패로 다룹니다.
- 대체값은 그 자리를 메우는 데만 쓰고, 진짜 결과와 같은 저장소·캐시에 넣지 않습니다. 넣으면 다시 돌려도 고쳐지지 않습니다.
- 모델을 바꾸면 비용·진행률이 아니라 결과물 몇 건을 직접 봅니다.
