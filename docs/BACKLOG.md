# 추후 작업

기준일: 2026-10-13. 기준 코드: `main` `ae3b59a3`.

제품은 현재 기능을 갖춘 완성형으로 두고, 아래 결정·검증·개선은 후속 업데이트에서 처리합니다. 상태를 확인할 수 없는 항목은 `확인 필요`로 남깁니다. 코드로 확인한 문제는 [알려진 문제](KNOWN_ISSUES.md)에 적습니다.

기억·대화 흐름·도구 선택 개선은 [기억·대화·도구 개선 계획](plan-memory-conversation.md)에 있습니다. 2026-10-15 조사(예약 작업, 운세·공지 카드, 콘솔 페이지 전환, 기다리는 동안 안내·팁, 운영 데이터 점검, Hermes·OpenClaw 차용 2건)는 [Discord 사용 경험·운영 개선 계획](plan-discord-experience.md)에 있습니다. 검색 구조를 바꾸는 실험·결정은 [RAG 문서](rag/README.md)에서 시작합니다.

## 0. 남은 결정과 기술 한계

| ID | 항목 | 현재 상태와 근거 |
|---|---|---|
| ADR-18 | 유휴 방 메모리 내리기 | [ADR-18 초안](adr/ADR-18-idle-room-unloading.md). 0단계(계약·측정 진단·게이트 도구·실측 §13)를 마쳤고, C-5 게이트 보고에서 1단계 진행 결정을 기다립니다. 방마다 색인을 따로 두지 않고 전체 방에 색인 하나를 씁니다. 최근에 사용한 활성 방이 모두 메모리에 올라 있으면 절감량은 0입니다. 1단계 전에 할 일이 둘 있습니다. `EstimateRoomBytes` 계수를 보정하고, hot 재구축에서 다시 만드는 메시지 배열·leaf 메타를 줄일 후보(약 26MiB+40MiB/23만 메시지)를 검토합니다. |
| WIDTH | 임베딩 너비 전환의 한계 | raw `config.patch`로 너비를 올리면 재색인 전까지 검색 결과가 비어 있습니다. 리랭커가 없는 호스트로 공급자만 바꾸면 1024를 유지하고 안내만 표시합니다. 명시적 4096은 1024 기본값과 다른 설정으로 취급합니다. `gemini-embedding-2`는 MRL 목록에 없어 명시 폭이 없으면 전체 너비를 유지합니다. 비-MRL 모델에 명시 leaf 폭이 남으면 leaf 자체가 절단되는 기존 문제는 전체 leaf 재임베딩을 피하기 위해 이번에 고치지 않았으며, 메시지와 질문은 그 설치의 같은 leaf 폭을 사용합니다. 채널 분리 때 정책 ID마다 `dbBlocks`를 다시 조회하는 작은 중복도 있습니다. 설계 문서는 [RAG 문서](rag/README.md)에서 찾습니다. |
| MSG-512 | 메시지 벡터 512 검증 | 마쳤습니다. MRL 기본은 512이고, 비-MRL은 실제 저장된 leaf 폭을 씁니다. 활성 leaf 폭이 섞이면 메시지를 보류하고 폭이 다른 leaf만 다시 임베딩합니다. 공급자가 짧게 돌려주면 기다리고 진단에 표시합니다. 실데이터 parity(`fusion_diff 0`·`hits_diff 0`)와 새 기본 측정 1회를 확인했습니다([측정 기록](rag/embedding-width-2026-10.md) §7, ADR-18 §13). 남은 일은 비-MRL 공급자가 패스마다 폭을 바꾸는 드문 경우입니다. 이때 패스 예산 안에서 수리가 반복됩니다. |
| LOWSPEC | 저사양 확인 | 2026-10-12 측정은 x86에서 `GOMAXPROCS=1`로 했습니다. 실제 Raspberry Pi·SD 카드·512MB 장치 확인은 안 했습니다. 메시지 10만 건의 첫 로드는 1코어에서 약 7초이며 그동안 검색 색인이 없습니다. 방별 콘솔 블록 목록의 첫 호출은 대기 메시지 집계가 끝날 때까지 5–7초 걸립니다. 실기기·실제 모델 지연도 확인해야 합니다. |
| LOWSPEC-DECISIONS | 동작 결정이 필요한 저사양 잔여 | 동의를 철회하면 기존 스레드 참여자 기록은 메모리와 DB에서 지워집니다(`TestThreadParticipantWriteCannotFollowWithdrawal`). 다만 철회한 회원이 그 뒤 봇 스레드에서 다시 말하면 저장되지 않는 메모리 전용 참여자로 다시 들어갑니다(`TestThreadParticipantAfterWithdrawalStaysInMemoryOnly`). 이를 막으면 "철회한 사람은 스레드에서도 멘션해야 봇이 답한다"로 동작이 바뀌므로 결정이 필요합니다. `channels.attachments.add/remove`로 저장한 채널 참조 파일은 답변 경로에서 읽지 않는 휴면 기능입니다. 참여 상태는 현재 512 상한을 넘을 수 있습니다. |
| PARITY | 검색 parity의 검출 범위 | 점수는 달라도 순서가 같은 변화는 parity 비교에서 잡히지 않습니다(leaf/golden 테스트가 점수 차이를 다룹니다). |
| LIVE-14 | 한도 거절 안내 시점 | 월 예산·사용자 일일 한도에도 다시 시도 시점을 구체적으로 알려 주지 않습니다. `locales/*.json`의 `discord.chat.budget`·`discord.chat.limited`를 고칩니다. |
| LIVE-19 | Discord 도움말 길이 | `/help`·`!도움말`은 활성 슬래시 명령과 접두 명령·별칭을 나열합니다. 명령별 한 줄, 대표 별칭, 상세 도움말로 줄일지 결정하고 실제 길이를 다시 잽니다. |
| U1000 | 미사용 함수 경고 | 이전 staticcheck 기록에는 함수 이름이 없었습니다. 현재 `jobs_persist.go`의 일부 함수는 호출되지만, 이번에는 staticcheck를 실행하지 않아 원래 경고가 해결됐는지 확인 필요로 둡니다. |

| 12 | 답변하지 않은 이유 진단 | 대화 기록에 개별 거절 사유는 있습니다. `/turns`에서 사유를 묶어 보여 주는 요약 화면은 없습니다. |
| 13 | 운세 등록의 성별 선택지 | 성별은 선택 사항이고 현재 값은 남성·여성입니다. 성별을 답하지 않는 선택지를 UI에서 명시할지 결정합니다. |
| 14 | 공개 서비스용 모더레이션 | 현재 서버 관리자 차단 외에 슬로 모드·일반 대화 필터·신고 흐름은 없습니다. 모르는 사람에게 공개할 때 필요 여부를 결정합니다. |
| 15 | 이미지 요청 분류기 | 금지어는 빠른 거절이고 실제 콘텐츠 필터는 공급자에 있습니다. 별도 분류기를 둘지 검토합니다. |
| 16 | 공급자 오류 문구에서 드라이버 이름 빼기 | 공급자 오류 문구가 운영자 화면에 그대로 보일 수 있습니다. 사용자에게 보이는 문구와 내부 로그를 구분할지 확인합니다. |
| 17 | 콘솔 번들 줄이기 | `/api/i18n` 응답 압축과 캐시는 적용됐습니다. 활성 언어와 작은 영어 대체본만 보내는 방식은 남았습니다. |
| 18 | Windows 정상 종료·부팅 실행 | 감시 프로세스는 자식 PID·데이터 폴더를 확인한 뒤 기존 중지 API로 정상 종료를 요청합니다(일반 약 60초, 중지 요청이 성공한 뒤부터; 확정 세션 종료 4초; 실패는 자식만 즉시 강제 종료). 숨은 최상위 창은 트레이 없이도 사용자 세션 종료를 감지합니다. 작업 스케줄러 부팅 등록·해제는 [설치](wiki/설치.md)의 수동 절차로 제공하며 자동 등록·GUI·Windows 서비스는 추가하지 않습니다. 세션 0 시스템 종료 보장과 실제 부팅·로그오프 검증은 보류입니다. |
