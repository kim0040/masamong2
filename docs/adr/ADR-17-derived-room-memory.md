# ADR-17: 방 기억(L1 방 상태·L2 에피소드)에 근거가 붙은 짧은 파생 문장을 저장한다

- 날짜: 2026-10-11
- 상태: 채택. [원문 정책](../RAW_DATA_POLICY.md)의 범위를 정한 예외다. 원문이 유일한 근거라는 원칙은 그대로다.
- 관련 문서: [기억·대화·도구 개선 계획](../plan-memory-conversation.md) 5.4절, 9장 D2·D3·D8

## 배경

원문 정책은 요약·주장 같은 파생 결과를 새 인덱스의 입력으로 쓰지 않고, 근거를 원문 복사본이 아니라 참조로 저장하라고 정한다. 그런데 "지난주에 뭘 정했나", "여행은 어떻게 됐나"에 답하려면 방 단위로 정리한 짧은 기록이 있어야 한다. 매 턴 원문 전체를 다시 읽으면 비용이 너무 크고, 사람별 카드만으로는 방의 흐름을 따라가지 못한다. 그래서 사용자가 2026-10-11에 D2·D3·D8을 확정했다.

## 결정

1. **짧은 파생 문장을 저장한다(D2).** L1 방 상태(`channel_state`)와 L2 에피소드(`channel_episode`, `episode_item`)는 모델이 원문에서 만든 문장을 저장할 수 있다.
   - 항목 문장은 120자 이하, 에피소드 제목도 120자 이하다. 어떤 경우에도 200자를 넘지 않는다. 길면 자르지 않고 그 항목을 버린다.
   - **모든 항목에 근거 observation ID가 1개 이상 있어야 한다.** 근거 없는 항목, 입력에 없는 번호를 댄 항목, 봇의 말을 근거로 댄 항목은 코드 검증기가 버린다.
   - 사람은 `PersonRef`(단방향 참조)로만 적는다. 같은 표시명이라도 계정이 다르면 다른 사람이다. 카카오 화자는 `kakao:<방>:<표시명>` 참조로 따로 두고 Discord 사람과 합치지 않는다.
   - 근거는 기존 근거 색인(`evidence_refs`)에 등록한다. 원문 삭제·수정·동의 철회는 기존 삭제 작업자(redaction worker)를 거쳐 파생 항목에 닿는다.
2. **파생의 파생을 허용한다(D3).** 일간 정리처럼 에피소드에서 다시 만드는 결과는 허용한다. 단, 항목은 원래 근거 ID를 그대로 상속하고, 이전 결과에 덧붙여 접지 않고 매번 에피소드에서 다시 만든다.
3. **백그라운드 파생 작업은 전용 월 예산을 쓴다(D8).** `memory.derived_budget_usd`(기본 3.00달러, `0`이면 끔). `memory_spend`의 `episode`·`state` 종류로 집계하고, 한도에 가까워지면 L1 갱신을 먼저 멈추고 다 쓰면 에피소드 추출도 멈춘다.

## 계속 금지하는 것

- 원문을 그대로 기억에 복사하는 것. 원문은 보여 줄 때 현재 저장소에서 조회하고, 지운 메시지와 철회한 사람은 조회되지 않는다.
- 사람을 합치는 것. 표시명·비슷한 시각·인접 메시지만으로 사람, 답장, 사건을 합치지 않는다. 서버가 다르면 다른 사람이다.
- 파생 결과를 원문 RAG 인덱스(leaf, 임베딩)의 입력으로 쓰는 것. 에피소드는 leaf 위의 별도 층이고 `episode_leaf`로 연결만 한다.
- 봇의 말과 실패를 다시 기억으로 추출하는 것. 건강·연애·돈 소문은 추출하지 않는다.
- 취소(`dropped`)를 모델이 추론하는 것. 명시적인 표현이 근거로 있을 때만 바꾼다.

## 무효화 규칙

| 원문 변화 | L2 에피소드 항목 | L1 방 상태 |
|---|---|---|
| 메시지 삭제 | 그 메시지를 근거로 댄 항목만 숨김(`hidden`) | 그 메시지를 근거로 댄 상태 행 삭제(다음 갱신 때 원문에서 다시 만듦) |
| 메시지 수정 | 숨기고 다시 만들 대상으로 표시(`dirty`) | 상태 행 삭제 |
| 동의 철회 | 그 사람의 메시지를 근거로 대거나 그 사람을 가리키는 항목 삭제, 참가자 목록에서 제거 | 상태 행 삭제 |

- 에피소드의 숨긴 항목이 40% 이상이거나 결정 항목이 숨겨지면 **원문에서 다시 만들기** 대기열에 넣는다. 남은 원문이 너무 적으면 에피소드를 지운다.
- 항목이 하나도 남지 않은 에피소드는 지운다.
- 생성 중에 근거 원문이 바뀌면(수정·삭제·철회 tombstone) 저장 트랜잭션이 거부한다.
- 읽을 때도 근거 원문이 아직 유효한지 다시 확인하고, 아니면 보여 주지 않는다.
- 방(블록)을 지우면 그 방의 에피소드도 함께 지운다.
