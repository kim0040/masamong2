# 기억 블록과 채널 연결

기억 블록은 한 source room에서 가져온 원문과 그 검색 산출물을 관리하는 단위입니다. 채널 연결은 Discord 목적지가 어떤 블록을 검색할 수 있는지 정하는 revision된 view입니다.

## 블록

블록은 다음 정보를 유지합니다.

- `block_id`, 표시 이름과 메모
- platform, collection과 원래 `source_room`
- 원문 관찰 수와 기간
- segmentation recipe와 embedding space
- 준비 상태, 진행률, 비용과 마지막 오류
- Discord 수집 설정

블록 이름을 바꿔도 원문 ID, 방, recipe와 embedding space는 바뀌지 않습니다. 삭제는 확인 뒤 블록과 제품 파생 산출물을 제거하지만 가져온 원본 파일 자체를 수정하지 않습니다.

## 채널 연결

```text
Discord 채널 A ← 카카오 블록 1, Discord 블록 2
Discord 채널 B ← Discord 블록 3
```

- 한 채널은 여러 블록을 사용할 수 있고 한 블록도 여러 채널에 연결할 수 있습니다.
- 연결은 단방향입니다. A가 B를 검색한다고 B가 A를 검색하지 않습니다.
- 연결은 인물, 권한, reply 또는 원문을 병합하지 않습니다.
- 붙이기·떼기마다 revision을 올리고 이전 revision의 결과와 캐시를 사용하지 않습니다.
- 검색은 목적지 채널 자체의 기억 사용 설정과 연결된 블록의 허용 범위를 모두 만족해야 합니다.

## 상태

| 상태 | 의미 |
|---|---|
| 가져옴 | 원문은 저장됐지만 검색 준비가 끝나지 않음 |
| 준비 중 | leaf·색인·선택적 embedding 작업 실행 중 |
| 준비됨 | 현재 recipe의 검색 산출물을 사용할 수 있음 |
| 중단됨 | 사용자가 취소했거나 서비스 종료로 멈춤, 재시도 가능 |
| 실패 | 오류를 확인한 뒤 재시도 가능 |

진행 작업은 `/jobs`와 블록 상세에서 같은 상태를 보여 줍니다. 취소·재시도는 durable job 상태 머신을 사용합니다.

## 관리 콘솔 흐름

1. `/blocks`에서 CSV를 선택하고 미리보기를 확인합니다.
2. 이름·메모, 예상 시간·비용과 예산을 정합니다.
3. 백그라운드 준비를 시작합니다.
4. 진행률과 남은 시간을 확인하고 필요하면 취소·재시도합니다.
5. `/blocks?view=channels`에서 사용할 Discord 채널에 연결합니다.

세부 운영 방법은 [기억 운영](../memory-operations.md)을 참조하세요.
