## What's new

- Web search now reads the text of the pages behind its top results, so an answer can use the pages and not only the snippets.
- The bot now decides itself when a question needs a deep search. A deep search gives a longer answer that ends with a synthesis of what was asked.
- For a question about a reason or a situation, a search answer now also gives the concrete facts the results contain.
- When a turn searches for long, the bot posts a short silent line saying it is still looking, and deletes it before the answer.
- A reply based on a deep search is shown up to 1,800 characters before the rest goes behind the More button, up from 700.
- Several lookups in one round (weather, alerts, prices, searches, places, links) now run at the same time, so such a turn finishes sooner.
- Fixed: a failed search no longer throws away the reply when another search for the same question in that turn worked.

## For operators

- New setting chat.progress sets when the still-looking line appears: deep (default), slow (also after 12 seconds) or off.
- New page-reading settings on the web search tool page: web_search.read_pages, deep_pages, fetch and fetch_daily_limit.
- web.read now tries TinyFish Fetch first and Jina Reader second. Scheduled tasks read no pages in their searches.
- Each search service now uses its own depth mode: Exa, Linkup, Tavily, Brave, TinyFish and Kakao.
- Behaviour change: for new installs the default budget per reply is 0.15 USD (was 0.03) and outside calls per reply are 10 (was 6). Existing installs keep their values.
- A search holds the most it may cost for its depth. A service that reports no cost is counted at list price.
- Search cost: a request that timed out waiting for a slot was never sent and is not charged. A request whose answer was lost is charged.
- A turn record keeps 200 characters of each page passage and its length.

## 새 기능과 수정

- 웹 검색이 상위 결과 뒤의 페이지 본문을 읽어, 답변이 요약문만이 아니라 페이지 내용도 쓸 수 있습니다.
- 질문에 깊은 검색이 필요한지 봇이 스스로 판단합니다. 깊은 검색은 더 긴 답변을 주고, 물은 내용을 종합하는 말로 끝냅니다.
- 이유나 상황을 묻는 질문에는 검색 결과에 있는 구체적인 사실도 함께 알려 줍니다.
- 검색이 오래 걸리면 봇이 아직 찾는 중이라는 짧은 알림 없는 줄을 올리고, 답변을 보내기 전에 지웁니다.
- 깊은 검색에 기댄 답변은 1,800자까지 보이고 나머지는 더보기 버튼 뒤로 갑니다(이전에는 700자).
- 한 번에 여러 조회(날씨, 특보, 시세, 검색, 장소, 링크)를 하면 동시에 처리해, 그런 턴이 더 빨리 끝납니다.
- 수정: 같은 질문을 찾은 다른 검색이 그 턴에서 성공했다면, 실패한 검색 때문에 답변이 버려지지 않습니다.

## 운영자용

- 새 설정 chat.progress로 찾는 중 줄이 나타나는 때를 정합니다: deep(기본), slow(12초가 지나도 올림), off.
- 웹 검색 도구 화면에 페이지 읽기 설정이 생겼습니다: web_search.read_pages, deep_pages, fetch, fetch_daily_limit.
- web.read는 이제 TinyFish Fetch를 먼저, Jina Reader를 그다음에 씁니다. 예약 작업의 검색은 페이지를 읽지 않습니다.
- 검색 서비스마다 자기 깊이 모드를 씁니다: Exa, Linkup, Tavily, Brave, TinyFish, 카카오.
- 동작 변경: 새로 설치하면 답변당 예산 기본값이 0.15달러(이전 0.03), 답변당 외부 호출이 10회(이전 6)입니다. 이미 있는 설치는 값을 그대로 씁니다.
- 검색은 그 깊이에서 낼 수 있는 최대 금액을 잡아 둡니다. 비용을 알려 주지 않는 서비스도 정가로 셉니다.
- 검색 비용: 자리를 기다리다 시간이 지난 요청은 보내지 않았으므로 차감하지 않습니다. 답을 잃은 요청은 차감합니다.
- 턴 기록은 페이지 발췌마다 200자와 전체 길이를 남깁니다.
